复权事件的复合顺序：xdxr1→xdxr2→xdxr3，还是反过来

结论日期 2026-10-11 ｜ 池内 800 只 · 2941 个真实除权日 ｜ 脚本 sandbox/zero_scan/c4_order.py · c4b_jump.py · c4c_impact.py
有区别，而且你的直觉（xdxr1 → xdxr2 → xdxr3，按时间正序）是对的。代码现在用的是 reversed(events)（从最近的除权往回推），这是错的。

仿射变换 P' = a·P + b 不满足交换律，两次事件复合的差 = b₁(a₂−1) + b₂(1−a₁) —— 只有全是纯现金分红（a 恒为 1）或全是纯送转股（b 恒为 0）时两种顺序才等价。A 股绝大多数公司既有送转又有分红，所以差异是常态。

池内实测：641 / 791 只（81.0%）两种顺序给出的复权价不同，涉及 1,049,137 根 K 线（占全池 39.3%）。

为什么正序才对

关键在于：现金红利是按「除权后的股数」派发的。

设 E1 = 10 送 10（a₁=0.5, b₁=0），E2 = 每股派息 5 元（a₂=1, b₂=−5）。持有 1 股穿越这两次除权：

  • E1 之后：1 股变 2 股
  • E2 派息：每股 5 元 × 2 股 = 原 1 股实收 10 元

所以正确的复合是先把价格折到除权后的股数口径，再减去当期红利：

正序 T2∘T1 :  100 →(×0.5)→ 50 →(−5)→ 45     常数项 = a₂·b₁ + b₂
逆序 T1∘T2 :  100 →(−5)→ 95 →(×0.5)→ 47.5   常数项 = a₁·b₂ + b₁
逆序先减 5 再折半，相当于假设「原股每股只收到 5 元红利」—— 漏掉了送转后多出来那一半。这就是差异的物理来源。

备注：_build_adjust_events 里的 fenhong 是交易所口径的原股本每股现金红利（与「除权参考价 =（前收盘 − 红利 + 配股价×配股比例）/（1+送转配）」一致），所以单次事件的 a, b 是对的；错的只是多次事件的复合顺序。

一个必须一起看的连带后果

改成正序后，出现 ≤0 复权价的标的会从 83 只增加到 129 只。因为正序正确认领了送转后的全部现金红利，减得更多，早期价被压得更低、穿零更深。

这说明：「顺序」和「加法口径」是两个独立的问题。只把顺序改对，会加剧负价。要从根上解决，必须同时把 ×a+b 的加法公式换成乘性（等比）复权 —— 因子恒正、尺度不变，顺序问题也随之消失（纯乘法满足交换律）。

修复点

DataAPI/TdxAPI.py:852：

# 现状（错）
for event_date, a, b in reversed(events):
    for r in records:
        if r["dt"] < event_date:
            r["close"] = r["close"] * a + b

# 应为（正序 = 先早后晚）
for event_date, a, b in events:
    for r in records:
        if r["dt"] < event_date:
            r["close"] = r["close"] * a + b

语义不变：每个事件仍然只作用于 dt < event_date 的 bar，最新一根仍恒为真实价；变的只是多次事件的复合次序。
