## 三、新增：P26 术语护栏（`Trading/Test/test_p26_terminology_guard.py`）

**把"不要用这些词"从文档升级为可执行断言**，三层结构：

| 层 | 作用 |
|---|---|
| `[0]` 元护栏 | 先证明**检测器本身有效**：`leg` 正则应命中 `leg`/`legs`/`_is_today_leg`/`locked_leg`，且**不误伤** `legacy`/`legal`/`privilege` |
| `[1]` 全仓扫描 | `Trading/**`、`App/**`、`Frontend/**` 的 `.py`/`.js` + 根目录 `verify_*.py`；禁用词零命中 |
| `[2]` 覆盖面自检 | 断言关键文件**确实被纳入扫描**，防止有人把扫描范围改窄导致护栏静默失效 |

禁用词表：中文「腿」及其全部复合词、`双仓`、`丢仓`、`腿态`、`挑腿`；英文 `leg`/`legs`（含 `_leg` 前缀）。

**不扫 `Docs/**`** —— 那是历史决策快照（v1.2/v1.3 并存），批量改会篡改可追溯性。

### 护栏有效性已做变异测试（`mutation_test_p26.py`）

往 `PositionBook.py` 注入 1 处中文禁用词 + 1 处 `_is_today_leg` 形式的英文标识符：

```
注入后 → exit code = 1
  ✗ 无已废弃中文术语 -> got 1, want 0
  ✗ 无英文 leg / legs 标识符 -> got 1, want 0

```

> ⚠️ `mutation_test_p26.py` **刻意不以 `verify_` 开头** —— 因为它自身必须含
> `_is_today_leg` 等字面量作为注入样本，若以 `verify_` 命名会被 P26 自身扫到而误报。
> 它放在仓库根目录（不在扫描范围内）。

## 四、附带修复：两个探针脚本此前已彻底跑不起来

上一轮 `EntryMode → PositionOrigin` 改名时**漏改了根目录的验证脚本**，
它们仍在 `import EntryMode` 并使用 `pos.entry_mode` —— 实际已 `ImportError`：

| 文件 | 问题 | 修复 |
|---|---|---|
| `verify_rule5.py` | `from ... import Bar, EntryMode, ...` + `pos.entry_mode.value` + `legs` 变量 | 去掉 `EntryMode`；`entry_mode` → `origin`；`legs` → `pos_list` |
| `verify_anchor.py` | 同上 | 同上 |

另外顺手修掉 `verify_anchor.py` 两处自身瑕疵：

1. **离场检测判据写错**：原判据是"簿是否清空"，但**场景X 是当日单、离场走软离场锁仓（保留双向持仓），簿永不清空** → 恒报 `None`。
   改为"是否发出新的 `lock`/`close` 报单"。修正后输出显示**场景X 与场景Y 在第 5 根 K 线同根触发** —— 这是"L1-L3 判定完全一致"的直接证据。
2. **结论段是占位文案**：`解锁仓 已落 Trade + 升级仓 见 store.trades` → 改为输出真实 Trade 条数与净点数。

修复后 `verify_anchor.py` 的完整结论：

```
离场触发: 场景X 第 5 根 K 线；场景Y 第 5 根 K 线（喂同一批 K 线，应同根）
离场后簿面: 场景X 2 笔（软离场锁仓，保留双向持仓）；场景Y 0 笔（硬离场平昨，清空）
离场报单 intent: X = lock / Y = close
离场报单 offset: X = OPEN / Y = CLOSE
场景Y 的 L1-L3 风控锚 = 3900.2（解锁成交价），会计锚 = 4000.2（原开仓价，仅用于记账）
场景X：Trade 0 条，净点数合计 0（当日单 → 软离场锁仓，不兑现 PnL）
场景Y：Trade 2 条，净点数合计 -21.16（跨日单 → 硬离场平昨，兑现 PnL）
```

## 七、注意事项

1. **`Docs/` 未改动**（含"腿" 319 处）—— 那是历史决策快照，改了等于篡改历史、
   破坏 v1.2/v1.3 旧章节的可追溯性。`术语对照表_腿_新旧_20260910.md` 的作用正是
   "读旧文档时对照新表述"，保持不变。
2. **P26 会扫你项目里 `Trading/`、`App/`、`Frontend/` 下的 `.py`/`.js`**。
   若你在这三处有自建脚本恰好含"腿"字，会红 —— 按对照表改写即可。
3. 本轮**零逻辑改动**：所有替换都在注释、docstring、打印文案与局部变量名上；
   唯一涉及标识符的是 `_is_today_leg` / `locked_leg` / `legs`（均为内部名，
   调用处为位置参数，且已确认无跨模块引用）。
4. 本轮过程中发现本环境 **Edit 工具存在"报成功但磁盘未变"**的现象（Git Bash 侧也会
   读到过期缓存）。因此本轮所有改动均改用 Python 直接落盘，并**强制写后读回校验**。
   你后续若用脚本批量改，建议同样加读回断言。
