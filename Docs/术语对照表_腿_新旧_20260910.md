## 一、为什么要分三类（不是全局替换成"一笔持仓"）

代码里"腿"承担了 **3 类不同含义**，压平成一个词必然别扭：

| 类 | 含义 | 判别 | 典型词 |
|---|---|---|---|
| ① | 一笔持仓记录（= 一个 `Position`） | 指单个对象 | 反向仓、原仓、剩余持仓、被平持仓 |
| ② | 锁仓这一"对"（pair） | 指多+空两笔构成的一组 | 双向持仓、留双向持仓 |
| ③ | 笔数·容量计数 | 指数量 | 笔数、总笔数、丢失持仓 |

## 二、完整对照表

### ① 类：一笔持仓（Position）

| 旧 | 新 | 说明 |
|---|---|---|
| 反向腿 | **反向仓** | 锁仓时新开的那笔反向持仓 |
| 原仓腿 | **原仓** | "腿"本就多余 |
| 锁仓腿 | **锁仓持仓** | 处于 LOCKED 状态的持仓 |
| 配对腿 | **配对持仓** | 同一 `lock_pair_id` 的另一笔 |
| 配对同向腿 | **配对同向持仓** | |
| 同向腿 | **同向持仓** | 与信号同向的那笔 |
| 剩腿 | **剩余持仓** | 解锁后剩下的那笔 |
| 被平腿 / 被平持仓腿 | **被平持仓** | 正在被平的那笔 |
| 最老一腿 | **最早一笔持仓** | FIFO 选中的那笔 |
| 平错腿 | **平错持仓** | 缺陷场景 |
| UNLOCK_FIRST 腿 / LOCKED 腿 / LONG 腿 | **UNLOCK_FIRST 持仓 / LOCKED 持仓 / LONG 持仓** | 状态词 + 持仓 |

### ② 类：锁仓这一"对"（v2：双仓 → 双向持仓）

| 旧 | 新 | 说明 |
|---|---|---|
| 留双腿 | **留双向持仓** | 软离场后原仓 + 反向仓都留在簿里（即"同时持有同品种多+空两笔"） |
| 锁仓双腿 | **锁仓双向持仓** | |
| 双腿 | **双向持仓** | |
| 两腿 | **两笔** | |

> 说明："双向持仓"是期货标准说法（指同时持有同品种多+空两笔）；"双仓"读起来像自造词，故 v2 改为双向持仓。

### ③ 类：笔数·容量计数

| 旧 | 新 | 说明 |
|---|---|---|
| 总腿数 | **总笔数** | |
| 腿数 | **笔数** | |
| 静默丢腿 / 静默丢仓 | **静默丢失持仓** | 缺陷名：引擎在 LOCK 落簿(D2b) / 恢复截断(D3) 时静默丢弃 `Position` 记录，导致账实不符 |
| N 条腿 / N 腿 | **N 笔** | |
| 一腿 | **一笔** | |
| 笔腿 | **笔** | |

> 说明："丢仓"是本项目自造的缺陷名（非市场术语），指引擎**静默丢弃持仓记录**（Position 从簿中消失，真实持仓还在 → 账实不符 / phantom）。v2 改为"丢失持仓"更直白。

|---|---|

## 四、用户二次确认的四点澄清（v2 依据）

**⑴ 笔数定义**：用户定义"一次开仓/平仓指令无论成交量多大，结算单上记为一笔"——正确。本项目中"笔"有两种口径，已并存：
- **持仓笔数**（`Position` 记录条数）：`max_open_positions`、`总笔数`、解锁"多空两笔"均指此；
- **成交笔数**（fill/结算笔数）：`main.py` 的成交统计用"成交笔数"。
术语替换里的"N 笔"一律指**持仓笔数**（一笔报单形成的持仓记录），与用户定义一致。

**⑵ 双仓 → 双向持仓**：用户指定。期货标准说法，指同时持有同品种多+空两笔持仓；"留双向持仓"对应软离场后原仓+反向仓都在簿里。

**⑶ 丢仓 → 丢失持仓**：用户指出"丢仓"非标准术语、不知其意。经查代码，它是本项目**自造的缺陷名**，含义是：引擎在 LOCK 落簿(D2b)或恢复截断(D3)时**静默丢弃 `Position` 记录**，导致簿中持仓消失但实盘还在（账实不符 / phantom）。v2 改为"丢失持仓"，字面即"持仓记录丢失"，消除歧义。

**⑷ 锁仓↔解锁流程（用户给的完整示例，已逐字核对代码，完全正确）**：

```
初始状态：持有 1 手原仓（MA409 多单）
执行锁仓：开 1 手反向仓（MA409 空单）→ 形成双向持仓（多空两笔，均 entry_mode=LOCKED）
解锁操作：行情符合预期，平掉空单 → 该空单即"被平持仓"
最终状态：只剩最初那手原仓（MA409 多单），即"剩余持仓"
```

代码对应（`Engine.py`）：锁仓时 `lock` 意图两笔均落簿为 `LOCKED`（=留双向持仓）；跨日解锁 `unlock` 意图 FIFO 平掉最老一笔反向仓（=被平持仓），原仓保留为 `OPEN_FIRST`（=剩余持仓）。与用户描述一致。唯一补充：本项目每笔为 FOK 报单、默认 2 手；多空"两笔"在簿中即 2 个 `Position` 对象。
