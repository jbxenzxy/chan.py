# SimNow + CTP 自动下单可行性分析

> 对象：chan.py `custom-dev` 分支（2026-09-04 拉取，快照位于 `sandbox/chanpy_custom_dev/`）
> 目标：缠论买点信号 → 自动开多；卖点信号 → 自动开空（SimNow 仿真，CTP）
> 本文只做可行性评估，**未改动任何项目代码**

---

## 0. 结论先行（Verdict）

**可行，但有前提。**

| 判定项 | 结论 |
|---|---|
| 技术可行性 | ✅ 可行。项目已具备「期货实时K线 + 缠论买卖点 + 每根K线闭合后的事件推送」三件套，缺的只有「下单执行层」 |
| 「在快期3上开仓」这个说法 | ⚠️ **需要纠正**。不是控制快期3下单，而是**新开一个与快期3平行的 CTP 会话** |
| 快期3 与程序并存 | ✅ 可以。SimNow 官方 FAQ：每账户允许同时 **4 个 session**（压力时可能降到 2/1） |
| 工程量 | 中等偏大。**不是加几行代码**，主要工作量在信号工程化（重绘/幂等）、合约映射、仓位模型、风控 |
| 最大风险 | 🚨 不在技术接入，在**信号本身的可用性**：缠论 bsp 是「结构信号」，不是带止损的交易系统，裸跑大概率亏损 |

**推荐路线**：A 方案（TqSdk + `TqAccount("simnow", ...)` + **进程外独立交易网关**）。
**不推荐**：直接把 `TqApi(auth=...)` 那一行改成带账户（理由见 §4）。

## 2. 概念澄清：「在快期3上开仓」到底是什么

```
┌─────────────┐                          ┌──────────────────────┐
│   快期 3     │  CTP 会话 ①（人工看盘）    │  SimNow CTP 前置      │
│  （CTP终端） ├──────────────────────────▶│  182.254.243.31:30001│
└─────────────┘                          │  BrokerID = 9999     │
                                         │  同一账户 → 4 session │
┌─────────────┐                          │                      │
│  chan.py    │  CTP 会话 ②（程序自动）    │                      │
│  交易网关进程├──────────────────────────▶│                      │
└─────────────┘                          └──────────────────────┘
```

- 快期3 只是一个 **CTP 客户端**，不是服务端。不存在「让快期3 代我们下单」这回事。
- 我们的程序是**同账户下的第二个 CTP 会话**。SimNow 官方 FAQ 明确：**每个账户允许同时 4 个 session 登录**（系统压力大时可能调为 2 或 1）。所以「快期3 保持登录 + 程序并行登录」在正常时段是允许的。
- 程序下的委托/成交，在快期3 里**能看到**（同一账户资金/持仓/委托共享），但快期3 不会参与执行。
- ⚠️ **若你的快期3 是用「快期账户」而非 SimNow CTP 账号登录的**，那更简单：TqSdk 的 `TqKq()` 直连同一账户体系，跳过 SimNow 中转（见 §3 备注）。

## 3. 三条技术路线对比

| 维度 | **A. TqSdk + TqAccount("simnow")** | B. 自建 CTP 网关（openctp / vnpy_ctp） | C. TqSdk2 `TqCtp` 直连 |
|---|---|---|---|
| 做法 | `TqApi(TqAccount("simnow", 投资者号, 密码), auth=TqAuth(...))` | 用 CTP API 直连 SimNow 前置 | `TqApi(TqCtp("tcp://前置", ...))` |
| 官方支持 | ✅ 天勤文档 Example2 明确支持 | ✅ SimNow 官方支持程序化接入 | ⚠️ **需企业版权限（付费）** |
| 改动量 | 小（复用现有 TqApi 生态、合约代码、quote 查询） | 大（网关层、穿透式认证、合约映射、报单状态机全自己写） | 小 |
| 依赖 | 依赖信易服务器中转 | 无第三方中转 | 依赖信易企业版授权 |
| 延迟 | 多一跳（几百 ms 级），对 15s/1m 周期信号无所谓 | 最低 | 低 |
| 主连 `KQ.m@` 可用性 | ⚠️ **需实测**（见下方风险） | ❌ CTP 不认识 KQ 代码，必须自己做主连合成 | ⚠️ 同 A |
| 成本 | 免费（需注册免费天勤账户，你已有） | 免费 | 付费 |
| 结论 | **⭐ 推荐** | 备选（若 A 的行情实测不过） | ❌ 排除 |

**A 方案的已知风险点（必须实测才能定稿）**：
天勤文档对 `TqAccount` 的描述是「直连行情和交易服务器」。若连接后**行情通道也切到 SimNow CTP 行情前置**，则 CT P不认识 `KQ.m@SHFE.rb` 这类主连代码，现有期货链路会直接失效。
→ 缓解办法正是 §4 的**进程隔离**：行情继续用无账户的纯行情 `TqApi`（保留主连），交易另起一个进程。这个风险就消失了。

**备注**：如果你的快期3 登录的是「快期账户」，用 `TqKq()` 更符合直觉——委托会直接同步到你的快期3 界面，且不消耗 SimNow 会话额度。

## 4. 推荐架构：进程外交易网关（信号与执行解耦）

```
┌──────────────────────── chan.py（现有，基本不动）───────────────────────┐
│  TqApi(auth=...) 纯行情 → KQ.m@ 主连K线 → CChan 缠论 → SSE 快照(含 bsps) │
│  App/AppSSE.py:604  ← 唯一改动点：在此挂「信号发布」钩子                  │
└────────────────────────────────┬───────────────────────────────────────┘
                                 │ 信号事件（JSON，落盘 + 队列/HTTP）
                                 ▼
┌─────────────── 新模块：Trader Gateway（独立进程）──────────────────────┐
│  ① 信号接收 + 去重/幂等（冻结快照，防 bsp 重绘）                        │
│  ② 信号 → 交易合约映射（主连 → 具体月份，换月移仓）                     │
│  ③ 仓位模型（+1 / 0 / -1，用 TargetPosTask 管理目标持仓）               │
│  ④ 风控闸门（时段、涨跌停、单日止损、最大手数、断线保护）                │
│  ⑤ TqApi(TqAccount("simnow", ...)) → 报单 / 撤单 / 回执落盘             │
└────────────────────────────────┬───────────────────────────────────────┘
                                 ▼
                        SimNow CTP（BrokerID 9999）
```

**为什么不能「就地改那一行 TqApi」**：

1. **每个前端页面一个 TqApi**：`DataAPI/TqSdkCSSESource.py:239` 的 `connect()` 是**每 SSE 连接一次**。开 3 个期货页面 → 3 个带交易账户的会话 → 占用 3 个 session 额度 + 信号互相打架。
2. **TqSdk 单进程实例约束**：一个进程内塞多个 `TqApi` 会冲突，交易连接必须收敛成**单例**。
3. **行情侧不能冒 §3 那个风险**：主连 K 线是现有功能的基础，独立进程后行情链路零改动。
4. **故障隔离**：交易网关崩了/卡了，不影响你看盘。

## 5. 真正的难点：五个必须解决的工程问题

### ① 买卖点会「重绘」→ 必须冻结 + 幂等
- 缠论笔依赖分型，新 K 线进来后**笔端点会移动、买卖点会位移甚至消失**。
- 项目已有防护苗头：一类买卖点在「虚笔」时直接不生成（`BuySellPoint/BSPointList.py:681` `_is_virtual_bi` → return None），强势分型也会过滤（`:1528`）。但**二/三类点、以及历史 bsp 列表的整体变动**仍存在。
- 对策：`(symbol, freq, bsp.date, bsp.type, is_buy)` 作为**幂等键**，下过就永不重复下；只在 **K 线闭合的那一拍**取信号（正好是现有推送时机），不在 tick 级取。
- bsp 的 `price` 是**右肩 K 线收盘价**（`BS_Point.py:19-27`），不是当前市价 —— 信号到达时价格已走完一根 K 线，**滑点是结构性的**，要在期望里扣掉。

### ② 主连不能直接下单 → 必须做合约映射
- 天勤 `KQ.m@SHFE.rb` 是虚拟连续合约，**交易所不认**，CTP 无法报单。
- 对策：下单前用主连 quote 的 `underlying_symbol` 解析出当前真实月份合约（如 `SHFE.rb2610`），并对 `underlying_symbol` 变化做**换月移仓**监听。
- 信号算在主连上、执行落在具体月合约上 —— 这两条序列的 K 线**时间戳不同、价格不同**，换月日尤其要小心。

### ③ SimNow 的下单约束
- ⚠️ **SimNow 不支持市价单**，只支持限价 / FAK / FOK。→ 用**对手价或超价限价**（买用卖一+n tick，卖用买一-n tick）。
- 价格必须对齐 `price_tick`，否则直接被拒单。
- 上期所品种平仓要区分**平今 / 平昨**。
- 撮合规则：三价取中（委托价、对手价、最新价），不是你想的即时成交。

### ④ 仓位模型：买点开多、卖点开空 ≠ 简单互换
需要明确定义，否则会「多空双开、仓位爆炸」：
- 推荐**目标持仓（TargetPosTask）**模型：买点 → 目标 +1；卖点 → 目标 -1；信号消失/止损 → 目标 0。让库去处理「平空 + 反手开多」的组合委托，比自己写开平逻辑稳。
- 手数：按品种乘数和保证金算，SimNow 初始资金 2000 万，别一次打满。

### ⑤ 风控与可观测（这块不做，前面全白做）
- 非交易时段不下单、集合竞价不下单、涨跌停不下单、断线不下单。
- 撤单重追超时、单日最大亏损熔断、最大持仓手数、单品种冷却期。
- **全部委托/回执落盘**（sqlite 或日志），SimNow 没有结算服务，事后复盘只能靠自己的记录。

### ⑥（额外提醒）信号本身的胜率问题
缠论 bsp 是**结构信号本身**，不带止损、不带过滤、不带品种适配。这类信号直接连到真金白银的执行器上，历史上亏损概率远大于盈利。
→ 强烈建议先跑 **M0 阶段（只记录信号与模拟成交，不真下单）至少 1~2 周**，统计信号数、信号后 N 根 K 线的盈亏分布、最大回撤，确认值得做再接执行器。这一步不花什么成本，但能避免最贵的那类错误。

## 10. 买卖点信号的代码级定义（第 8 点核查结论）

### 你的假设：✅ 基本正确，但**实际条件更严格**

强势分型的判定在 `BuySellPoint/BSPointList.py:1514 _is_strong_fx()`，且**它是所有笔级别买卖点的公共前置条件**
（`BSPointList.py:666 cal_bsp_precondition()` 的 ⑶，通过后才依次计算 0/1/2/3 类买卖点）。

**底分型（买点方向）必须三条全满足**：

| 条件 | 代码 | 缠论出处 |
|---|---|---|
| ① 右肩 K 线**收阳** | `k3_c > k3_o` | 第82课 |
| ② 收盘站上中间K线（k2）**区间一半以上** | `k3_c > (k2_h + k2_l) / 2` | 第82课 |
| ③ 收盘站上 **MA5**（5根原始K线收盘均价） | `k3_c > ma5` | 第79课 |

三条全中 → 强势（返回 1）；再满足 `k3_h > k1_h 且 k3_c > k1_mid` → 最强（返回 2）。
**顶分型（卖点）完全镜像**：收阴 + 跌破 k2 区间一半 + 跌破 MA5。

> 所以"买点 = 底分型右肩红K、卖点 = 顶分型右肩绿K"是对的，但那只是**必要条件之一**，
> 还有 MA5 和区间一半两道关。这意味着信号比你想象的**更稀有、也更严格**。

### 信号的完整前置条件（缺一不可）

`BSPointList.py:666 cal_bsp_precondition()`：
1. 存在**非单笔中枢**（pivot_a）
2. 最后一笔是**实笔**（`_is_virtual_bi` = False，即 `bi_list[-1].is_sure = True`）
3. **强势分型**（`_is_strong_fx != 0`）

之后还要过 `check_nested_diver()`（区间套背驰判断）。

### 时序：信号在哪一根 K 线上产生？

`KLine/KLine_List.py:128 add_single_klu()` → `bi_list.update_bi(lst[-2], lst[-1])`
→ 用**倒数第二根 KLC** 更新实笔 → `cal_seg_and_zs()` → 计算买卖点。

在 SSE 的 step_load 模式下（每根 5 分钟 K 线闭合喂一次），
**bsp 的右肩 k3 = 刚闭合的那根 5 分钟 K 线**，`bsp.klu = k3.lst[-1]` = 那根 K 线本身。

> ✅ **所以你的判断成立**：信号在走完一根 K 线后才出，`price` = 该 K 线收盘价。
> 快照里已经输出了 `bsps[].price / high / low`（`App/AppSSE.py:1372-1396`），
> **可以直接用作入场价和止损价，不需要额外计算**。

### ⚠️ 三个必须注意的坑

**坑 1：bsp.klu 是"右肩合并K线的最后一根原始K线"，不一定是"那根红K"**
`BuySellPoint/BS_Point.py:19-27`：`self.klu = right_klc.lst[-1]`。
而强势分型判定用的是**整根合并K线**的 `lst[0].open → lst[-1].close`。
若右肩发生包含合并（多根原始K线合成一根 KLC），"收阳"是合并后的整体判定，
而 `klu` 是其中最后一根 —— **它可能本身是阴线**。5 分钟周期下通常两者一致，但不是保证。

**坑 2：重绘的主因是"笔端点位移"，不是"强弱判定翻转"**
后续 K 线若创出新低/新高，笔会延长，笔的终点（end_klc）右移 →
**右肩 k3 跟着右移 → 同一个买点信号整体挪位置**（时间和价格都变）。
→ 所以幂等键不能只看"是否已下过单"，还要能识别"信号位移后旧信号作废"。
→ M0 录制器专门记录这个（`revisions` 数组 + `disappear_count`）。

**坑 3：快照里的 bsps 只是"笔级别"**
`KLine_List.cal_seg_and_zs()` 计算两套：笔级别 `bs_point_lst` 和线段级别 `seg_bs_point_lst`；
`Chan.get_latest_bsp()` 返回的是**笔级别**（`Chan.py:312`）。线段级别买卖点未出现在 SSE 快照中。

## 11. 白话解释：独立进程 vs 新服务 / 多标签页 / 切换周期

### 独立进程 ≈ 新服务，对你来说就是"多开一个程序"

- 现在 chan.py = **一个 Python 程序**（Web 服务，跑在某个端口）
- "独立进程" = **再开一个 Python 程序**，专门负责下单
- "新服务" = 这个新程序对外开一个小接口，chan.py 把信号发过去
- 两者是同一件事的两种说法：独立进程（怎么跑）+ 进程间通信（怎么对话）= 新服务

**为什么不能塞进现有程序**：
1. 你每开一个标签页就建一个天勤连接（`TqSdkCSSESource.py:239`）。如果下单也塞进去，
   开 3 个标签页 = 3 个交易连接 = 吃掉 3 个 session 额度，而且信号互相打架
2. TqSdk 在同一进程内塞多个带账户的连接会有冲突
3. **下单程序崩了/卡了，不影响你看盘**
4. 将来换实盘、换合约，重启下单程序即可，看盘服务不用动

**你的实际操作差别**：启动时多敲一行命令，其他无感。

### 多标签页（IF 5m + IM 5m）：✅ 现有架构就支持

每个 SSE 连接是**自包含的**（独立天勤连接、独立 K 线缓存、独立 CChan），
代码里有明确注释（`TqSdkCSSESource.py:229-233`，P0-1 修复）。所以同时跑多个合约**没问题**。

⚠️ 但前提是**交易网关独立于看盘连接**——否则你有几个标签页就占几个交易 session。

### 切换周期：v1 建议"禁止带仓切换"

切换周期 = 断掉旧 SSE、重连新的（旧连接的 `finally` 会 `close` + `cleanup_records`）。

由此推出一条**硬性设计约束**：

> **信号的幂等与持仓状态，绝对不能放在 SSE 连接内部**（切一次周期就全丢了）。
> 必须放在交易网关侧并持久化。这是选独立进程架构的第三个理由。

**v1 简化方案**：
- 配置里写死「一个合约 + 一个周期」= 一个策略实例
- **已有持仓时禁止切换周期**（先平仓或人工确认），避免"旧周期信号开的仓，被新周期信号平掉"的错配
- 后续若要支持多实例，按 `(合约, 周期)` 作为策略实例 ID，各自独立维护仓位

## 12. ⚠️ 期指平今成本：这一条会显著改变你的参数

`IF/IH/IC/IM` 的平今仓手续费远高于开仓（中金所标准，**以交易所最新公告为准**）：

| 项 | 费率 | 以 IF 4000 点 / 1 手计算 |
|---|---|---|
| 开仓 | 0.0023% | 27.6 元 = **0.09 点** |
| **平今** | **0.0345%** | **414 元 = 1.38 点** |
| 平昨 | 0.0023% | 27.6 元 = 0.09 点 |

**结论**：日内反手一次 ≈ **1.47 点成本**，加上双边滑点（IF 最小变动 0.2 点，实盘取 0.2~0.4 点/边），
**单次往返成本约 1.9 点 ≈ 570 元/手**。

### 对你「止盈 10 点」的测算

假设止盈 10 点，止损距离 = 信号 K 线振幅（用 S 表示）：

| 止损距离 S | 净盈 | 净亏 | 盈亏比 | **保本胜率** |
|---|---|---|---|---|
| 3 点 | 8.1 | -4.9 | 1.65 | **37.7%** |
| 5 点 | 8.1 | -6.9 | 1.17 | **46.0%** |
| 8 点 | 8.1 | -9.9 | 0.82 | **55.0%** |
| 10 点 | 8.1 | -11.9 | 0.68 | **59.5%** |
| 15 点 | 8.1 | -16.9 | 0.48 | **67.6%** |

> **关键洞察**：你这套参数能不能赚钱，**几乎完全取决于信号 K 线的振幅**（= 止损距离）。
> 振幅 5 点以内 → 保本胜率只要 46%，很有希望；
> 振幅 10 点以上 → 需要 60% 胜率，很难。
>
> **这正是 M0 阶段必须先测出来的东西**（`analyze.py` 的"信号K线振幅分布"一节）。

### 另一个可选优化

若允许**持仓过夜**，平昨费率只有平今的 1/15，往返成本从 1.9 点降到约 0.5 点。
但会引入隔夜跳空风险，且缠论 5 分钟信号本身是日内级别的 —— **建议先按日内做，跑通后再评估**。
