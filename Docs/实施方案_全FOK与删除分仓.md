## 一、先回答你的问题：金字塔分仓现在到底用在哪

**代码事实**（逐处核实过）：

| 使用点 | 位置 | 说明 |
|---|---|---|
| 开仓拆分循环 | `engine._open_positions` | 一个信号拆 N 个小仓位、`#idx` 编号、共享 open_order_id |
| 批次解锁整套机制 | `engine._unlock_round_entry / _check_unlock_round / _unlock_round_settle` + in-flight 持久化 + 5s 轮次窗口 + 新开补齐 | 只在 `split_unlock ≥ 2` 时运行；=1 时走 E2 单笔路径 |
| 配置项 | `sizing.split_positions / split_unlock / unlock_no_new_open` | 前两个是分仓专属；`unlock_no_new_open` 与分仓无关，**保留**（见 D5） |

> **术语纪律（2026-09-06 21:36 用户要求）**：重构后的代码、注释、文档一律只用"**笔**"（报单/order）和"**手**"（lot/手数），不再出现"分仓 / 单仓 / 多仓 / 小仓位 / 批次"等词。持仓账本里的每条记录称"一笔持仓"。
>
> **Position = 持仓，是官方/行业术语**：CTP 柜台的持仓查询接口就叫 InvestorPosition（投资者持仓），tqsdk 官方 API 是 `get_position()`，返回对象类名就叫 `Position`。"持仓账本（PositionBook）"= 程序内记的持仓流水账，一条 Position = 一笔持仓（带手数）。这个词保留，中文表述一律写"持仓"。

**止盈止损算法用到了吗？——没有。** 每个仓位单元的止损止盈是开仓时挂在它身上的独立 `exit_plan`（`exit_policy.plan(sig, entry_price, spec)`），单仓路径同样工作。多仓位账本（PositionBook、FIFO 平仓、同向仓上限）也不是分仓造出来的——你一天打多个信号，每个信号各开一笔，账本自然是多仓。**结论：分仓机制是纯粹的独立玩法，删掉它不碰止盈止损、不碰多信号多仓。**

## 二、目标模型（按你 ⑴⑵⑶ 的表述落成规则）

| 环节 | 报单指令 | 不成交时 | 成交后 |
|---|---|---|---|
| 开仓 OPEN | FOK，一笔挂 N 手（N≤20） | 全撤 → 本信号作废（rejected），不追价，等下一信号 | 簿面记 1 个 Position |
| 解锁 UNLOCK | FOK（一笔对一个锁仓单元） | 全撤 → 作废，不追价，等下一个对向信号 | 删该锁仓单元、记 Trade |
| 锁仓 LOCK（软离场） | FOK | 全撤 → **立即按最新对手价重报**，循环直到成交 | 簿面落反向 LOCKED 仓 |
| 平仓 CLOSE（硬离场） | FOK | 全撤 → **立即按最新对手价重报**，循环直到成交 | 删仓、记 Trade |

关键简化：FOK 全成或全撤 → **成交归属永远无歧义**，不存在"部分成交算谁的"问题，这正是当年引入"逐笔拆单"的历史原因，现在连根拔掉。

### 批次 B：engine.py —— 开仓路径删除分仓

### 批次 C：engine.py —— 删除 H2 解锁轮次机制（原"批次解锁"）
- 整体删除：`_unlock_round_entry` 多笔分支、`_check_unlock_round`、`_unlock_round_settle`、`_unlock_round_in_flight`（初始化/持久化/重启恢复/on_bar 复核调用/exit_busy 挂起逻辑）。
- 解锁流程归一为：一个反向信号 → 对当前最老的一笔锁仓持仓发**一笔 FOK 解锁报单（整笔全量手数）**，成交即删这笔持仓。没有"轮"的概念，多个锁仓持仓就等多次信号逐笔解。
- **保留补开分支**（用户 ⑹ 场景）：昨日锁了 V 手、今日反向信号要 N 手（N>V）→ 解锁 V 手后，若 `unlock_no_new_open=False` 则对差额 (N−V) 手继续走正常开仓（一笔 FOK）；`=True` 则跳过新开（规避平今高手续费）。此开关从被删的轮次机制中解耦迁出，落在单笔解锁路径上。
- F1 解锁复核（`_check_unlock_stuck`）**保留**（见 D2 答复），改挂在新的单笔解锁路径上。
- `_book_unlock_trade` 删 `pos_idx/pos_count` 参数。
- **验证门**：p13/p16/p18 回归 + 新增"解锁后补开 / 不补开"两用例。
- **回退**：还原 engine.py。
