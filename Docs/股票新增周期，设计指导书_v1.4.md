# 股票新增周期，设计指导书 v1.4

> 用途：把「给股票新增一个 K 线周期」变成可机械执行的核对清单，避免漏改。
> 基线：custom-dev 最新代码，本指导书核对于 commit `8f6848f`。

---

## 0. 范围与现状

- **当前股票周期**（`STOCKS_FREQS`）：周 K / 日 K / 30 分 / 15 分 / 5 分。
- **计划新增**：月 K（M）、1 分（1m）。
- **核心架构变更（v1.1 起）**：所有周期的「客观属性」——KL_TYPE、秒数、中文标签、是否日内分钟级、是否秒级——已统一为 **`Common/CEnum.py` 的 `FREQ_TABLE` 单一事实源**，并自动派生下列视图（消费方一律从 CEnum 导入，不再内联副本）：
  - `FREQ_SEC_MAP`（freq→秒）、`KL_TYPE_TO_FREQ` / `FREQ_TO_KL_TYPE`（KL↔freq 双向）、`FREQ_SEC_TO_KL`（秒→KL）
  - `INTRADAY_FREQS`（日内分钟级）、`SUBSECOND_FREQS`（秒级）
- **市场开放集**：`STOCKS_FREQS` / `FUTURES_FREQS`（均为 frozenset），界定「该市场开放哪些周期」。客观属性共享 `FREQ_TABLE`，市场集各自独立演进（互不牵连）。
- **回归测试守卫**：`Test/test_15m_period.py::test_market_freq_partition` 跨语言校验——前端 `levels` 集合 == `STOCKS_FREQS ∪ FUTURES_FREQS`、`STOCKS_LOOKBACK_CONFIG`/`FUTURES_LOOKBACK_CONFIG` 的 keys ⊆ 各自市场集、`_STOCKS_MAIN_PERIOD` keys ⊆ `STOCKS_FREQS`、期货 `SUPPORTED_FREQS` 派生自 `FUTURES_FREQS`。新增周期后跑此测试即可防漂移。

> **v1.0 的「多副本总表 [A]–[H]」为何不再存在**：原 [A] KL_TYPE 映射、[B] 主周期时长、[C] 中文标签，已彻底收口到 `FREQ_TABLE`（加一行即全部派生，不再是漏改点）；原 [E] 前端镜像、[D] 回看配置，仍需手动同步但已被上述测试守卫。仅剩 [H] 取数分支、[F] 前端按钮、[G] 双窗配对是业务逻辑上无法自动化的必要步骤。

## 1. 新增周期标准动作（基于 FREQ_TABLE 单一事实源）

| 步骤 | 动作 | 是否自动 | 说明 |
|---|---|---|---|
| 1. 元数据 | 在 `FREQ_TABLE` 加一行 `(KL_TYPE, 秒数, 中文标签, 是否日内分钟, 是否秒级)` | ✅ 派生自动同步（原 [A][B][C]） | 一行解决 KL_TYPE 映射、主周期时长、中文标签、INTRADAY/SUBSECOND 分类。标签须**显式填值**（如周/月），不要留 `None`——否则 `_get_freq_label` 会回退成「日线」 |
| 2. 市场开放 | 把 freq 加入 `STOCKS_FREQS`（或 `FUTURES_FREQS`） | 手动 | 决定该周期对股票/期货是否开放；联动影响回看配置 key、主周期时长 keys、前端 `levels` |
| 3. 取数路径（原 [H]） | `read_main_level_records` 加 `elif freq == ...` 分支 | 手动（无法自动） | 月 K 走日线聚合 `_resample_day_to_month`；1 分走 `read_tdx_1min_file`（读 `.lc1`，底层与 `read_tdx_5min_file` 共用 `_parse_tdx_min_binary`，**不能由 5 分降采样**） |
| 4. 前端镜像（原 [E]） | `FREQ_SEC_MAP_JS` / `levels` / `STOCKS_DUAL_PAIRS_JS` 同步 | 手动，但 `test_market_freq_partition` 守卫 | JS 无法 import Python，必须保留镜像；测试防漂移 |
| 5. 前端按钮（原 [F]） | 放开 `btn-<freq>.disabled` 开关 | 手动 | 如股票启用 1 分，去掉 `!isFutures` 限制 |
| 6. 回看配置（原 [D]） | `STOCKS_LOOKBACK_CONFIG` 加 key | 手动，测试守卫 | key 必须 ⊆ `STOCKS_FREQS` |

> 与 v1.0 相比：原八站中的 [A][B][C] 已消除（不再是漏改点）；[E][D] 仍需手填但被测试守住；[H][F][G] 是业务本身无法自动的步骤。整体「漏改」面大幅缩小。

## 2. 月 K 专项（M）

**元数据已登记**：`FREQ_TABLE["M"] = (K_MON, 2592000, "月线", False, False)`。

- 枚举 `K_MON = 17`、各派生映射已含、`check_kltype_order` 仅校验降序 → **内核零改动**。
- **仍需做**：

  2. [D] `STOCKS_LOOKBACK_CONFIG` 加 `'M'`。
  3. [F] 若股票开放，前端放开月 K 按钮。
  4. 步骤 2：把 `'M'` 加进 `STOCKS_FREQS`。
  5. [G] 纳入双窗（已拍板）：把 `'M'` 加进 `_STOCKS_DUAL_PAIRS` 及对应副窗频率集合。
- **命名已拍板：用 `'M'`**。注意 `'M'` 与 `TqSdkAPI.FUTURES_ALIASES` 豆粕别名同字符串（不同命名空间，运行时无冲突，但 `?freq=M` / `?code=M` 在 URL 与日志易混淆）——已确认可接受，三处统一用 `'M'`（`FREQ_TABLE['M']`、`_get_freq_label`、`levels`、`STOCKS_LOOKBACK_CONFIG`）。

## 3. 1 分专项（1m）

**元数据已登记**：`FREQ_TABLE["1m"] = (K_1M, 60, '1分钟', True, False)`。

- 映射 / 标签层已就位，比月 K 还省事。
- **头号坑（必读）**：`read_main_level_records` 仅处理 `30m/15m/5m`（均从 `.lc5` 上采样），**1 分没有 `.lc5` 源，也不能由 5 分降采样**（方向反了）。须用 **`read_tdx_1min_file` 读 `.lc1`（1 分钟线）**（[H]，方案已定；底层 `_parse_tdx_min_binary` 与 `read_tdx_5min_file` 共用，无重复副本）。
- **仍需做**：
  1. [H] 在 `read_main_level_records` / `read_sub_level_records` 中新增 `elif freq == '1m'` 分支，调 `read_tdx_1min_file(min_file, ...)`（`min_file` 指向 `fzline/xxx.lc1`）。
  2. [F] 前端放开股票 1 分：`btn-1m.disabled = !isFutures` 须改为股票也启用。
  3. [D] `STOCKS_LOOKBACK_CONFIG` 加 `'1m'`（条数克制，数据量大）。
  4. 步骤 2：把 `'1m'` 加进 `STOCKS_FREQS`。
  5. [G] 纳入双窗（已拍板）：把 `'1m'` 加进 `_STOCKS_DUAL_PAIRS` 及对应副窗频率集合（可参考既有的 `_FUTURES_SUB_FREQ_MAP` 写法）。
