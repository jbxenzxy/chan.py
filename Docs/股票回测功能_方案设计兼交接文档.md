## §1 结论先行

### 1.1 一句话结论

**新增一个与 `Trading/` 平级的顶层包 `Backtest/`，用"钉死五条契约 + 放开插件实现"的方式搭框架**，把现役股票页那套「**一个买卖点 → 出场 → 单笔结果**」的推演（`App/AppTPSL.py::compute_stock_tpsl`，网页右键止盈止损就是它）泛化成「**N 笔 × M 标的 × K 级别**」。三样现成资产直接复用——缠论引擎增量推进、`Trading/Strategy/Exit.py::LayeredExitPolicy` 出场口径、`Trading/Infra/TradeStats.py::compute_trade_stats` 绩效统计；**不复用 `Trading/Engine/Engine.py`**（期货语义焊死在决策链里，剥离成本 ≈ 重写）。

**F3 专述（用户反馈"没看懂"，这里说透）**

实测（探针 `sandbox/probe/poc2_scale.py`，可复跑）：

| 数据 | 步数 | bsp 事件累计 | **去重后信号数** | 耗时 | 单步 |
|---|---|---|---|---|---|
| 日线 500 根（单一标的） | 500 | 91 | **1** | 0.05 s | 0.11 ms |
| 60m 500 根 | 500 | 1246 | 6 | 0.08 s | 0.16 ms |
| 60m 1000 根 | 1000 | 6815 | 19 | 0.19 s | 0.19 ms |
| 60m 2000 根 | 2000 | 38532 | 36 | 0.81 s | 0.41 ms |

> 三种 `bs_type` 口径（默认 / 放宽 / 全开）结果完全一致 —— 已独立确认 `CChanConfig({"bs_type":...})` → `CPointConfig.target_types` 随入参变化，**配置确实生效**，三条一致是数据本身所致。

**为什么"1 个信号"就没有统计意义**：

- 1 笔交易 ⇒ 胜率只能是 0% 或 100%；盈亏比 = 这一笔的盈亏比；夏普 / 最大回撤 / 卡玛全是**单点噪声**，不是统计量。
- Backtrader 官方 `SQN` 明确写了「**可靠需要 trades ≥ 30**」—— 业界对"最少样本"的共识就是这个量级。
- 所以这句话**不是"回测引擎有 bug"，而是"喂进去的样本量不够"**。任何回测引擎，你喂 1 笔，它都只能给你 1 笔的结论。

**要拿到可信结论，样本必须 ≥ 30 笔**，两条路：

- **横向**：多标的。20 只股票 × 平均 1.5 笔/500 根日线 ≈ 30 笔。
- **纵向**：子级别。60m 2000 根 → 36 笔（实测）。另：`Test/snapshots/multilevel_d_30m.json` 里子级别 30m 有 **53 个**买卖点，主级别日线只有 1 个 —— 双窗是提密度的有效手段。

**F3 对框架的意义（这是关键）**：既然统计意义**必然**要求多标的或多级别，那么 ——

> `universe`（标的集合）和 `lv_list`（级别组合）**必须是 Runner 的一等参数，且 `Portfolio` 从第一天就按多 symbol 建账**；否则二期要加多标的时就得改内核数据结构 —— 那正是用户反馈 ⑷ 担心的"框架跟着改动"。

**F3 是对框架形状的要求，不是对某一次回测的要求。**（初版把它写成"回测必须走多标的或子级别双窗"，含糊，这里说清了。）

## §2 现状盘点（全部为代码事实）

### 2.1 缠论引擎侧（可直接用的入口）

| 能力 | 稳定锚点 | 说明 |
|---|---|---|
| 增量推进（**回测主入口**） | `Chan.py::CChan.step_load` | 调用一次 = 清空重建 + 逐根 yield `self`。**每调一次都 `do_init()` 全量重建**，所以一个标的只能调一次、在循环里取快照 |
| 外部喂 K 线 | `Chan.py::CChan.trigger_load` | **全仓零调用点（死接口）**。能力存在但无人验证，一期不依赖 |
| 取买卖点 | `Chan.py::CChan.get_latest_bsp`（`number=0` 取全部） | 内部走 `BuySellPoint/BSPointList.py::CBS_PointList.get_latest_bsp` |
| 买卖点对象 | `BuySellPoint/BS_Point.py::CBS_Point` | 字段 `bi` / `klu` / `is_buy`（**布尔属性不是方法**）/ `type` / `features` / `is_segbsp`；**没有 price 字段** |
| 买卖点价格口径 | 成交价 = `bsp.klu.close`；绘图 = `klu.low`(买)/`klu.high`(卖) | 三处消费方同构：`App/AppEngine.py` 主级别与子级别、`App/AppSSE.py` 期货侧 |
| 分型极值（止损参考） | `bsp.bi.get_end_klu()` → `.low`/`.high` | 与 `Trading` 的 `fractal_low/fractal_high` 是同一个量 |
| 市场类型 | `CChan(market_type="stock")` | **必传**：`BuySellPoint/BSPointList.py::check_nesting_divergence` 里 `market_type is None` 直接 `raise RuntimeError` |

**回测必须处理的结构事实**：

- **笔买卖点不会被撤销**。`BuySellPoint/BSPointList.py::CMyBSPointList.cal` 不调用 `clear_store_end()`（全仓该方法的唯一调用点在 `CBSPointList.cal`，即**线段**买卖点路径）。⇒ 笔买卖点一旦入 store 就永久存在。
- **因此同一笔延伸会产生"漂移的重复买卖点"**：`add_bs` 用 `(bi.idx, cur_klu.idx)` 做键，而锚点 K 线由 `_cur_anchor_klu(bi)` 现算 —— 笔一延伸，锚点移动，旧锚点的 bsp 与新锚点的 bsp 并存。⇒ **回测必须自己做信号去重**，否则同一笔会被反复交易。
- **线段买卖点会被撤销**（`clear_store_end` pop 并清 `bi.bsp`）。若将来消费 `seg_bs_point_lst`，必须逐步推进 + 每次重取快照。

### 2.2 股票数据侧

| 数据源 | 股票历史能力 |
|---|---|
| `DataAPI/TdxAPI.py::CTdxAPI` | ✅ **日/周 + 30m/15m/5m（由本地通达信文件合成）**，含 vol/amount，含前复权。入口 `read_main_level_records` |
| `DataAPI/BaoStockAPI.py::CBaoStock` | ✅ 日/周/月 + 5/15/30/60 分钟（需登录） |
| `DataAPI/csvAPI.py::CSV_API` | ✅ 但列固定 `time,open,high,low,close`，**volume/turnover 被注释掉**，文件须放仓库根、命名 `{code}_{freq}.csv` |
| `DataAPI/AkshareAPI.py::CAkshare` | ⚠️ **仅日/周/月**，分钟级直接 `raise` |
| `TqSdkAPI` / `TqSdkCSSESource` | ❌ 期货 / 实时流 |
| `ElTdxAPI` / `SinaAPI` / `TxAPI` | ❌ 基本面/名称，非 K 线源 |
| `waditu/tushare` | ❌ **本项目不引入**：`TdxAPI` 走本地通达信文件，离线、含 `end_date` 复权锚点 |

**回测数据源首选 `TdxAPI`**，理由只有一条：它提供 `end_date` 参数，前复权只以该日为最新锚点递推 —— 这是**全仓唯一天然防未来函数（复权口径）的数据路径**。

其他必须记住的口径：

- **股票周期集合** `Common/CEnum.py::STOCKS_FREQS` = `{w, d, 30m, 15m, 5m}`。**60m 不在其中**（`Test/fixtures/stock_60m.json` 存在且能算，但不在产品开放列表）。
- **股票 K 线 `dt` = 结束时间**（期货相反）。日/周线 dt 为 00:00，靠 `_STOCKS_EOD` 补齐语义。

| 成交统计 | `Trading/Infra/TradeStats.py::compute_trade_stats` | **输入是 `List[Dict]`，不依赖 sqlite**，造出同键 dict 就能用。输出含 `count/wins/losses/flat/win_rate/avg_win/avg_loss/profit_factor/pl_ratio/total_net/max_win/max_loss/expectancy/equity_curve/by_reason/by_bsp_type`。硬耦合只有 `net_cash` 与 `signal_key` 两个键名 |
| **分层出场策略** | `Trading/Strategy/Exit.py::LayeredExitPolicy`（`plan()` / `check()` / `on_bar()`） | **回测最该复用的一块**。L1 结构 R / L2 ATR / L3 保本+跟踪。已有股票侧先例：`App/AppTPSL.py` 直接 `LayeredExitPolicy(dict(_STOCK_EXIT_OVERRIDES))` |
| 撮合思路 | `Trading/Broker/DryRun.py::DryRunBroker.submit` | 固定 tick 滑点 + 立即全量成交。**只有这一种成交模型**，无流动性/部分成交 |

**不可复用（期货专属，改动即破坏语义）**

| 期货概念 | 锚点 |
|---|---|
| 平今/平昨 | `Trading/Infra/Records.py::OrderIntent.CLOSETODAY`；`Trading/Engine/Engine.py::_decide_exit` 的 CLOSETODAY 分支 |

| 交割月护栏 | `Trading/Infra/Instrument.py::delivery_guard_blocked` |
| 夜盘归属次一交易日 | `Trading/Infra/Clock.py::NIGHT_SESSION_START_HOUR` / `trading_day_of_ms` |
| 手数派生 | 按品种表 `lots_per_order`，**不是按资金** |

**`Trading/` 里已有的"半个回测"**：`Trading/Tool/Recorder/Analyze.py::backtest` —— 它是**离线信号复盘 + 单参数网格扫描**，不是组合级回测：

- 输入是**已录好的信号**（`signals.json`），不是让策略在历史 K 线上重算信号；
- 硬编码期货 IF 默认值（`DEFAULT_MULTIPLIER=300.0` 等），乘数是单一标量；
- **不复用 `LayeredExitPolicy`**，只有"固定点数止盈 + 信号 K 线极值止损"；
- **无持仓互斥**：所有信号并列独立结算，没有"运行态占仓时不接受新信号"的约束。

⇒ 定位为"**信号质量快速体检工具**"，**不是**本次要建的东西，也**不冲突**（两者可并存）。

### 2.4 股票路径：现役的「单笔回测」（最直接的复用资产）

用户反馈 ⑴ 指的就是这条链。**完整链路**：

| 环节 | 锚点 |
|---|---|
| 右键菜单：仅**股票页** + 命中 0123 类买卖点的 K 线才显示「止盈止损」 | `Frontend/app.js` 里 `_tpslHit` 的判定 —— `!isFuturesMode() && _tpslBspCandidates(date).length > 0` |
| 菜单项 DOM | `Frontend/app.html` 的 `annotation-menu-tpsl` / `annotation-menu-tpsl-cancel` 两个 id |
| 路由 | `FrontAPI.py::api_stocks_tpsl`（`POST /api/stocks/{code}/tpsl`） |
| 编排 | `App/AppOrch.py` 的 dispatch 白名单含 `"call_stock_tpsl"` |
| 漏斗壳 | `App/AppChart.py::call_stock_tpsl` |
| 推演主体 | `App/AppTPSL.py::compute_stock_tpsl` |

`compute_stock_tpsl` 实际做的事 —— **它本身就是一个"单笔回测"**：

| 步骤 | 锚点 |
|---|---|
| 构造 `Signal.from_bsp(bsp, symbol, freq)`；`Instrument(product=None)`（无品种档案，不做 tick 对齐） | `compute_stock_tpsl` 组装段 |
| 入场价 = 信号根收盘价，与信号根 `close` 不一致直接 `BadRequestError` | `compute_stock_tpsl` 的 `bsp.price` 一致性校验 |
| 股票侧显式口径 `_STOCK_EXIT_OVERRIDES = {"win_loss_ratio": 3.0, "trailing_trigger_r": 1.0}`（**不跟 .env / 品种档案 / 模型默认**） | `App/AppTPSL.py::_STOCK_EXIT_OVERRIDES` |
| ATR 预热 60 根 | `App/AppTPSL.py::_WARMUP_BARS`（覆盖 `atr_period+1=15`，取整 60） |
| 生成 `ExitPlan`（风控锚 = 入场收盘价） | `compute_stock_tpsl` 里的 `LayeredExitPolicy.plan(sig, entry_price, inst)` |
| 从**入场根的下一根**起逐根 `on_bar` + `check`，`not chk.only_update` 为终态离场 | `compute_stock_tpsl` 的逐根推演循环 |
| 输出 `entry / r / a / b / atr / segments / current / exit / terminal / params` | `compute_stock_tpsl` 的返回结构 |
| 守护测试 | `Test/test_stock_tpsl.py`（已在门禁 `COMPONENTS` 里，条目名 `stock_tpsl`） |

**对回测框架的意义（这条最关键）**：回测框架要做的**不是从零造一套交易逻辑**，而是把这条现成的 `1 笔` 泛化成 `N 笔 × M 标的 × K 级别`。这带来两个白送的东西：

1. **复用**：出场逻辑不用重写，写个 Adapter 就能进框架（§6）；
2. **对照基准**：框架跑"单标的、单信号"必须能与网页推演**逐字段对拍** —— 这是一条极强的护栏，能一次性证明框架的时间口径和出场口径没跑偏（§7 G6）。

## §3 业界方案调研

### 3.1 czsc（waditu/czsc；`crates.io/crates/czsc` 是其 Rust 核心）

**核心抽象：`Signal → Event → Position` 三层**（`czsc/objects.py`，v0.9.x）。

| 层 | 关键字段 |
|---|---|
| `Signal` | `signal / k1/k2/k3 / v1/v2/v3 / score`（`key` 唯一串，`is_match(s)` 匹配） |
| `Event` | `operate ∈ {LO, LE, SO, SE}` + `factors`（`signals_all/any/not` 的逻辑组合） |
| **`Position`** | **`symbol / opens / exits / interval / timeout / stop_loss(BP) / T0 / name`** |

**`Position.update(s)` 逐根驱动（最值得抄的一段）**：① 拒绝时间倒流；② 第一个 `is_match` 命中的给 `op`；③ **开仓**：`LO` 且 `pos != 1` 且距上次开多 > `interval`；④ **出场三选一**（全是 Position 内置参数，不是策略逻辑）：`LE` 命中 / 跌破 `stop_loss` / 超过 `timeout`；⑤ **T0 门**：所有出场被 `self.T0 or dt.date() != self.last_lo_dt.date()` 包住 —— **这就是 A 股 T+1 的等价物**；⑥ 每步 append 一条 `{"dt","pos","price"}`。

**产出三件套**：`operates`（操作流）/ `holds`（持仓快照流）/ `pairs`（开平交易对，含持仓 K 线数/事件序列/持仓天数/盈亏比例 BP）。**绩效**：`Position.evaluate_holds()` → `覆盖率/夏普/卡玛/最大回撤/年化收益/日胜率`；组合层交给 wbt。

### 3.2 wbt（zengbin93/wbt）—— 组合层的"统一回测原理"

- **输入契约极简**：`dt / symbol / weight / price` 四列。
- **原理（README 原话）**：「给定 `(dt, symbol, weight, price)`，资金曲线盈亏是权重变化与 bar 收益的确定性函数。其它一切——日度归因、多空拆分、回撤、交易对、相对基准的超额——都从这一次计算派生，**算一次、处处复用**」。
- **明确列入"非目标"**：逐笔撮合与盘口微观结构、交易所撮合机制级高频细节、券商特定执行细节。
- API：`WeightBacktest(df, digits, fee_rate, n_jobs, weight_type)`；`stats / long_stats / short_stats / daily_return / alpha / pairs / aggregated_pairs / key_trades / to_result / segment_stats / is_good_strategy`；独立工具 `daily_performance` / `top_drawdowns` / `calculate_position_risk`。

### 3.3 Vespa314/chan.py —— **本仓库的上游，回测范式可直接抄**

公开版只有 `Debug/strategy_demo*.py`（完整版 `ModelStrategy/backtest.py` 未开源），但那两个 demo 就是**针对本仓库 `CChan` 的回测范式**：

```python
config = CChanConfig({"trigger_step": True, ...})
chan = CChan(code=..., data_src=..., lv_list=[KL_TYPE.K_DAY], config=config, autype=AUTYPE.QFQ)
for chan_snapshot in chan.step_load():          # ① 逐根推进
    bsp_list = chan_snapshot.get_latest_bsp()   # ② 取最新买卖点
    last_bsp = bsp_list[0]
    if BSP_TYPE.T1 not in last_bsp.type and BSP_TYPE.T1P not in last_bsp.type:
        continue                                 # ③ 按类型过滤
    cur_lv_chan = chan_snapshot[0]
    if last_bsp.klu.klc.idx != cur_lv_chan[-2].idx:
        continue                                 # ④★ 防未来函数：锚点必须是"倒数第二根"已确认合并K线
    if cur_lv_chan[-2].fx == FX_TYPE.BOTTOM and last_bsp.is_buy and not is_hold:
        last_buy_price = cur_lv_chan[-1][-1].close   # ⑤ 成交价 = 最后一根原始K线 close
```

⑤ 是**乐观口径**（信号确认当根收盘成交）。本文 §5 D1 建议默认改成下一根开盘价。

`strategy_demo2.py` 演示 `trigger_load()` 外部喂 K 线；`strategy_demo3.py` 演示小级别驱动大级别 + `copy.deepcopy` 快照。

### 3.5 Backtrader —— 经典事件驱动（订单/佣金/仓位/分析器四分离）

Python 回测框架的事实标准，零外部依赖（除绘图）。**四个可插拔件**：

| 件 | 类 | 职责 |
|---|---|---|
| 数据 | `DataFeed` | CSV / pandas / 在线源；多标的、多周期、resample / replay |
| 策略 | `Strategy`（`next()` 每根一次，`notify_order/notify_trade` 回调） | 产生订单 |
| 佣金 | `CommissionInfo`（`commission/mult/margin/stocklike`） | **把"股票型"与"期货型"成本模型分成两种** |
| 仓位 | `Sizer` | `FixedSize` / `PercentSizer` / `AllInSizer` |
| 撮合 | `BackBroker`（Market/Close/Limit/Stop/StopTrail/OCO/bracket、滑点、volume filling） | 订单生命周期 |
| 绩效 | `Analyzer` | `SharpeRatio` / `DrawDown` / `TradeAnalyzer` / `SQN` / `Returns` / `TimeReturn` / `Transactions` / `VWR` |

**对本项目直接有用的三点**：

1. `TradeAnalyzer` 的统计维度清单是业界最完整的一份之一：总/开/平笔数、**连胜连败**、净盈亏总/均/最大、多空分别统计、**持仓长度(bars in market) 总/均/最大/最小并按胜负分拆**。本项目 `compute_trade_stats` 缺"持仓长度分布"与"连胜连败"，可按此补。
2. **`SQN`** = `sqrt(N) × mean(PnL) / std(PnL)`（Van K. Tharp），官方明确「**可靠需要 trades ≥ 30**」。这**正好是 F3（信号稀疏）的解药** ⇒ **纳入强制指标，样本 < 30 时打警告**。
3. **反面对照**：`Cheat-on-Close` / `Cheat-on-Open`（`cerebro.broker.set_coc(True)`）—— 即"以当前未收盘价成交"，是**明确的未来函数开关**。⇒ 我们的成交模型绝不能实现等价物。

### 3.6 VN.PY —— 国内实盘同源回测（逐日结算 + 参数优化）

`vnpy_ctastrategy/backtesting.py::BacktestingEngine`：

| 项 | 内容 |
|---|---|
| 参数 | `rate` / `slippage` / `size`（合约乘数）/ `pricetick` / `capital`（默认 1,000,000）/ `annual_days`（默认 **240**）/ `mode` / `inverse` |
| 主流程 | `set_parameters` → `add_strategy` → `load_data` → `run_backtesting` → `calculate_result` → `calculate_statistics` → `show_chart` |
| 撮合 | `new_bar` → `cross_limit_order` → `cross_stop_order`；`update_daily_close` 做**逐日盯市结算** |
| 绩效 | `total_net_pnl` / `daily_net_pnl` / `total_commission` / `total_slippage` / `total_turnover` / `total_trade_count` / `total_return` / `annual_return` / `max_drawdown` / `max_ddpercent` / **`max_drawdown_duration`（最长回撤天数）** / `sharpe_ratio` / `ewm_sharpe` / **`return_drawdown_ratio`** |

**借鉴**：① **逐日盯市结算**（`DailyResult` + `update_daily_close`）—— 日频 equity curve 照此做；② `max_drawdown_duration` 与 `return_drawdown_ratio` 是 `compute_trade_stats` 没有的，建议补；③ **`annual_days=240`**（A 股年交易日），年化要显式声明，别默认 252；④ GA 扫参留作 P3 可选。

⚠ **VN.PY 不解决 A 股股票**：`size`/`pricetick`/`inverse` 都是合约语义，本质是期货引擎；股票需 `size=1`、`pricetick=0.01`，但**没有 T+1 与整手**。⇒ 只能借鉴**结算与统计层**，不能借鉴撮合层。

### 3.7 Qlib —— A 股约束建模最全的一份（**重点参考**）

`qlib/backtest/exchange.py::Exchange` 是本次调研里**唯一把 A 股交易规则完整建模**的实现：

| A 股约束 | Qlib 实现 | 默认 / 说明 |
|---|---|---|
| **涨跌停** | `limit_threshold` + `check_stock_limit()` + `_get_limit_type()` / `_update_limit()` | 未设置时**主动 `logger.warning`**："The stocks hit the limit may be bought/sold" |
| **停牌** | `check_stock_suspended()` / `is_stock_tradable()` | 判据：`$close is None` |
| **整手** | `trade_unit`（注释明写"**100 for China A market**"）+ `round_amount_by_trade_unit()` | 用 `kwargs.pop("trade_unit", ...)` 区分"未设置"与"禁用" |
| **费率** | `open_cost=0.0015` / `close_cost=0.0025` / `min_cost=5.0` | 买卖不对称 + **单笔最低 5 元** |
| **成交量限制** | `volume_threshold` + `_clip_amount_by_volume()` | 单笔成交不超过当日成交量的一定比例 |
| **成交价口径** | `deal_price`（`$close` / `$open` / `$vwap`，买卖可分别指定） | **这是 §5 D1 的业界标准答案**：成交价是可配置表达式，不是硬编码 |
| 资金约束 | `_get_buy_amount_by_cash_limit()` | 可用现金决定可买量 |

**⚠ 必须如实指出的缺口**：在 `qlib/backtest/{exchange,account,position}.py` 三个文件里 grep `T+1` / `sellable` / `tradable_amount` → **0 命中**。⇒ **Qlib 不建模 A 股 T+1**。

### 3.9 Ziplime —— Zipline 的 Polars 重构

保留 Zipline 的 `initialize` / `handle_data` / `run_algorithm(...)` 语法；数据层用 Polars 重写；主打特性之一是「**Live: Use identical strategy implementations between backtesting and live deployments**」。

**借鉴点只有一个，但很重要**：**"回测即实盘同一份实现"** —— 与本文 §5 D2（必须复用 `LayeredExitPolicy`）是同一个原则，只是我们把它收窄到"出场口径必须同源"。⇒ 落为护栏 **G6**（§7）。

**不借鉴**：Polars（`requirements.txt` 已是 pandas，且实测性能足够，§2.5d）、AI 生成策略工作流。

### 3.10 六种回测接口范式对比（选型依据）

| 范式 | 代表 | 输入 | 撮合精度 | 适合 | 不适合 |
|---|---|---|---|---|---|
| **A. 事件-持仓驱动** | czsc `Position` | 逐 bar 信号 dict | 收盘价成交，无盘口 | 单标的择时、**A 股 T+1**（`T0=False`） | 高频、成交率建模 |
| **B. 目标权重序列** | wbt | `dt/symbol/weight/price` | 无（按权重估值） | 多标的组合、横截面 | 单笔止损止盈细节 |
| **C. 订单/成交驱动** | Backtrader、Zipline | 订单流 | 可细（限价/止损/跟踪单） | 精确订单语义 | 慢、复杂、**易写出未来函数（`coc`）** |
| **D. 固定金额下注** | chanlun-pro | 信号 + 固定金额 | 收盘价 | 快速评估信号胜率/盈亏比 | 组合与资金曲线 |
| **E. 逐日盯市结算** | VN.PY | bar 序列 + 合约参数 | 含 `cross_limit/stop_order` + 每日 `update_daily_close` | 与实盘同源 | 股票（无 T+1/整手） |
| **F. 权重→订单 + 交易所约束** | Qlib `Exchange` | 目标权重/金额 → 订单 | **含涨跌停/停牌/整手/费率/成交量（无 T+1）** | A 股多因子组合 | 单笔出场细节（L1-L3 这类） |

**本文选型 = A（主体）+ D（仓位默认值）+ E（结算层）+ B（P3 聚合层），并局部吸收 F 的 A 股约束项。** 理由：

- 本项目信号天然是**稀疏离散事件**（一条买卖点 = 一次可能的操作），A 范式最贴合；
- D 作为默认仓位口径，因为项目没有任何资金管理模型，引入权重模型要连带引入"初始资金/再平衡/杠杆"，一期不做；
- E 的**逐日盯市结算**是 equity curve 与年化/回撤指标的基础，成本极低，直接采纳（`annual_days=240`）；
- F 只吸收"**整手 + 买卖不对称费率 + 单笔最低佣金 + 成交量上限**"（都不需要额外数据）；**涨跌停/停牌因缺板块与 ST 标识、且复权价下前收需还原，一期不做**（§10 U7）；
- **不采纳 C**：订单/成交驱动会引入限价单/止损单的完整生命周期，而本项目出场已由 `LayeredExitPolicy`（价格线逐级改写）表达，再做一层订单语义是重复建模，且是未来函数的高发区。

## §4 框架设计（本文主体 · 对应反馈 ⑷）

> 用户关切原话：**"框架搭好了，后面细节可以在不改动框架的前提下慢慢补。但如果框架不好，后面增加或删除细节，框架就要跟着改动，那就麻烦大了。"**

### 4.1 核心思想：钉死「契约」，放开「实现」

**框架要钉死的不是"有哪些功能"，而是"功能之间对话的 5 条契约"。只要契约不变，功能是加是删，内核一行不动。**

### 4.2 五条契约（这就是框架全部的"不可变"）

#### 契约 C1 · 时间契约 —— **唯一真正不能动的一条**

- 一根 bar = 一个时间步。
- **不变量**：处理第 i 根 bar 时，任何组件可访问的数据**严格限于 `bar[0..i]`**。框架只把 `HistoryView`（只读切片）交给组件，组件**拿不到未来**。
- **决策 / 成交分离**：在 `bar[i]` 上产生的决策，**最早在 `bar[i+1]` 成交**。
- 这条是回测可信度的唯一来源，也是 §7 的 G1~G3 要测的东西。

#### 契约 C2 · 信号只是「意图原料」，不是订单

- 信号源产出 `Signal(time, symbol, side, anchor_price, meta)` —— **不产出订单**。
- 由 `Strategy`（仓位策略）翻译成 `Intent(action, symbol, target_qty)`。
- ⇒ 换缠论参数 / 加信号过滤 / 换信号源，都只是换 `Plugins/` 里的对象，不动循环。

#### 契约 C3 · `Intent → Order → Fill` 三段分离（都是纯函数）

| 段 | 输入 | 输出 | 这里替换什么 |
|---|---|---|---|
| `Sizing` | intent + 账户状态 + bar | `Order`（含整手化后的 qty） | 固定 200 股 / 固定金额 / 固定比例 |
| `Constraint` | Order + 账户 + bar | `Order`（裁剪后）或 `None` | T+0/T+1、涨跌停、停牌、资金不足、成交量上限 |
| `Broker` | Order + bar | `Fill`（成交价 / 成交量）或 `None` | 下一根开盘 / 信号根收盘 / VWAP / 加滑点 |

三段**都是无副作用的纯函数** ⇒ 可单独单测、单独替换、组合出任意口径。

#### 契约 C4 · 出场是「外挂状态机」，不是循环的分支

接口**直接沿用现役 `LayeredExitPolicy` 的三方法**（因为是现役口径，框架去适配它，不是反过来）：

- `on_bar(bar, inst)` → 更新内部状态（ATR / 极值）
- `plan(signal, entry_price, inst)` → `ExitPlan`
- `check(pos, bar, inst)` → `ExitCheck | None`

⇒ 换「固定止盈止损」/「持有到反向信号」/「ATR 跟踪」= 换对象。现役策略写个 Adapter 就进框架，零改内核。

#### 契约 C5 · 绩效只吃 `trades + equity`

- 输入 = `(trades: List[Trade], equity: Series)`，输出 = `Dict[str, float]`，**与回测过程完全解耦**。
- 指标注册表 `@register("sharpe")`；**增删指标 = 增删函数**。
- 一期直接复用 `Trading/Infra/TradeStats.py::compute_trade_stats`（交易级）+ 新增日频指标（年化 / 夏普 / 卡玛 / 最大回撤 / **SQN**）。

### 4.4 主循环（伪代码 · C1 的落地）

```python
for i, bar in enumerate(feed):
    # ① 先成交上一根留下的挂单（用本根的价格）—— 这是"决策/成交分离"的落地
    for od in pending:
        fill = broker.fill(od, bar, intrabar=None)      # 默认 bar.open
        if fill:
            cash_delta = cost.compute(fill)             # 佣金/印花税/过户费
            portfolio.apply(fill, cash_delta)
            if fill.is_open:
                portfolio.lot(fill).exit = exit_policy.plan(fill.signal, fill.price)
    pending.clear()

    # ② 再判出场（用本根的已收盘信息）
    for lot in portfolio.open_lots():
        lot.exit.on_bar(bar)
        chk = lot.exit.check(lot, bar)
        if chk and not chk.only_update:
            pending.append(Order(lot.symbol, CLOSE, lot.qty, reason=chk.reason))
        elif chk and chk.plan:
            lot.exit = chk.plan                          # 保本/跟踪抬价

    # ③ 最后处理新信号（hist 右端 = i，看不见未来）
    for sig in signal_src.new_signals(clock.view(upto=i)):
        intent = strategy.decide(sig, portfolio)         # 占仓互斥在这里
        if not intent: continue
        od = sizing.size(intent, portfolio, bar)         # 整手 200 在这里
        od = apply_all(constraints, od, portfolio, bar)  # T+0 / 资金 / 涨跌停 / ...
        if od: pending.append(od)                        # 下一根才成交

    # ④ 记账：equity[i] = cash + Σ qty × close（逐日盯市，照 VN.PY）
    clock.advance(bar)
```

三条纪律（写进 `Core/Engine.py` 的注释，防后来者当 bug 修）：

- `step_load()` 每次调用都 `do_init()` 全量重建 ⇒ **一个标的只调一次**，在循环内取快照（O(n²) 陷阱）；
- **每根不要拉全量买卖点**，只取"本次新出现"的键（去重键即可判新）—— 单步成本随存量增长（§2.5d 实测）；
- 信号必须**去重**（笔延伸会产生漂移重复点，§2.1）。

### 4.6 反过来：什么会逼你改框架？（以及框架怎么预留）

诚实列出会冲击框架的四个方向。**"框架好"的标志是：现在不实现，但接口现在就留好，将来只加不改。**

| 未来方向 | 会冲击什么 | 预留方式（内核现在就写好，一期不启用） |
|---|---|---|
| **A. 盘中撮合 / bar 内触发止损**（现在是一 bar 一步 ⇒ 止损实际在收盘才判定，偏乐观） | `Clock` 的"一根 bar 一步"语义；`Fill` 只吃一根 bar | `Broker.fill(order, bar, intrabar=None)` 预留 `intrabar`；`Clock` 预留 `substeps`。一期恒传 `None` ⇒ 语义不变 |
| **B. 做空 / 融资融券** | `Portfolio` 只能记多头 | `Portfolio(allow_short=False)` 开关 + `Lot.qty` 允许负值；一期恒 `False` |
| **C. 组合层资金分配**（多标的怎么分钱） | 现在每个标的独立建仓 | 预留 `Allocator` 扩展点（一期 `NoopAllocator`）；二期 `EqualWeight` 或 wbt 式权重 |
| **D. 复权口径切换** | 影响成交价与股数 | `Plugins/Data/` 的 `adjust` 参数；且**整手与费率必须按不复权价算** —— 这条现在就要定死 |

**D 是唯一一个"现在不定死、以后必返工"的**，所以放进 §5 硬口径 D5。

## §6 与现役股票推演的关系：复用 + 对拍

- **复用**：`Plugins/Exit/Layered.py` 直接包 `Trading/Strategy/Exit.py::LayeredExitPolicy`，参数用 `App/AppTPSL.py::_STOCK_EXIT_OVERRIDES`。
- **对拍（白送的护栏）**：框架跑「单标的、单信号、从入场根推到末根」，结果必须与 `compute_stock_tpsl` 的 `exit / terminal / r_multiple` **逐字段相等**。这一条能一次性证明框架的时间口径和出场口径都没跑偏。
- **必须承认的差异**：

| | 入场价 | 锚点 |
|---|---|---|
| 网页推演 | 信号根收盘价（不一致直接 `BadRequestError`） | `compute_stock_tpsl` 的 `bsp.price` 一致性校验 |
| 框架默认 | 下一根开盘价（D1） | `Plugins/Fill/NextOpen` |

## §11 风险与已知边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| **信号稀疏 → 结论过拟合** | 单标的单周期信号个位数（F3），任何"胜率 100%"都没有意义 | P2 强制多标的；报告强制输出**样本量 `count`** 与 **SQN**，样本 < 30 时打警告 |
| **回测与实盘分叉** | 若自写出场逻辑，回测结论无法外推 | D2 硬约束：必须复用 `LayeredExitPolicy`；G6 强制对拍 |
| **乐观偏差（涨跌停/停牌）** | 一期不建模（D6），会在涨停板买入等场景高估收益 | 报告显式标注；`Feed` 提供 `vol==0` 的停牌判据（成本为零，先做） |
| **乐观偏差（bar 内触发）** | 一 bar 一步 ⇒ 止损实际在收盘才判定 | 报告标注；`Broker.fill(..., intrabar=)` 已预留（§4.6-A） |
| **性能：每根拉全量买卖点** | 单步成本随存量增长（实测 0.11 ms → 0.41 ms） | §4.4 纪律②：只处理新增键 |
| **O(n²) 陷阱** | `step_load()` 每次调用都 `do_init()` 全量重建 | 一个标的**只调一次**，在循环内取快照 |
| **术语护栏** | 新增文案可能踩禁用词 | 交付前必跑 `test_p26_terminology_guard.py` |
| **门禁文档失同步** | 加 `COMPONENTS` 忘改 `run_all_tests.py` 写死的 142 | §8 已列为改动分内事 |
