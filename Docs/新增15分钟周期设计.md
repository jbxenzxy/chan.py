# 股票场景新增 15 分钟周期 —— 设计文档

## 1. 需求确认

1. **股票周期列表**：现有 `周K / 日K / 30分 / 5分`，新增一个 `15分`。
2. **单窗 ↔ 双窗切换**：默认上下窗配对**保持不变**（周K-日K、日K-30分、30分-5分）；仅在进入双窗、且焦点在下窗时，上下窗**可自由指定 15 分**（作为上窗或下窗）。
3. **数据合成**：15分 与 30分 一样，均**由 5 分钟线（.lc5）合成**，前复权等处理与 30分 完全一致（先对原始 5m 前复权，再做周期合成，避免二次复权）。
4. **先出设计文档，确认后再改代码。**

***

## 2. 关键结论（前置分析）

代码审计后确认几个关键事实，直接决定改动范围：

* 枚举 `KL_TYPE.K_15M` **已存在**（`Common/CEnum.py`，值为 12），缠论内核本身支持 15 分钟级别，无需动内核。

* 频率字符串 `'15m' → 900 秒` 的映射在 `CTqSdkAPI.FREQ_SEC_MAP` 和 `App/utils._FREQ_SEC_TO_KL` 中**均已存在**，`_get_kl_type('15m')` 无需改动即可正确解析。

* CSV 选点列 `FREQ_TO_COL['15m'] = '15m'` 与 `SAVED_POINT_COLUMNS` 的“15分选点”**已存在**，选点落库无需新增列。

* 真正的缺口集中在：**① 数据取数/合成层**（TdxAPI 未识别 `'15m'` 会落到日线文件分支）、**② 后端双窗配对空间/周期时长表**、**③ 买卖点区间套的 KL\_TYPE↔freq 映射**（漏了 K\_15M 会直接抛 `主级别映射缺失` 运行时错误）、**④ 前端周期按钮/输入框/双窗配对/时间格式化**。

> ⚠️ 特别注意：`BuySellPoint/BSPointList.py` 的 `_KL_TYPE_TO_FREQ` 没有 `K_15M`，一旦构建 15m 图表且开启买卖点，`check_nested_diver` 会 `raise RuntimeError("主级别映射缺失")`。**必须补充该映射**，这是最容易遗漏的崩溃点。

## 3. 改动清单

### 3.1 后端 —— 数据取数与合成（`DataAPI/TdxAPI.py`）

**3.1.1 新增** **`_resample_5m_to_15m`（由 5m 合成 15m）**

将现有 `_resample_5m_to_30m` 泛化为一个按“目标周期分钟数”分桶的公共函数，再让 30m/15m 各自调用，避免复制粘贴：

```python
def _resample_5m(records, period_min, market="sh"):
    # 按 A股/港股交易时段，把每根 5m 归属到距离该时段起始点对齐的 period_min 边界桶
    # A股: 上午 9:30 起、下午 13:00 起；港股: 9:30/13:00 起
    # 30m 桶例: 10:00,10:30,11:00,11:30,14:00,14:30,15:00（与现行为完全一致）
    # 15m 桶例: 9:45,10:00,...11:30, 13:15,...,15:00（对齐会话起点派生）

def _resample_5m_to_30m(records, market="sh"):   # 保持现有函数签名不变
    return _resample_5m(records, 30, market)

def _resample_5m_to_15m(records, market="sh"):
    return _resample_5m(records, 15, market)
```

> 关键点：新 `_resample_5m` 的 30 分支必须与现有 `_resample_5m_to_30m` 输出**逐字节一致**，保证不回归现有 30m 行为。

**3.1.2** **`read_main_level_records`（主级别取数）**

* `.lc5` 文件选择分支：`if freq in ('30m', '5m')` → 改为 `if freq in ('30m', '15m', '5m')`。

* 新增 `elif freq == '15m':` 分支，完全复刻 30m 路径：

  ```python
  elif freq == '15m':
      raw_5m = read_tdx_min_file(data_file, market=market, aggregate_30m=False)
      did_adjust = False
      if _tdx_config["forward_adjust_enabled"]:
          raw_5m, did_adjust = _forward_adjust(raw_5m, ...)      # 先前复权（与30m一致）
      records_15m = _resample_5m_to_15m(list(raw_5m), market=market)  # 再合成，避免二次复权
      return (records_15m, raw_5m, did_adjust) if return_raw else (records_15m, did_adjust)
  ```

**3.1.3** **`read_sub_level_records`（双窗下窗取数）**

* `.lc5` 分支：`if sub_freq in ('30m', '5m')` → 加 `'15m'`。

* 合成判断：`if sub_freq == '30m':` → 改为 `if sub_freq == '15m': _resample_5m_to_15m(...)`（新增一行）或 `in ('30m','15m')` 内按目标周期分发。

**3.1.4 前复权**：与需求⑶一致 —— 15m 只在原始 5m 上做一次前复权后再合成，不在合成后的 15m 上二次复权。**无需改** **`_forward_adjust`**。

**3.2.2** **`_STOCKS_MAIN_PERIOD`（双窗下窗对齐）**

新增：

这是 `_stocks_sub_dt_algo`（下窗结束时间语义截断）与 `_build_sub_kl_times`（灰框对照表）所需的“主级别单根覆盖时长”。缺了 15m，双窗下窗对齐会退化为不过滤。

**3.2.3 `_DUAL_LV_LIST`（legacy 联立双窗）+ `_get_sub_klus`（灰框取数）**

> ⚠️ **关于「删 legacy」的判断（⑵ 排查结论）**：legacy 联立**不是废弃残留**，而是**受控的 A/B 实现**——
> 由环境变量 `CHAN_STOCK_DUAL_IMPL=independent|legacy` 切换，定位为「快照基线/回滚通道」
> （`AppEngine._stock_dual_impl`，唯一事实源），且 `Test/snapshot_runner.py` 会强制 `legacy`
> 跑快照对拍（`_force_dual_impl("legacy")`）。**直接删除会破坏快照/一致性测试与回滚能力，不可删。**
> 故对 15m 采取「最小扩展而非删除」：给 legacy 也补上 15m 映射，避免万一走 legacy 模式时崩溃。

`_DUAL_LV_LIST` 是 legacy 联立双窗（`AppEngine.py:L671`）的主/子级别列表，`_get_sub_klus`（`:L908`）供其灰框取数。前端主用 independent 路径，但为 legacy 通行不崩，一并补：

```python
_DUAL_LV_LIST = {
    'w':   [KL_TYPE.K_WEEK, KL_TYPE.K_DAY],
    'd':   [KL_TYPE.K_DAY,  KL_TYPE.K_30M],
    '30m': [KL_TYPE.K_30M,  KL_TYPE.K_5M],
    '15m': [KL_TYPE.K_15M,  KL_TYPE.K_5M],   # 新增
}
# _get_sub_klus：
elif main_freq == '15m':
    end = main_dt
    start = main_dt - timedelta(minutes=15) + timedelta(microseconds=1)
```

### 3.4 后端 —— 买卖点区间套映射（`BuySellPoint/BSPointList.py`）

**这是避免崩溃的必改项：**

```python
_KL_TYPE_TO_FREQ = { ..., KL_TYPE.K_15M: '15m', ... }   # 否则 check_nested_diver 抛“主级别映射缺失”
_FREQ_TO_KL_TYPE = { ..., '15m': KL_TYPE.K_15M, ... }
_STOCKS_SUB_FREQ_MAP = { ..., '15m': '5m' }             # 15m 主级别默认下窗 5m
_STOCKS_FREQ_SEC = { ..., '15m': 900 }                  # ★必加：否则红框/区间套 [C,D] 空
```

> **★ `_STOCKS_FREQ_SEC`（新增、需求⑵ 的关键缺口）**
> 独立双窗的红框边界纯函数 `_stocks_red_range_algo`（BSPointList.py:L1912）用
> `_STOCKS_FREQ_SEC.get(main_freq) / .get(sub_freq)` 换算 [C,D]；**该表只有 w/d/30m/5m，
> 缺 15m → 一旦 main 或 sub 为 15m，`get()` 返回 None，函数直接返回空字符串**。
> 后果：上窗15分或下窗15分时，红框中枢显示为空、买卖点区间套 `if not fx_a_sub_dt or not fx_b_sub_dt:_return True（按子级别背驰放行）` 静默失效。
> **补 `"15m": 900` 后**，逐组合验算均正确（股票 K 线 dt=结束时间）：
> - 上窗15m/下窗5m：C=A−900+300=A−10min（15m 起点后续首根完整 5m），D=B。
> - 上窗30m/下窗15m：C=A−1800+900=A−15min（首根 15m），D=B。
> - 上窗d(或 w)/下窗15m：走日期分支 → C=当日00:00（w=所在周周一）、D=右肩当日23:59，
>   全覆盖当日/当周全部 15m 线。

* **风险点 1（必查）**：`_KL_TYPE_TO_FREQ` 漏 `K_15M` → `check_nested_diver` 抛 RuntimeError。已列入必改。

* **风险点 2**：泛化 `_resample_5m` 后，30m 桶结果必须与旧实现一致（用现有 30m 快照/测试比对）。

* **风险点 3**：`freqLevel` 重编号后，期货侧 30m>5m>1m>15s 相对序必须保持（= 15s 只跟 1m/5m/30m 比较）。

* **边界**：`_get_kl_type` 走 `CTqSdkAPI.FREQ_SEC_MAP`，15m 已存在且与 AppSSE 期货映射同源，股票/期货互不串扰。
