0结论摘要

值得做、且范围比预期小：真正存在重复的是期货初始化片段——App/AppSSE.py 内至少 5 处各自完整的「connect → fetch_kline → set_data → 周期映射 → 建 CChan → step_load」，应收敛为一个公共构造函数。这是无行为变化的重构，风险低、收益明确。

要纠正上一版表述：「手动选点没走统一协议」的说法不准确。fetch_and_inject 的 source 参数实际是死参数（选了也一律委托 analyze_stock）；股票走 TdxAPI 读文件、期货走 CTqSdkSession.fetch_kline 属多源适配，不是重复，架构上本就应各自实现。把股票强行统一到 fetch_kline 是高成本低价值，建议不做。

给决策的一句话：若推进，建议只做「阶段 A + 阶段 B」（收敛 AppSSE 内期货初始化 5 处为单一 _build_futures_chan），不推进「阶段 C」（股票取数协议统一）。

1.2 易被误判为「重复」、实际不是的项

  • 股票 vs 期货取数：股票经 TdxAPI 读本地 .day/.lc1/.lc5 文件；期货经 CTqSdkSession().fetch_kline() 拉天勤。这是不同数据源的适配实现，属多源架构的正常形态，不算重复。
  • fetch_and_inject 的 source 参数：参数解析后未生效——该函数固定 return _m.analyze_stock(...)。它在 LOCK_POLICY 登记为 RAW、注释自述「阶段 5 拆分时收敛」，属于应清理的遗留接口，而非取数重复。

2.2 约束清单（决定拆分怎么做）

约束说明对方案的影响
锁分类SSE（SELF_CONTAINED，每连接独立 TqApi+CChan） 公共构造必须自含新建源对象，不得共享跨连接状态。

3拆分方案（分期）

阶段 A —— 抽公共「数据→期货 CChan」构造函数 推荐 · 低风险

在 App/AppSSE.py 新增模块级纯构造函数，收敛「set_data + 周期映射 + 建 CChan + step_load」：

def _build_futures_chan(records, symbol, freq_sec, config=None):
    """根据 records 构造期货 CChan 并全量消费。
    唯一来源：_get_kl_type(freq) + _make_chan_config()（消除三份 _freq_to_kl 与配置差异）。"""
    from ChanConfig import CChanConfig
    CTqSdkAPI.set_data(records, symbol=f"{symbol}:{freq_sec}")
    kl_type = _get_kl_type(freq_sec)
    config = config or _make_chan_config()
    chan = CChan(code=f"{symbol}:{freq_sec}", begin_time=None, end_time=None,
                 data_src="custom:TqSdkAPI.CTqSdkAPI", lv_list=[kl_type],
                 config=config, autype=AUTYPE.NONE, market_type="futures")
    for _ in chan.step_load():
        pass
    return chan, kl_type

替换范围（行为应零变化）：init_chan_symbol（L82–108）、双窗选点主/子（L945–960+、L865 附近）。验证：重跑 test_sse_gray、test_sse_sequence、snapshot_runner.py --all，期望全绿。

阶段 B —— 复用同一构造到静态期货路径 推荐 · 中低风险

让 _analyze_futures_internal 的「注入 + 建链」段（L498–527）改为调用 _build_futures_chan，并核对 CChanConfig() → _make_chan_config() 的配置差异是否影响静态输出。若不引入回归即合入；若有差异，则保留静态侧原配置、仅抽公共后由参数注入。验证：snapshot_runner.py --all（期货维度）+ 手动比对静态 /api/futures 输出。

阶段 C ——（建议不做）股票取数协议统一 不推荐

为 TdxAPI 补一个 fetch_kline 以匹配 CCommonStockApi 协议、让 _analyze_stock_internal 改走协议。代价：股票路径深度耦合前复权 / 时间截断 / 冷启动 / 选点回放，改动面大且横跨 snapshot 全部股票基线；而收益仅是「概念统一」。二者本就该是多源适配，不建议为形式统一冒险。

阶段 D ——（可选）清理遗留接口

fetch_and_inject 及 source 死参数：确认无路由引用后瘦身或标注弃用，同步 LOCK_POLICY 登记与守护测试。若非本期目标可延后。
