# eltdx 项目能力分析

> 分析对象：[electkismet/eltdx](https://github.com/electkismet/eltdx)
> 分析方式：克隆仓库并通读核心协议层 `crates/eltdx-protocol` 与接口文档 `docs/`
> 仓库性质：通达信（TDX）在线行情协议 Python 库，Rust 驱动，Research-Only 协议客户端

---

## 结论速览

| 问题 | 结论 |
| --- | --- |
| 是否支持全 A 股每只股票的前复权 K 线 | ✅ 前复权支持；「全 A 股每只」需自行枚举代码后逐只拉取，无一次性批量导出接口 |
| 支持哪些周期 | ✅ 周 K / 日 K / 30 分 / 15 分 / 5 分 / 1 分 全部明确支持（外加 60 分、月、季、年及扩展周期）|
| 每个周期拉多少数据 | 单请求上限 800 根；自动分页默认上限 200 页（16 万根/只）；实际深度取决于主站存储 |

## 一、前复权 K 线支持情况

### 1.1 复权模式完整定义

复权模式定义在 `crates/eltdx-protocol/src/unit.rs` 的 `AdjustMode` 枚举中：

| `adjust` 参数 | 底层值 | 含义 |
| --- | --- | --- |
| `none` | 0 | 不复权 |
| `qfq` / `front` | **1** | **前复权** |
| `hfq` / `back` | 2 | 后复权 |
| `fixed_qfq` | 3 | 定点前复权（需 `anchor_date`）|
| `fixed_hfq` | 4 | 定点后复权（需 `anchor_date`）|

### 1.2 调用方式

```python
from eltdx import TdxClient

with TdxClient(timeout=3) as client:
    # 前复权日 K
    qfq = client.bars.get("sz000001", period="day", adjust="qfq", count=200)
    # 定点前复权（以某日为锚）
    fixed = client.bars.get("sz000001", period="day",
                            adjust="fixed_qfq", anchor_date="2024-06-03")
```

- 前复权 / 后复权值由**服务端 `0x052d` 直接返回**。
- 也可取不复权数据，再用 `client.corporate.adjustment_factors()` 在本地自行计算复权系数（基于权息记录 `0x000f`）。

### 1.3 「全 A 股每只」如何落地

项目**没有**"一次导出全市场"的批量接口，正确流程是：

1. **枚举代码**：使用 `0x044d` 代码表 / `client.helpers.latest_stock_list()` 拿到全部 A 股代码。
   - 按市场（沪/深/北交所）分页，每页上限 `1600`（`DEFAULT_CODE_PAGE_SIZE`）。
   - `SecurityCategory::AShare` 已内置区分沪市主板、科创板、深市主板、创业板、北交所。
2. **逐只拉取**：对每只代码请求 K 线。多只时用多线程调用同一个 `TdxClient`，请求由连接池分配到不同主站 Slot 并发执行。

## 二、支持的周期

周期定义在 `KlinePeriod::normalize`（`unit.rs`），并经文档 `docs/methods/7709-K线周期线.md` 确认。

### 2.1 本次关注的 6 个周期（全部支持）

| 周期 | 参数写法 | 底层编号 (raw/param) |
| --- | --- | --- |
| 周 K | `week` / `1w` / `w` | 5 / 1 |
| 日 K | `day` / `1d` / `daily` | 4 / 1 |
| 30 分 | `30m` / `30min` | 2 / 1 |
| 15 分 | `15m` / `15min` | 1 / 1 |
| 5 分 | `5m` / `5min` | 0 / 1 |
| 1 分 | `1m` / `1min` / `minute` | 7 / 1 |

### 2.2 其他已定义周期

| 周期 | 参数写法 | 底层编号 |
| --- | --- | --- |
| 60 分 | `60m` / `60min` / `1h` | 3 / 1 |
| 月 K | `month` / `1mo` | 6 / 1 |
| 季 K | `quarter` / `1q` | 10 / 1 |
| 年 K | `year` / `1y` | 11 / 1 |
| N 分钟扩展 | `10m` / `20m` … | 8 / N |
| N 日扩展 | `2d` / `45d` … | 9 / N |
| N 秒 | `5s` / `15s` … | 13 / N |

> 扩展周期（如 `10m`/`2d`/`5s`）是否有数据以**服务端实际支持为准**。

⚠️ **易混点**：`minutes.rs` 中的"分时"是**当日 / 历史某日的 1 分钟走势**（命令 `0x0537`/`0x0fb4`），与「1 分钟 K 线」不是同一东西。请求的 1 分 K 走的是 K 线命令 `0x052d` + `period=1m`（历史分钟 K 线，含开高低收量额）。

## 三、每个周期能拉多少数据

数据量上限属于 **SDK 约束** 与 **主站存储约束** 两层，需分开看。

### 3.1 SDK 层约束（代码与文档确认）

- **单页（单次请求）上限 = 800 根**：`MAX_KLINE_PAGE_SIZE = 800`，`count` 取值必须在 `1..=800`。
- **自动分页**：`all_pages=True` 时按页顺序向后翻，直到主站返回空页才停止。
  - 默认 `max_pages = 200` → 单只单次调用最多 `200 × 800 = 160,000` 根。
  - 设 `max_pages=None` 则**不限制 SDK 页数**。
- 单只分页为**串行**执行；多只之间由连接池并发调度。

```python
# 自动翻页拉取全部可用历史（日 K）
history = client.bars.get("sz000001", period="day",
                          all_pages=True, page_size=800, max_pages=None)
```

请求参数表（节选自文档）：

| 参数 | 含义 | 默认值 / 上限 |
| --- | --- | --- |
| `start` | 起始位置，从 0 开始 | — |
| `count` | 本页条数 | 默认 800，上限 800 |
| `page_size` | 自动分页每页条数 | 默认及最大值均为 800 |
| `max_pages` | 自动分页最大页数 | 默认 200，可设 `None` |
| `batch_size` | 多代码并发数 | 跟随连接池容量 |
| `all_pages` | 是否自动翻页合并 | `False` |

### 3.2 主站层约束（实际深度）

- **日 / 周 / 月线**：主站基本保留全历史，可拉满。
- **分钟线（1/5/15/30 分）**：受主站保留窗口限制，通常仅有**有限年数**的分钟数据，并非无限回溯。这是服务端约束，非 SDK 限制。
- 复权与周期**正交**，前复权对全部周期（含分钟线）均生效。

## 四、关键前提与限制

1. **数据来源是通达信行情主站（7709 协议）**，并非免费公开 REST API。需要能连接到一个可用主站，并遵守其服务协议。本项目声明为 **Research-Only**，禁止商业 / 付费 / 生产用途。
2. **全 A 股（5000+ 只）是循环 + 分页的大批量操作**：分钟线尤其重（1 分钟 × 多年翻页数极大、耗时长、受主站限速 / 窗口限制），需并发 + 容错设计。
3. **无内置全市场批量导出**：必须先枚举代码（`0x044d`/`helpers.latest_stock_list()`）再逐只拉取。
4. 每页上限 800 根，单只自动分页默认至多 200 页（16 万根），可通过 `max_pages=None` 取消 SDK 上限，但主站实际返回量仍取决于服务端。

---

## 五、一句话总结

> eltdx **支持前复权**，且**周 K / 日 K / 30 分 / 15 分 / 5 分 / 1 分全部支持**；每请求最多 800 根、可自动翻页至 16 万根/只（默认上限）；「全 A 股」需先枚举代码再逐只拉取，且依赖一个可达的通达信主站。
