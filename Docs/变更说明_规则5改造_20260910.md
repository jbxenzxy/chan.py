# 规则 ⑸ 改造：离场方式按日期判定 + 删除 CLOSETODAY 分支

日期：2026-09-10　基线：custom-dev（远端与本地 `C:\my_chan_project` 逐字节一致）

## 一、改了什么

### 变更 1（核心）：`_exit_intent` 由「entry_mode 联动」改为「按日期判定」

规则 ⑸ 用户口径 —— **今日单锁仓 / 跨日单平仓** —— 落地为代码硬规则。

| 判定条件 | 离场方式 | 报文 |
|---|---|---|
| `entry_mode == LOCKED` | UNLOCK（防御分支，settle 已跳过 LOCKED） | `CLOSE` |
| `entry_date < today`（跨日单） | HARD_EXIT 硬离场 | `CLOSE` + 平昨 |
| `entry_date >= today`（今日单） | SOFT_EXIT 软离场 | `LOCK` + 反向 `OPEN` |
| `today` 缺省/为空 | SOFT_EXIT（选永不拒单的一侧） | `LOCK` + 反向 `OPEN` |
| `entry_date` 缺失（旧 state.db 恢复） | 沿用 Types.py:242 既定口径 `"" < today` → 硬离场 | `CLOSE` 平昨 |

**修掉的缺陷**：旧实现 `OPEN_FIRST→LOCK / UNLOCK_FIRST→CLOSE` 隐含"当日开当日平"。
一旦当日开仓、隔日才触发离场，该仓物理上已是昨仓却仍走 LOCK（开反向今仓）→
多付一次开仓费，次日还要再平两笔。按日期判定后走 CLOSE 平昨（0.0023%），更优。

这也是 `Docs/自动下单_Q1-Q6决策全记录_v1.3.md` 里 **Q2=A 的既定决策**（此前只决策未落地，
同文档 D6 记的缺陷"`_exit_intent` 无日期输入"即指此处）。

### 变更 2：删除 `_close_offset` 的 CLOSETODAY 分支

规则 ⑸ 保证 `OrderIntent.CLOSE` **只用于跨日单**（今日单离场一律走 LOCK），
故 CLOSE 恒为平昨 `CLOSE`，`CLOSETODAY`（平今 0.0345% ≈ 平昨 15 倍）不可达。
已删 `_close_offset()` 与 `_today_str()`，`_submit_close` 里 `offset = "CLOSE"`。

`submit(..., entry_date=)` 参数**保留**（带默认值，不破坏签名），用途降级为
审计/诊断（DryRun 写入 `Order.meta["entry_date"]`），不再参与 offset 选择。

## 四、未改动（已核实无需改）

**风控锚**：`_upgrade_lock_pair` 用 `anchor=unlock_price`（解锁成交价 P₂）重算 ExitPlan，
会计锚 `entry_price` 保持 P₀ 不动 —— 这是**正确**的：
- 风控侧：`Exit.check()` 取 `plan.params["risk_anchor"] or entry_price` → 恒用 P₂
- 会计侧：两笔 Trade 加总 = 真实盈亏（解锁腿 P₁−P₂ + 升级腿 P₃−P₀），P₀ 不动才对得上
