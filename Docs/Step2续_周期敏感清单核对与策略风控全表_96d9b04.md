## 3. Q3 核对：第 2 项不是"断连"，是"信号新鲜度"——且它适合经验定值，甚至可根数化

**语义澄清（对照 Config.py:215-218 + Source/SSE.py 首连逻辑）**：
`source.signal_max_age_minutes`（60.0）= **信号新鲜度过滤**，不是断连判定。作用：chan.py SSE **首连时会 replay 一批历史 bsp**，本参数把「首次出现距今 > X 分钟」的历史信号当**陈旧残留丢弃**，防止启动瞬间拿过期信号开仓。`0=不过滤`。
- **断连**是另一组：`source.reconnect_wait / reconnect_wait_max / reconnect_max_retry`（墙钟秒，与周期无关，2.5 收口）。
- 为什么周期相关：量纲是"分钟"，但过滤对象本质是"信号距当前多少根 bar"。15s 下 60min=**240 根**（太宽，陈旧被误判新鲜）；30m 下 60min=**2 根**（太窄，当天有效信号可能被误杀）。

**你的判断基本对**：这确实是经验型规则参数，不需要统计实测标定。更进一步——**它根本不必按周期各存一个数**：直接改成根数口径（如 `max_age_bars=2`）× bar_secs 派生，四个周期一套规则即消除周期敏感性 → 该项可从 PERIOD_SENSITIVE_FIELDS 消失（这是 2.1 F1 遗留里可顺带消化的简化点，见 §6 待拍板 T-2）。
