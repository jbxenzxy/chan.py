## 0. 需求原文（用户原话，一字不改）

股票单窗口场景下，重新梳理一遍：
⑴ 页面加载多少根K线，由两部分组成：左边界L 和 右边界R
⑵ 改变左边界L的操作或方式，有两种：
方式A："STOCKS_LOOKBACK_CONFIG": {"w": (0, "不限制"), "d": (500, "24年09月10日"), "30m": (800, "近5个月"), "15m": (960, "近3个月"), "5m": (960, "近1个月")}
方式B：选点
⑶ 改变右边界R的操作或方式，也有两种：
方式C：从本机数据源目录读取到的最新K线
方式D：选择复盘

最干净的状态是，方式A和方式C的组合，即没有选点，也没有复盘
干净状态下，用户的操作可以是：先选点（方式B），再复盘（方式D）；也可以先复盘（方式D），再选点（方式B）；也可以先选点，再选点；也可以先复盘，再复盘。
改变左边界的操作，如果让左边界落在当前[L, R]区间的右边，弹窗提示用户，先加载数据 —— 目前应该走不到这个分支，因为选点无法选当前右边界的右边
改变右边界的操作，如果让右边界落在当前[L, R]区间的左边，弹窗提示用户，先加载数据 —— 比如选择日历日期落在了左边界的左边了
改变左边界的操作，如果落在当前[L, R]区间左边，正常执行，改变左边界即可 —— 目前应该走不到这个分支
改变右边界的操作，如果落在当前[L, R]区间右边，正常执行，改变右边界即可 —— 比如选择日历日期落在了右边界的右边
改变左边界的操作不改变右边界，改变右边界的操作不改变左边界

## 1. 窗口模型

页面加载的K线区间 = `[L, R]`（左边界 L 含于窗口，右边界 R 含于窗口，需求⑴）。

无选点且无复盘 = **基准状态**（方式 A + 方式 C 的组合，需求⑻）。

**改 R 二选一（需求⑷）**：R 恒为二者之一 —— 「数据源最新」（非复盘态）或「复盘点」（复盘态），
不并存、无第三态；「回最新 / 取消复盘」即把 R 从复盘点切回数据源最新。

**改 L 二选一（需求⑸）**：某时刻的 L 要么按方式 C 截断（= **从 R 起往左**截 N 根），要么取方式 D 的
选点位 —— **选了 D 就不再套 C 的根数截断**，两者不叠加（§1 表 D 行、§2.6）。

**改变 L 的方式**（改 L 不改 R）：

| 方式 | 触发 | 新 L |
|---|---|---|
| C 按配置截断 | 冷启动类操作（见下文整体重置类） | **从 R 起往左截 N 根**，N 按 `STOCKS_LOOKBACK_CONFIG`（`AppConfig`；期货同款 = `FUTURES_LOOKBACK_CONFIG`，见 §3.2/§5.1）：w 不限制 / d 500 根 / 30m 800 根 / 15m 960 根 / 5m 960 根；`FULL_DATA_MODE=True` 时不截断 |
| D 选点 | 双击选点 | 选点位置；此后窗口 = [选点, R]，**不套用方式 C 的根数截断**。选点动作本身只命中当时可见K线（距今根数 ≤ 当时窗口根数），但选点之后随新K线累积、或隔日冷启动从 CSV 恢复选点，[选点, R] 的根数会超过配置值——此时不截断，保证选点始终留在窗口内（若截成最近 N 根，选点会被截出窗口：图上看不到选点，系统却认为选点存在） |

**改变 R 的方式**（改 R 不改 L）：

| 方式 | 触发 | 新 R |
|---|---|---|
| A 数据源最新 | 冷启动类操作 / 回最新 | 本机数据源目录最新K线 |
| B 复盘 | 日历选日期 或 右键「复盘至此」（两者最终都走 `gotoDate`） | 复盘目标日期 |

复盘入口确认：股票的箭头逐根步进已删除，日历输入、键盘 Enter、日历控件、右键「复盘至此」全部汇入 `gotoDate` 一个出口——所以改 R 的拦截逻辑只需在这一处实现。

**整体重置类操作（模型外，不走 §2 判定，直接重算 [L, R]）**：
换代码、切周期、实时态取消选点（D→C，清 CSV 后冷启动回基准）、重启按钮、回今天/回最新。
（复盘态取消选点不是重置类——它是改 L 操作，R 保持复盘点，见 §2 第 5/6 条。）

## 2. 行为规则

1. **改 R 不改 L、改 L 不改 R**。复盘窗口 = [当前 L, 复盘点]，恒为冷启动窗口的子集——数据量只少不多，且左侧K线一根不变，复盘前后的缠论结构可直接对照。

   **「L = R 往前 N 根」只在改 L 操作执行的那一刻成立**（冷启动时 R=最新 → L=最新往前 N 根；复盘态取消选点时 R=复盘点 → L=复盘点往前 N 根）；之后的改 R 操作只动右边界，L 冻结不动、**不随复盘点平移**。例（d 周期，N=500）：今天冷启动 → L = 今天往前第 500 根（记为 L0）；复盘到任意历史日期 T → 窗口 = [L0, T]，L 仍是 L0，而**不是**"T 往前 500 根"。若 L 随复盘点平移，左侧数据改变，两次复盘的结构就失去可比性。
2. **改 R 落在 L 左边（需求⑾）** → 前端弹窗拦截，不发请求：
   「复盘日期 XX 早于已加载数据起点 YY，请扩大数据范围」
   （文案只指向真实出路：扩数据范围，或 `FULL_DATA_MODE` 配置。）
   右键「复盘至此」只能命中可见K线，天然落在区间内——此拦截只对日历输入可达。
3. **改 R 落在 R 右边或等于今天/未来（需求⑿）** → 分两态，都是「正常改 R」：
   - **复盘态**：末根 = 复盘点 < 数据源最新，往右复盘（落在 (复盘点, 今天) 内）**必须放行**，走 end_date
     正常复盘加载 [L, 复盘点]，不得钳位；落在今天/未来 → 回最新（等价于取消复盘）。
   - **非复盘态**：末根 = 数据源最新，R 已在最右，输入 ≥ 末根时「钳到回最新」= 走冷启动（不带 end_date）
     重新落到同一根 ⇒ **行为等价于 R 不变**（不是"拒绝执行"，而是右侧无处可去）。
4. **改 L 落在区间右边（需求⑼）** → 前端本分支无入口，后端兜底**两市场归一为「报错 + 弹窗提示」**：
   - **前端为什么没有入口**：四条改 L 路径的新 L 取值域都被约束在 `L ≤ R` ——
     方式 D 选点（双击）只能命中可见 K 线，落点 ∈ (L, R]；取消选点 L 重算为「R 起往左 N 根」，恒 ≤ R；
     复盘态取消选点 L = 复盘点往前 N 根 < 复盘点 = R（§2.5）；整体重置类 L 由 R 与方式 C 直接重算，
     恒 ≤ R。故需求⑼ 的「弹窗提示先加载更多数据」**无需在前端实现**。
   - **后端兜底保留并归一**（唯一可能触发的是落在 R **上**的退化形态，见 §2.4.1）：两市场同判据
     `start ≥ end`、同文案「复盘起始时间 XX 不早于复盘截止时间 YY」，**都中止本次加载并让用户看到提示**：
     - 股票：`_analyze_stock_internal` 返回 `error` → 前端 `showAlert` 弹窗（既有通道）；
     - 期货：`_sse_single_gen` / `_sse_dual_gen` 发出 init 错误帧并中止（双窗**任一窗倒挂即整体中止**，
       对齐 §4.3「任一窗越界即拦/回」）→ 前端 init 的 `error` 分支弹窗（v1.15 由 `console.warn` 改为此）。
   - **为什么不静默回退**：v1.14 及以前期货侧是「丢弃 start、回退默认窗口 [end-N, end]」，用户看不到
     任何提示、窗口却被悄悄改掉，与需求⑼「弹窗提示用户」相悖，也与股票侧（同一场景报错）不归一；
     本仓库更早已刻意删除过同类静默放行（`test_replay_window_start` 的用例名即「报 error（静默放行已删除）」）。
     归一的代价（可回退点）：若将来判定「落 R 上应视同方式 C 正常执行」，只需把两处判据由 `>=` 放宽为 `>`，
     期货侧回到回退即可——判据只此两处，无隐式耦合。
   - ⚠️ **§2.4.1 与需求⑼/⑽ 的边界**：需求⑼ 只约束「落在区间**右边**」，需求⑽ 约束「落在区间**左边**」，
     落在 R **上**两者都没直接覆盖；本方案按「窗口退化为单根 = 不可用」处理成报错，判据取 `>=`。
5. **改 L 落在区间左边/区间内（需求⑽：正常执行，只改左边界）** → **无条件放行、不做任何判定**（无论
   落在区间内还是区间左边，一律只改 L）。可达实例 = 复盘态取消选点（已放开，见第 6 条）——L 重算为
   方式 C 在当前 R 下的左边界（复盘点往前 N 根），R 保持复盘点。复盘点 < 最新，故新 L 比取消前更早
   （窗口变宽），天然合法。
6. **复盘态选点放开（已实现，四场景一致——见 §5.4）**：选点 = 改 L（新 L = 选点左肩时间 T），R 保持复盘点——窗口 = [选点, 复盘点]，保持复盘态。选点照常落 CSV，回最新后冷启动恢复 [选点, 最新]。
7. 等价性保证：回今天/回最新的实现（冷启动从 CSV 恢复选点，无选点时重算方式 C）与「只改 R」等价——无选点时重算的 C 左边界 = 原 L（同一周期、同一份 `STOCKS_LOOKBACK_CONFIG` 回看根数、同一天，重算结果不变）；有选点时 CSV 恢复的就是当前 L。

## 3. 期货单窗（二期，已实现）

### 3.1 与股票的架构差异（载体不同、体验一致）

- 期货 K 线**实时推进**（SSE 增量推送），股票为静态 HTTP 加载；
- 期货复盘 = **SSE 软断开**：连接保持、更新停在 `end_time` 边界（K线冻结），回实时 = 重连不带 end_time——用户可见行为与股票复盘态一致（复盘态 UI、菜单、窗口语义）；
- 期货复盘入口与股票统一（日历/Enter/右键「复盘至此」全部走 `gotoDate`）。

### 3.2 与股票对齐的窗口语义（§2 全部适用，差异点如下）

- **复盘继承选点**：`_sse_single_gen` 的 end_time 分支不再丢弃 start_time——显式传入优先生效，缺失时从 CSV 恢复（F5 刷新后前端内存丢失，CSV 是 SSOT）；`_futures_window_fetch_bars` 新增 start+end 组合分支：取数 = 墙钟估算(start→now)（多拉 end→now 流逝部分），`_truncate_records_by_end` 截去 end 之后 → 窗口 = [选点, 复盘点]，**不做根数截断**（对齐股票选点路径）；
- **复盘越界弹窗**：日历输入早于窗口左边界 L → 「复盘日期 XX 早于已加载数据起点 YY，请扩大数据范围」（同股票）；
- **钳位修正**：非复盘态末根 = 数据源最新，输入 ≥ 末根 → 回实时；**复盘态末根 = 复盘点 < 数据源最新，只拦今天/未来**（回实时），(复盘点, 今天) 内放行往右复盘——与股票同款修正；
- **复盘态选点放开**：选点请求带当前复盘点（`end_date`），后端 `futures_manual_select_point` 在选点重建时按 end_time 截断 → 窗口 = [选点, 复盘点]，保持复盘态；选点照常落 CSV；
- **复盘态取消选点放开**：清 CSV 后重连保持复盘态（无 start_time、带 end_time → 窗口 = [复盘点-N, 复盘点]，N = `resolve_lookback_bars` 期货配置）；
- **meta.saved_selection_date 恒回显 CSV 真值**（`_get_saved_point`），与股票同规则——方式 A 复盘的 start=左边界 不会冒充选点；
- **起止倒挂（`start ≥ end`）报错中止**（需求⑼ 的兜底分支，v1.15 归一，见 §2.4 与 §6.3）：
  `_sse_single_gen` 在解析出倒挂后记日志、发 init 错误帧（文案与股票逐字同形）并 return；
  `_sse_dual_gen` 两窗**任一**倒挂即整体中止（双窗文案带「上窗 / 下窗」定位）。
  `_futures_window_fetch_bars` 内部「组合取数只在 `start < end` 时成立」的守卫保留——那是**纯函数**
  无处报错时的保底，正常流程到不了（gen 层已先报错）。

### 3.3 自动下单拦截（期货特有）

交易引擎（自动下单）运行中（`autoOrderRunning`，5s 轮询 status）时，以下四类操作弹窗拦截：「交易引擎运行中，请先关闭，再选点/复盘/取消选点/取消复盘」——双击选点、复盘（gotoDate 期货分支）、取消选点、取消复盘（复盘态回实时）。拦截仅前端（与切周期/切合约的既有拦截完全同款：体验拦截前端做、安全闸门在后端）；股票页不受影响（`isFuturesMode()` 判定）。

### 3.4 天然约束

- **tqsdk 取数上限 10000 根**：选点很早 + 复盘点很早的组合窗口超限时自动降级（拉最近 10000 根再过滤），窗口可能比理想窄——股票（本地通达信全量）无此约束；
- 期货选点端点需起临时天勤连接（两次握手），比股票慢，功能不受影响；
- 复盘至此执行后菜单变「取消复盘」、回实时后恢复「复盘至此」——期货现状即有（`meta.is_replay` 驱动），本期无改动。

### 3.5 单窗归一差异表（需求⒀：股票 vs 期货，差异 → 理由）

**结论：除下表各项外，改 L / 改 R 的方式 A/B/C/D 在两市场行为一致（§2 全部适用）。** 表里每一项都是
「确实无法（或不必要）归一」的，逐项给理由；**新增差异必须补进本表并给理由**。
（v1.14 表里的 #2「改 L 落右侧的兜底」与 #6「倒挂判据的边界」已于 v1.15 归一、移出本表，见 §6.3。）

| # | 差异 | 股票 | 期货 | 理由（为何无法归一） |
|---|---|---|---|---|
| 1 | 复盘载体 | 静态 HTTP 重取（`end_date`） | SSE 软断开（连接保持、更新停在 `end_time`） | 行情通道本就不同：期货是实时推送流，「冻结在复盘点」只能靠软断开；**用户可见行为已归一**（复盘态 UI / 菜单 / 窗口语义 / 越界弹窗文案），见 §3.1 |
| 2 | 取数上限 | 本地通达信全量，无上限 | tqsdk 单次上限 10000 根（`_TQ_MAX_BARS`），超限自动降级为「拉最近 10000 根再过滤」，窗口可能比理想窄 | 数据源事实，代码无从规避 |
| 3 | 选点端点耗时 | 本地文件读，快 | 需起临时天勤连接（两次握手），慢 | 数据源事实；功能不受影响 |
| 4 | 交易引擎运行中拦截 | 无（`isFuturesMode()` 为假） | 四类操作被拦（选点/复盘/取消选点/取消复盘，`autoOrderRunning`） | 期货特有功能：期货选点/复盘会改变交易引擎可见的行情窗口；股票页不驱动该引擎，无对应风险 |

## 4. 股票双窗（三期，已实现）

### 4.1 配对与加载顺序

- **配对**：上窗周期严格大于下窗周期，不允许相等或反向（现状 `_STOCKS_DUAL_PAIRS` + `_validate_stock_dual_pair` 显式校验，维持不变）。前端可达配对维持现状三对：w+d、d+30m、30m+5m（`_SUB_FREQ_MAP` 缺省）；后端全表更宽但前端不放开。
- **CChan 构建顺序 = 先下窗、后上窗**（需求⒃「下窗K线先于上窗K线加载」指此，即区间套的"下窗先加载"）。双窗数据文件在 `fetch_main_level(return_raw=True)` 一次调用里**同时读取**（w+d 共用日线文件、d+30m 与 30m+5m 共用 5m 文件，并共用同一次前复权——两窗数据同时就绪，不分先后）；随后先建下窗独立 CChan 整读入运行时缓存，上窗后建并从缓存读下窗笔结构（消除"主K线先到、子级别笔未跟上"的时序退化，与期货 SSE 双窗时序约定一致）。

### 4.2 选点：上下窗独立（各一套 [L, R]，继承单窗逻辑）

- **仅上窗可选点的限制废除**：下窗双击可选点（焦点窗判定 `activeDualWindow`），选点请求按焦点窗带 `freq`；
- 每窗选点 = 改该窗 L（改L不改R）、窗口 = [选点, R] 全量不套根数截断——与单窗完全同构；
- **落各自周期列**：选点 CSV 按 (code, 周期列) 存，上下窗互不覆盖；
- **单双窗同周期共享选点状态**（历史拍板废除）：双窗选点落 CSV、双窗冷启动/回最新读各自周期列的选点——原"双窗选点不落 CSV（会话内一次性）"与"双窗不读 CSV 选点"两条拍板废除。行为变化：单窗茅台日K选的点，双窗上窗(茅台日K)继承；双窗下窗(30m)选的点，切回单窗 30m 也恢复；
- **双窗取消选点放开**：清**焦点窗**周期列的选点（语义与单窗一致）；
- **上窗选点不联动下窗**（原"下窗跟随上窗选点收缩"联动废除）：各窗 L 独立，互不牵动。

### 4.3 复盘：上窗执行、下窗跟随（需求⒂）

- 复盘操作只在上窗执行（入口天然在上窗），下窗同步跟随：上下窗 R = 复盘点，**L 各自冻结**（改R不改L 的双窗版——上窗 L 按上窗选点/方式C，下窗 L 按下窗选点/方式C，互不牵动）；
- 取消复盘（回最新）**同样只在上窗触发**，下窗随动（两窗 R 一起回到数据源最新；L 各自按 CSV/方式C 重算）——与复盘对称，不单独设计；
- 复盘继承选点按窗各自生效（上窗继承上窗周期列、下窗继承下窗周期列）；
- 越界弹窗与回实时钳位按 **max(L_main, L_sub)** 判定（任一窗越界即拦/回）；**起止倒挂同理：任一窗倒挂即整体中止**（§2.4）。

### 4.4 联动：下窗变动 → 上窗重新加载（需求⒃，新增联动）

**触发清单（穷举下窗 L / R 变化的全部来源）**：下窗选点 / 下窗取消选点 / 下窗随上窗复盘（含取消复盘）/
切周期 / 整体重置类（换代码、重启按钮、回今天/回最新）。任一触发 → 上窗按**自身 [L, R]** 重新加载
（上窗 L/R 一律不变，重建 CChan 以获得基于新下窗的区间套买卖点）——**与下窗的 L/R 无关**。

落地形态：股票走**同一次** `analyze` 请求（`dual=1` + `sub_freq`），响应里 `data`（上窗）与 `data.sub`
（下窗）一起回、前端一次全文替换（`gotoDate` 与下窗选点响应同款）；期货走**同一次** `connectRealtimeDual`
连接（一连接两窗，`sub_start_time` 拆出口径见 §5.2）。

**与 §4.3 复盘随动的关系（勿读成"两次加载"）**：复盘（与取消复盘）是**上窗发起**、下窗随动，两窗在
同一次请求 / 同一次连接里一起落地 ⇒ 复盘本身**不产生**第二次上窗加载。§4.4 的联动只在下窗被**单独**
操作时生效（下窗选点 / 下窗取消选点 / 切周期 / 重置），不存在「复盘 → 下窗变动 → 再触发上窗重载」的双次加载链。

### 4.5 区间套覆盖性（方案 b：自由 + 如实降级）

上下窗独立选点后，上窗 L 早于下窗 L 的区间下窗数据覆盖不到——该段**区间套买卖点被保守压制，属预期行为**，不新增校验。当前 `check_nesting_divergence` 的两级降级（行为不同，已核实）：
- 子级别 [C,D] 无法换算（"可能子级别K线不够"）→ 按子级别背驰处理（return True）；
- [C,D] 换算成功但下窗找不到被红框完全覆盖的笔 → **不判背驰、不放行买卖点**（return False；2026-09-02 一致性决策，修掉 P1 假阳性，与盘后红框中枢显示口径一致）。

### 4.7 双窗 vs 单窗归一差异表（需求⒂：归一优先，差异 → 理由）

双窗把上/下窗**各自当单窗看待**：§1/§2 的四条改 L / 改 R 路径逐窗生效（每窗一套 [L, R]、各自的选点、
改 L 不改 R 的独立性逐窗成立）；需求⒂ 点名的两类特殊处理（复盘只在上窗、下窗先加载）见下表。**双窗
特有（无法按单窗处理）的只有下表四条**，其余一律按单窗逻辑走：

| # | 双窗特有 | 为何不能按单窗处理 |
|---|---|---|
| 1 | 复盘 / 取消复盘**只在上窗执行，下窗随动**（两窗 R 一起 = 复盘点 / 一起回最新，L 各自冻结不动） | 双窗只有一个日期入口（上窗的日历 / Enter / 右键，全部走 `gotoDate`），下窗没有独立日期控件 ⇒ 下窗的 R 只能跟随，不存在"各自复盘" |
| 2 | 越界判定基准 = `max(L_main, L_sub)`（弹窗与钳位「任一窗越界即拦/回」）；起止倒挂同样「任一窗倒挂即整体中止」 | 两窗 L 可各自有选点 ⇒ 单窗的「L 越界」判定在多窗下必须收敛成一个标量；取 max = 取最严的那个窗，避免"拦了上窗却没拦下窗"的半拦状态 |
| 3 | 下窗 K 线先于上窗 K 线加载（先下后上构建 CChan，§4.1） | 区间套：上窗买卖点要读下窗笔结构，顺序反了会退化成"主K线先到、子级别笔未跟上" |
| 4 | 下窗变动 → 上窗重新加载（§4.4） | 同 3：区间套依赖下窗笔，下窗一变就必须按上窗自身 [L, R] 重算上窗 |

配对约束（上窗周期严格大于下窗周期，`_validate_stock_dual_pair`）与前端可达配对三对（`_SUB_FREQ_MAP`）
属**产品约束**，不是归一差异。

## 5. 期货双窗（四期，已实现）

### 5.1 一致性原则与继承

期货双窗的选点与复盘**逐条继承股票双窗设计（§4）**，无一条另设计：选点改焦点窗 L（R 不变）、落焦点窗周期列（CSV 单双窗同列共享）、另一窗不动（上窗选点）/上窗重载（下窗选点，区间套基于新下窗笔——`_sse_dual_gen` 先下后上的构建顺序现成）；复盘上窗执行、两窗 R=复盘点、L 各自冻结；越界弹窗/钳位按 max(L_main, L_sub)；取消选点清焦点窗列；autoOrder 拦截由既有条件天然覆盖。

**方式C统一（折算废除）**：下窗方式C = R 往前 `FUTURES_LOOKBACK_CONFIG[sub_freq]` 根（1m 1200/5m 960/30m 800/15s 960）——原「上窗配置 N_main 折算」机制废除，两市场与单窗完全同构（股票侧同步返工：双窗下窗方式C 由「跟随上窗区间」改为 `STOCKS_LOOKBACK_CONFIG[sub_freq]`）。

### 5.2 架构事实（为何不用大改）

无选点（方式 C）时 `_sse_dual_gen` 对两窗**各自调用** `init_chan_symbol`（上窗 `start=None, num_bars=N_main`；下窗 `start=None, num_bars=折算`）——两窗取数本就独立，流的结构（一次连接、两次取数、下窗先处理）不变。四期改动 = **选点 / 复盘两种模式的入口 start 参数拆分**（与股票三期加 `sub_start_time` 同构）：

1. `_sse_dual_gen` 签名与其内 `sub_start_time` / `sub_num_bars` 解析段重写：`sub_start_time` 独立参数（显式 > CSV(sub_freq 列) > 方式C）；`sub_num_bars` 硬跟随与折算删除；
2. SSE URL（`connectRealtimeDual`）与 FrontAPI 路由加 `sub_start_time` 参数；
3. 选点端点按 freq 分流（`futures_manual_select_point` 已频率参数化，下窗选点 freq=sub_freq 保存 sub_freq 列）；选点后重连**不带 start**（后端从 CSV 恢复两列，单双窗同构）；
4. `sub_snapshot` 补 `saved_selection_date`（sub_freq 列回显；main_snapshot 已有）；
5. 前端：期货下窗双击选点放开（笔定位与上窗同款）、选点/取消选点按焦点窗、双窗复盘双 start（`connectRealtimeDual` 加 subStartTime）。

### 5.3 覆盖性

区间套覆盖不足（上窗 L 早于下窗 L 的区间）→ 期货分支同款两级降级（缓存缺失→按背驰、找不到完整覆盖笔→不放行买卖点），零改动，与股票 §4.5 一致。

### 5.4 复盘态选点四场景全放开（2026-10-03 追加，一致原则）

选点 = 改焦点窗 L、R 保持复盘点——股票/期货 × 单窗/双窗**四个场景行为完全一致**：
- 单窗（股票/期货）：选点请求带 end_date=复盘点，重建 [选点, 复盘点]；
- 双窗（股票/期货）：焦点窗选点带 end_date，重建 [焦点窗选点, 复盘点]，另一窗 L 按 CSV/方式C 冻结（股票后端 `stock_manual_select_point` 的「双窗口不支持复盘态选点」防御移除；期货 `futures_manual_select_point` 天然支持）；
- 配套统一：后端复盘分支 start 缺失时从 CSV 恢复（上窗 main_freq 列、下窗 sub_freq 列）——取消选点重载后焦点列已清=方式C、另一窗列在=L 冻结；
- 取消选点双窗复盘态放开（重载后端 CSV 恢复同上）。
