## 〇、用户原始提问（原文存档）

> 请拉取 https://github.com/jbxenzxy/chan.py/tree/custom-dev 最新代码，核对当前"自动下单"功能的逻辑是否如下这样？

> **⑴** 期货账户中，无仓单，账户称为"空仓状态"；有仓单，但多/空单数量相等，称为"锁仓状态"；否则称为"运行状态"（账户盈亏随行情实时变动，处于运行中）

> **⑵** 账户处于"空仓状态"时，如果交易信号出现，入场只能报单一笔（一笔挂 N 手，当前 N=2）。成交后，账户变为"运行状态"

> **⑶** 账户处于"锁仓状态"时，如果出现交易信号，分两种情况：
> 第一种：当日（交易信号发生日期跟锁仓的单子日期相同），用户只能用"开仓"指令开新仓，不能动锁仓的单子，因平今手续费高昂（开完新仓后，账户中多/空单子数量不等，账户变为"运行状态"）；
> 第二种：跨日（交易信号发生日期在锁仓的单子日期之后），用户只能用"平仓"指令平旧仓，直到账户再次变成"空仓状态"，入场才可以用"开仓"指令

> **⑷** 账户处于"运行状态"时，如有同向交易信号，不允许再次入场（前次交易还没了结，不允许再次入场）；如有反向交易信号，也不处理（在运行单子的出场交给止盈止损 L1-L3 策略）

> **⑸** 账户处于"运行状态"时，选择离场时（不管哪种原因触发离场），今日单，用反向"开仓"指令锁仓；跨日单，用反向"平仓"指令。成交后，账户变为"锁仓状态"。跟入场一样，离场也是一次只能报单一笔（一笔挂 N 手，当前 N=2）

> 实际运行情况大体如下：
> 第 M 日（M=1）空仓，有交易信号就"开新仓"入场，交易完就锁仓；当日再有交易信号，再次"开新仓"入场，交易完再次锁仓，当日收盘后，账户处于锁仓状态，当日不会平今；也就是说，第一日，只开仓，开多或开空，不会平仓
> 第 M 日（M≥2），如果账户处于"锁仓状态"，有交易信号就"平旧仓"入场 + "平旧仓"离场；比如前一日 2 锁（A 笔+B 笔互锁 和 C 笔+D 笔互锁），第二日先平旧仓 A 笔，交易完，再平旧仓 B 笔，此时账户剩下 1 锁（C 笔+D 笔），有信号再次平旧仓 C 笔，交易完，再次平旧仓 D 笔。也就是说，跨日，先平仓，让账户先变为"空仓状态"后，再有交易信号，才可以开新仓。只要账户处于"运行状态"，就忽略交易信号，只有账户处于"空仓状态"或"锁仓状态"才可以处理交易信号。

> 另外，还有一个细节问题需再次确认，以做多为例，
> 空仓状态下做多（记为场景 X），是买入开新仓，进场后通过止盈止损 L1-L3 策略决定何时离场

### §1.5 手数口径澄清（针对追问 ⑴）

**结论：你的理解正确 —— 离场就是"一笔挂 2 手"，跟我入场一样。**

上一版报告里写的"每笔一单"是措辞有歧义，实际含义是"**每个持仓腿只发一笔报单（不拆成 2 笔 1 手）**"，单笔的手数取该腿全量，不是 1 手。更正在此。

代码证据链（三层）：

| 环节 | 代码 | 事实 |
|---|---|---|
| 手数来源 | `Engine.py:54` `self.lots_per_signal = int(cfg.risk.max_volume)`；`Config.py:298` `max_volume: int = 2` | N=2，注释原文就是"每个买卖点**一笔挂 N 手**" |
| 建仓落簿 | `Engine.py:560` `Position(..., volume=volume, ...)` | 一笔持仓腿 = 2 手，整笔成交或整笔作废（FOK） |
| **离场报单** | `Engine.py:649` `o = self.broker.submit(intent, side, pos.volume, trigger_price, ...)` | **用的是 `pos.volume`，即该腿全量 2 手**，没有任何减半/分批逻辑 |
| 出场策略 | `Exit.py` 全文件 grep 无 `volume / partial / reduce / half / 分批` | `ExitPlan` **不含手数字段**，L1-L3 只做"走/留"二元决策，不存在分批减仓 |

模拟实测（`ab_xy_sim.py` 输出，四种意图全部 `vol=2`）：

```
intent=open    action=open   side=LONG  vol=2  offset=OPEN
intent=lock    action=open   side=SHORT vol=2  offset=OPEN             ← 软离场也挂满 2 手
intent=unlock  action=close  side=SHORT vol=2  offset=CLOSEYESTERDAY
intent=close   action=close  side=LONG  vol=2  offset=CLOSETODAY       ← 硬离场同样 2 手
```

需要注意的两个边界（不影响"2 手"结论，但和"一次信号几笔单"有关）：

1. **一次信号理论上仍可能连发多笔单**，但只发生在 `_close_positions(positions=[多条腿])` 的批量场景：`to_close` 里几条腿就循环 submit 几笔，**每笔仍是该腿的 2 手**（Engine.py:640-651，按 `entry_bar_seq` FIFO 逐腿处理）。运行态下簿里只有 1 条非 LOCKED 腿 → 正常就是 1 笔 2 手。
2. **拒单会整批停**：第一笔被拒 → 立刻 `return`，剩余腿留到下一根 bar 重试（Engine.py:671-685），不会拆小再报。

一句话：**入场一笔 2 手，离场也是一笔 2 手；"每笔一单"= 不拆单，不是 1 手一单。**

- 证据：`tqsdk 3.10.2`（本机 venv 实际版本）`api.py:1353`
  ```python
  if offset not in ("OPEN", "CLOSE", "CLOSETODAY"):
      raise Exception("开平标志(offset) %s 错误, 请检查 offset 是否填写正确" % (offset))
  ```
  tqsdk 文档（api.py:1201-1202）明确：「上期所和上期能源分平今/平昨，平今用 CLOSETODAY，**平昨用 CLOSE**；**其他交易所直接用 CLOSE** 按照交易所的规则平仓」
- 后果：`insert_order` 直接抛异常 → 被 `try/except` 吞成 `rejected`（"下单失败: Exception: 开平标志(offset) CLOSEYESTERDAY 错误"）→ 引擎 `signal_action=rejected`、state 回 IDLE → **规则 ⑶-② 与整个场景 Y 在实盘永远走不通**，账户会永久锁死在锁仓态
- 修法：UNLOCK 的 offset 改为 `"CLOSE"`（中金所 CLOSE 即平昨；上期所平昨同样是 CLOSE）。意图层 `OrderIntent.UNLOCK` 不用动，只改 `INTENT_TO_OFFSET` 与 SimNow 两处硬编码

### 缺陷 2：UNLOCK_FIRST 腿（昨仓）离场发 `CLOSETODAY` → 拒单或平错腿

- 代码：`Trading/Broker/SimNow.py:737` `offset = "CLOSETODAY" if bool(self.spec.close_today_first) else "CLOSEANY"`；`InstrumentSpec.py:40` `close_today_first: bool = True`，Docs v1.2/v1.3 参数表也写 True
- 但 UNLOCK_FIRST 腿 **必然是昨仓**：它只在 `_upgrade_lock_pair` 中产生，而升级的前提是 `opp[0].entry_date < today`，剩腿 entry_date 更早 → 至少是昨仓
- 后果（中金所）：
  - 账户无今仓 → CTP 拒"平今持仓不足" → 引擎 close 重试 cooldown，连续失败达 `close_max_streak` 后触发 **phantom 清仓**（Reconcile.py 无，Engine.py:675-684），真实持仓还在却从引擎簿里消失 → 账实不符，最危险
  - 账户恰有同向今仓 → **平掉今仓、昨仓仍在**，平错腿
  - 即便成交 → 按 0.0345% 平今费率计费，与"锁仓规避平今费"的初衷完全相悖
- 修法：`_submit_close` 按腿的 `entry_date` 与当日比较选 offset（昨仓→`CLOSE`，今仓→`CLOSETODAY`），而不是全局 `close_today_first`。引擎侧需把 `pos.entry_date` 传进 broker（当前 `submit()` 签名没有该参数，需扩展）

### 次要建议（P2）

1. 锁仓判据加对账：簿内"全 LOCKED 但多空手数不等"时写 warning（覆盖单腿遗留/旧数据）
2. `_upgrade_lock_pair` 后把 `signal_key` 更新为触发解锁的新信号 key，否则统计归因全串到 D1 老信号
3. 解锁后重置剩腿的 `entry_bar_seq`（或至少在 `bars_held` 注释里标明含隔夜段），为将来加"持有 N 根强平"留出正确口径
4. 配置漂移隐患：`want = max_volume` 与锁仓腿手数不一致时（`new_lots > 0`），`unlock_no_new_open=True` 会静默少开，敞口达不到 N 手

### 5.6 术语约定（"腿"是什么）

本报告大量使用"腿"一词，此处统一口径（见第二节追问 ⑵）：

- **"腿"不是 CTP/期货官方标准术语**。官方用语是"持仓""持仓明细""今仓/昨仓""多头持仓/空头持仓"；CTP 结构体是 `InvestorPosition`（汇总）与 `InvestorPositionDetail`（明细，一笔成交一条）。
- **"腿"（leg）是套利/价差/期权策略与锁仓语境下的行业惯用语**（英文 leg of a spread / locked position）。本项目代码本身就在用：`Trading/` 下 117 处、Docs 下 170 处（如"留双腿""反向腿""配对同向腿"），本报告沿用项目既有用语。
- **代码里一条腿 = 一个 `Position` 对象**，即 `PositionBook.positions` 列表中的一个元素。
- **一条腿 = 一笔报单**（FOK 全成或全撤）形成的持仓记录 —— 这是恒等关系。
- **一条腿 = 2 手只是当前配置的结果**（`risk.max_volume = 2`），**不是概念绑定**：若把 `max_volume` 改成 5，一条腿就是 5 手。所以"持仓腿就是 2 手一笔"在当前配置下成立，但严谨说法是"一条腿 = 一笔报单形成的持仓，当前每笔 2 手"。
- 后续沟通若需消除歧义，可用"**一笔持仓 / 一条持仓记录 / 一个 Position**"替代"腿"。
