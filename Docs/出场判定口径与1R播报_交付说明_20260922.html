二、⑴ 触发判据：根内极值 → 收盘价

2.1 为什么改：判定的「依据」要和判定的「时刻」是同一个东西

引擎只在每根 K 线闭合之后才调出场判定（on_bar → check()）。 判定时刻既然是「这根走完了」，那么依据若回头去看「这根盘中最小到过多少」， 就等于拿一个已经消失的价格去触发一笔按当时盘口成交的单——依据和时刻错位。 统一到收盘价后，两者都是「这根 K 线结束时的那个价」。

2.2 改到哪一层：整层 L1–L3 都改，只豁免 ATR

层改前的价格输入改后说明
① 止损线判定 多：bar.low <= stop／空：bar.high >= stop 多：close <= stop／空：close >= stop 止损线本身的值一字未动
① 止盈线判定 多：bar.high >= tp／空：bar.low <= tp 多：close >= tp／空：close <= tp 只对固定止盈单模式 / 旧库存量持仓生效（跟踪止盈模式下 tp is None）
③ L3 浮盈基准 best = max(best, bar.high)
（根内有利极值）		 best = max(best, close)
（收盘价序列的单调最好值）		 同时决定「保本止损抬升」与「跟踪止盈启动」两个动作
豁免_atr() 继续用 high / low / 前收 —— 不改 TR 是波动率度量（喂 L2 的距离标定），不参与「是否触发」

2.3 连带作废的一条旧规则：「同根 K 线双破 → 按止损计（悲观）」

该规则的前提是「一个 low 能破止损、同时一个 high 能破止盈」。收盘价口径下， 一个 close 不可能既 ≥ 止盈线又 ≤ 止损线，这条分支已不可达，规则随口径一并删除。 代码里 sl 仍写在 tp 前面，但那只是对畸形计划（例如手工塞进一个 stop > tp 的计划）的确定性兜底， 不再是「悲观优先」规则。护栏 test_p61 里也重新断言了这一点。

2.4 代价与收益

维度换口径前换口径后
止损会怎样 盘中一碰就走，容易被插针扫掉 认收盘，止损更晚、更深一档，不被插针扫；换来的是"确认"
止盈 / 抬止损会怎样 盘中冲高即算达标（哪怕收盘全回落），抬损偏激进 冲高回落的那根不再算达标，抬损迟一根，但依据是"真的收在那里"
与成交价的关系 触发价是"盘中出现过但已消失"的价 触发价是"刚刚收盘的价"，与判定的时刻同源
滑点 / 成交价 不变 —— 触发价只是判据，最终成交价始终由 broker 决定（ExitCheck.price 的既有语义）

2.5 对「已经在跑的持仓」有什么影响

结论：方向是安全的，不会变得更松。

跟踪状态 _trail_best 是落盘在出场计划里的单调值，改口径后第一根 K 线的 best = max(旧 best, 当天 close) —— 旧值若因盘中冲高而更高，会被保留下来， 于是止损只会停在（或高于）它原来抬到的位置，不可能因为换口径反而下移。 若希望完全按新口径重新开始累计，把该段 run 结掉重开即可（State/ 下的运行态数据）。

3.4 止损(1R) = 4010 这行为什么是错的

止损是价格（4010 点），1R 是距离（入场到止损的点数差，5 点）。 旧写法把括号里的「1R」直接套在止损价旁边，读起来像是「等于 1R」或「1R 这个价格」， 两回事被写成了一个。新写法把两个量分开各自带自己的单位与位置： 止损 = 4010（价格）／距入场 1R = 5 点（距离）。
