5问题清单与修复结果（v2.1）

5.1 已修复 AppSSE.py 潜在 NameError（未定义符号）· P0-1

原现象

双窗口子级别拉取分支直接构造 TqApi(auth=...) ，但 TqApi/TqAuth/TQ_ACCOUNT/TQ_PASSWORD 四个符号未 import（AST 静态扫描确认），仅「tqsdk 已装 + 期货双窗口静态分析」触发 NameError。

修复结果

改为复用 CTqSdkSession() 数据源抽象建连 + src.fetch_kline 协议（与主连接一致），tqsdk 不再被服务层直接构造；凭据随 load_tq_account 收敛到 DataAPI。追踪：App/AppSSE.py 双窗口子级别分支。

验证

AST 守卫通过（服务层 0 处 tqsdk 直连构造、0 处 m./_sse./orch. 残留引用）；新增双窗口路径由 test_sse_gray / test_sse_sequence 覆盖。

5.2 已修复 配置中心化未彻底接线 · P1-1

原现象

AppConfig 定义 forward_adjust_enabled / full_data_mode / time_truncate_config（现已演进为 stocks_lookback_config / futures_lookback_config）/ debug_cold_start_start_date / debug_cold_start_end_date 五个字段但全库零引用，引擎读取 AppEngine 内硬编码常量，.env / 环境变量不生效。

修复结果

AppEngine 的 FORWARD_ADJUST_ENABLED / DEBUG_COLD_START_START_DATE / DEBUG_COLD_START_END_DATE / FULL_DATA_MODE / TIME_TRUNCATE_CONFIG（现已演进为 STOCKS_LOOKBACK_CONFIG，按K线根数截断；期货另有 FUTURES_LOOKBACK_CONFIG 经注入生效）全部改读 app_config.*（保持符号名以兼容消费侧），单一事实源成立。

5.3 已修复 tqsdk 隔离只到 import 层 · P0-1 / P1-2

原现象

服务层 App/AppSSE.py 仍直接构造 TqApi、持有 TQ_ACCOUNT/TQ_PASSWORD 模块级凭据。

修复结果

凭据读取收敛到 AppConfig.load_tq_account（DataAPI 消费）；服务层统一经 src.fetch_kline / src.get_kline_serial 协议消费，不在构造 tqsdk 对象。设计 4.4「抽象负责统一获取（含连接）」要求达成。

7标注 CRUD 详解

7.1 CRUD 语义

标注在业务数据层 App/AppData.py 中按 CRUD（Create / Read / Update / Delete）四类操作建模，数据结构为 { "code_freq": [ {date, text, y_offset}, ... ] }，持久化到 text_annotation.json。各操作对应 AppAnnotate.py 分发、AppData.py 实现：

操作义前端 actionAppAnnotate 分发AppData 实现
Create新增一条标注（同日期同文字自动去重）addhandle_annotation_action("add")app_data.add_annotation(...)
Read读取某 (code, freq) 的全部标注—（GET）get_annotations(code, freq)app_data.get_annotations_for(...)
Update改一条标注文字（删旧 + 增新）updatehandle_annotation_action("update")delete_annotation + add_annotation
Delete删单条 / 删某日期全部 / 删某票全周期delete / delete_by_date / delete_all三个 "delete_*" 分支delete_annotation / delete_annotation_by_date / delete_all_annotations

7.3 关于「AppAnnotate 合并进 AppChart」的结论

标注虽然由「图表右键」触发，但从架构看数据归属在 AppData 而非图表引擎，且 AppAnnotate.py 体量极小（一个 GET + 一个 action 分发，约 60 行），保持独立能力域符合「服务层按业务能力拆分」原则，与 AppChart.py（分析漏斗/选点/红框，体量大）解耦。若合并，会让 AppChart.py 混入「画布交互」与「持久化数据操作」两类不同职责；建议维持现状。现有拆分已由 FrontAPI → AppOrch → AppAnnotate → AppData 单向依赖保证，无需改动。

8AppData 业务数据层详解

App/AppData.py 是业务数据层（设计 6.1 / 8.7），自阶段 4 起持有真实实现与真实状态，将「缓存 / 持久化 / 标注 / 自选股」四类职责收敛为零散模块。此处按「功能 → 存什么 → 怎么存」逐项展开。

8.1 分析结果缓存（LRU 50 条）

功能

分析结果 LRU 缓存（股票 _stocks_analysis_cache + 期货 _futures_analysis_cache），上限 50 条，超限淘汰最旧（LRU 语义），扫描时逐只释放非买点缓存控内存。

存什么

股票：OrderedDict，键为 single_{market}_{code}_{freq}_live 等，值为 CChan 分析结果键下结构。期货：独立 dict，键如 KQ.m@SHFE.rb:1m，值为下窗 CChan（供 /api/red_range_zs 访问）。

怎么存

纯内存（线程安全由 _cache_lock RLock 保护）；不落盘。对外提供 cache_put/get/remove 三件套 + 语义化子窗接口 set/get/pop_futures_sub_chan（key 大小写规则内聚数据层）。

8.2 名称 / PE / 指数归属 / 流通市值 缓存

功能

四类「获取侧元数据」惰性缓存（_names / _pe / _belong / _float_mc），首次访问触发从缓存文件加载，之后内存命中。

存什么

名称：market+code 复合键 → 名称或 dict（港股 5 位/A股 6 位不同证券不互相回退）。PE/归属：{code: {"pe_ttm": float, "index": "沪深300"|...}}。流通市值：亿元数值字典。

怎么存

落盘 JSON（路径经 AppConfig 派生属性）：stock_names.json、stock_pettm_index.json、stock_float_mc.json；加载带旧格式兼容迁移（纯数字键 → 复合键）、整体替换接口（replace_names / replace_index_belong）供获取侧刷新后同步。

8.3 手动选点持久化（CSV）

功能

手动选点时间表，图表左键选区段进入点后记录 (code, name) × 周期列 的选点时间。

存什么

CSV 行：code, name, y, q, m, w, d, 60m, 30m, 15m, 5m, 1m, 15s（列定义 SAVED_POINT_COLUMNS），周期列映射 FREQ_TO_COL。

怎么存

落盘 CSV（double_click_dt.csv，utf-8-sig）：save_point_time 写回、clear_saved_point_time 清除并同步内存 _saved_point_times；clear_saved_point 同时清分析缓存。

8.4 上次查看代码/周期持久化

功能

记录用户上次查看的 (code, freq)，启动恢复（股票/期货通用）。

怎么存

落盘 JSON（last_code_freq.json）：save_last_code_freq 写（静默失败不影响主流程）、load_last_code_freq 读，返回 (code, freq) 或 (None, None)。

8.5 文字标注持久化（JSON）

功能

图表右键文字标注（CRUD 详见 7 节），结构 { "code_freq": [ {date, text, y_offset}, ... ] }。

怎么存

落盘 JSON（text_annotation.json，ensure_ascii=False, indent=2）：add/delete(by_date/all) 原子写；get_annotated_codes 供自选扫描交叉匹配（返回 bare_code + market + name + count）。

8.6 自选股（zxg.blk）

功能

读写通达信自选股文件，供扫描候选列表。

怎么存

落盘通达信格式（<tdx_install_dir>/T0002/blocknew/zxg.blk，GBK，每行一代码）：A 股 {前缀}{6位}（1/0/2 前缀）、港股个股 31#、港股指数 27#、美股个股 74#、美股指数 12#A_。写盘自动去重、追加不重复；路径推导自含于数据层（不产生 App → DataAPI 依赖边）。

8.7 原子写底座（跨所有持久化）

safe_write_json_file

先写 .tmp 临时文件并做 JSON 可读性校验，再用 os.replace 原子替换正式文件，失败保留旧文件 —— 防断电/中断产生半截文件，是全部 JSON 持久化的底层底座。

SLA

开全局单例 app_data，实例化即完成选点/标注启动加载（与原 import 期行为一致）；提供只读状态出口供 my_chan_main 兼容别名共享同一对象、零漂移。
