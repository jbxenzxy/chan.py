## 二、核心行为

### ① 超价下单（做多 = 对手价 + 0.6 点 = 3 tick）
下单瞬间取**实时对手价**（不再用「信号 K 线收盘价」）：
- 买方向（开多 / 平空）：对手价 = `ask_price1`，下单价 = `ask + 0.6`，**向上取整**到 tick
- 卖方向（开空 / 平多）：对手价 = `bid_price1`，下单价 = `bid - 0.6`，**向下取整**到 tick

`overprice_points` 默认 **0.6**（IF tick=0.2，恰好 3 tick，挂价天然落在 tick 边界）。

**取不到实时行情怎么办**：三种场景会导致取不到——
1. tqsdk 行情**首帧未到**（`get_quote` 是异步订阅，刚连上时订单簿字段还没推过来）；
2. **集合竞价 / 单边市缺一边报价**（如跌停时卖一价为空）；
3. **断线重连瞬间** `get_quote` 抛异常。

关键细节：tqsdk 此时返回的是 **`float('nan')` 而非 `None`**，NaN 是真值，`not (ask and bid)` 拦不住。代码已改为显式 `math.isnan` 判断，NaN 一律**回退**到旧 `align_entry/align_exit`（基于信号价），不报错、绝不下出 NaN 限价单。

### ② 开仓卡单超时：5 秒
`fill_timeout_open` 默认 **5.0**。开仓 5s 未成交自动撤单、判 rejected、不建持仓，等下一信号再触发。

### ③ 平仓卡单：每轮重新超价（价格归一）
SimNow 不支持市价单，平仓用**限价追价**循环，且**每一轮都重新定价**：

1. 每轮取**最新对手价 ± 0.6** 作为挂单价——超价自带追价属性：盘口朝不利方向走了，下一轮挂价自动跟着走，挂价永远比当前对手价多让 0.6 点，**只要盘口有报价必然立即成交**；
2. 若 `fill_timeout_close`（默认 5s）内未成交 → 撤单，进入下一轮重新取价；
3. 最多 `close_max_chase`（默认 20）轮，直到成交；
4. 行情**临时取不到**时，用 `_close_fallback_limit` 兜底：在上一笔限价基础上朝成交方向推 `close_chase_ticks`（默认 2）跳，保证价格仍单边朝能成交的方向推进；
5. 全部轮数用尽仍不成交（如涨跌停锁死）才返回 rejected，由引擎对账（增强 B）兜底。

> M4.1 → M4.2 变化：早期版本是「在旧挂价上累加 chase_ticks 追价」，已按用户方案改为上述**价格归一**——每轮直接按最新对手价超价，`close_chase_ticks` 仅作行情中断兜底步长。

### ④ 增强 A + 增强 B

**A. 平仓自动追价**：即上面 ③ 的逐轮重新超价。

**B. 持仓对账**（`engine.py::_reconcile_position`）：
- 每根 K 线，若引擎记着持仓，就调 `broker.real_position(side)` 读**券商真实持仓**；
- 真实持仓 ≤ 0（你在快期3手工平了 / 幽灵持仓）→ 立即清空引擎账目并落盘，避免反复傻等平仓、或同向新买点被误判「已持仓」漏单；
- 真实手数 ≠ 引擎手数且非 0 → 只告警（`position_mismatch`），不自动接管未知持仓；
- `dry_run` 等无真实账户的通道 `real_position` 返回 None，自动跳过，零影响。

## 三、可调参数（都在 `config.json` 的 `broker_params`）

| 参数 | 默认 | 说明 |
|------|------|------|
| `overprice_points` | 0.6 | 超价点数（对手价 ± 该值；IF 恰好 3 tick） |
| `fill_timeout_open` | 5.0 | 开仓未成交超时（秒），超时撤单本笔作废 |
| `fill_timeout_close` | 5.0 | 平仓每轮未成交超时（秒），超时撤单进入下一轮 |
| `close_max_chase` | 20 | 平仓最大追价轮数 |
| `close_chase_ticks` | 2 | 兜底步长：仅在行情临时取不到时，在上一笔限价基础上朝成交方向推几跳 |

> 这些参数都带**内联默认值**，`broker_params` 留空也能跑；写入 config 只是方便你调。
> `config.py` 的 `DEFAULT_CONFIG` 每一条配置都已加行内注释，`--init-config` 生成的模板可直接对照。
