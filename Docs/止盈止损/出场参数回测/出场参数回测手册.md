# chan.py 出场参数回测手册（交接文档）

> **给谁看**：下一个要改 L1-L3 出场参数 / 出场逻辑的人。
> **解决什么**：把「改一个参数 → 判断它到底有没有用」这件事，变成一条**可复现、有判决标准**的流水线，而不是跑一遍看个数字就拍板。
> **不解决什么**：信号端（买卖点质量）的验证。那是另一条线。

---

## 0. 一句话方法论

> **先在单笔上复现现象 → 再统计现象有多普遍 → 再用真实引擎做 A/B → 再做稳健性与显著性 → 最后才看均值。**

四条铁律贯穿全程：

1. **等价性优先**：实验策略必须和真实实现逐笔一致，否则所有 A/B 结论都不作数。
2. **只认代码**：解释现象必须落到「文件:行号 / 函数名」，不靠印象。
3. **不只看均值**：均值会掩盖"削赢家补亏家"，必须同时看胜率、盈亏比、离场原因分布。
4. **不碰用户仓库**：改动只写在沙盒，交付形态由用户决定。

## 2. 标准流程（五个阶段，按顺序做）

### 阶段 A · 取数与质量门

```bash
cd <会话目录>/exp
# 全量预热（低并发！见坑 #1）
$PY prefetch.py w 800 0 800 5
```

- 参数：`<freq> <n根> <起> <止> <并发>`
- 产出：`.kcache/<code>_w_800.json`
- **先跑这一步**，后面的脚本都读缓存，不然每次都要重抓。

### 阶段 B · 在单笔上复现现象（建立直觉，务必先做）

```bash
# 解剖单只标的的全部交易
$PY case_trace.py                       # 默认 sz000158 周K
$PY case_csbm.py sz000158 w 800
# 同一笔在各候选方案下的结果
$PY case_pct.py
```

**为什么必须先做**：如果连那一笔都复现不出来，后面的统计都是幻觉。这一步的输出应当能对上用户描述的数字（入场价、R、最高价、离场价、收益率）。

### 阶段 C · 统计现象有多普遍

```bash
$PY batch_stats.py --freq w --limit 800 --out batch_clean.json --workers 12
# 顺带做 R 的构成诊断（R 由结构距离 A 还是 ATR 主导）
$PY diag_r.py 300 w
```

产出：问题规模表（例如「浮盈 5~10% 却止损」有多少笔、占全部/占止损笔多少、平均回吐多少个百分点）。

**这一步决定值不值得往下做**。如果只有个位数笔数，那是特例不是问题。

### 阶段 D · A/B 对照（用真实回测引擎）

```bash
$PY ab_pct.py --freq w --n 800 --n-in 400 --oos 400 --workers 12 --out ab_pct.json
```

**这一步会完整重跑 `Backtest/Runner.run()`** —— 包含「出场变早 → 持仓期拒收信号变化」的二阶效应，不是离线重放。所以耗时长（800 只 × 8 方案 ≈ 20 分钟），但结论可信。

**改参数就在这里改**：见 §3。

### 阶段 E · 稳健性 + 显著性

`ab_pct.py` 已经内置四切分 + 配对 bootstrap。手工补做时：

```bash
$PY signif.py        # 按标的配对检验（注意：方案名硬编码，见坑 #5）
```

**判决标准（三条全过才算通过）**：

| 检验 | 门槛 |
|---|---|
| ① 样本外方向 | Δ > 0 |
| ② 显著性 | 配对 bootstrap p < 0.05（理想 p < 0.01） |
| ③ 跨子集一致 | 样本内 / 样本外 / 早期 / 近期 **四处方向不打架** |

**只有一条过 = 不通过。** 样本内好看样本外难看，是最典型的过拟合信号。

## 3. 实验策略层：`exp_policy.py`（最重要的一节）

### 3.1 原理

`Backtest/Runner.py` 在函数体内 `from Trading.Strategy.Exit import LayeredExitPolicy`，所以实验侧可以把这个模块属性替换成子类：

```python
import Trading.Strategy.Exit as mod
mod.LayeredExitPolicy = ExpExitPolicy     # install()
```

⇒ **信号、三态状态机、拒收逻辑全部走真实路径，只有 `check()` 被换掉。**

`check()` 的写法是「原文照抄真实实现 + 在扩展点插入分支」，这样才能靠 `verify_equiv.py` 证明等价。

### 3.2 开关一览（类属性，通过 `configure(**kw)` 设置，`reset()` 复位）

| 开关 | 含义 |
|---|---|
| `PCT_ONLY` | **纯百分比替换**：R 口径的保本层与跟踪层**整层停用** |
| `PCT_GE` | `False` = 严格 `>`（与真实实现一致）；`True` = `≥` |
| `PCT_BE_TRIGGER` / `PCT_BE_BUFFER` | 百分比保本：浮盈 > 触发值 ⇒ 保护价 = 入场 × (1 ± buffer) |
| `PCT_TRAIL_TRIGGER` / `PCT_TRAIL_DIST` | 百分比跟踪：浮盈 > 触发值 ⇒ 保护价 = 最好极值 × (1 ∓ dist) |
| `OVR_BE_TRIGGER_R` / `OVR_BE_BUFFER_R` | 覆盖原 R 口径的保本参数 |
| `OVR_TRAIL_DIST_R` / `OVR_WIN_LOSS_RATIO` | 覆盖跟踪距离 / 跟踪启动阈值 |
| `STEPS` | 多级阶梯，元素 = `(触发口径, 触发值, 落点口径, 落点值)`，口径 `"r"` 或 `"pct"` |
| `TIME_STOP_BARS` | 持仓超 N 根且未抬过价 ⇒ 强制离场（**实验侧自行计数**，见坑 #4） |

`PCT_ONLY=False` 时，`PCT_*` 是**附加条件**（与原 R 层并存、取更靠有利侧的落点）；`PCT_ONLY=True` 时才是**替换**。

### 3.3 改一个参数的完整操作

1. 打开 `ab_pct.py`（或 `ab_run.py`），在 `PLANS` 字典里加/改一行：

```python
PLANS = {
    "基线（现状 R 口径）": {},
    "★你的方案": {"PCT_ONLY": True, "PCT_BE_TRIGGER": 0.05, "PCT_BE_BUFFER": 0.02,
                  "PCT_TRAIL_TRIGGER": 0.10, "PCT_TRAIL_DIST": 0.05},
}
```

2. **先跑等价性**（只要动过 `exp_policy.py` 就必须跑）：

```bash
$PY verify_equiv.py      # 期望输出：不一致 0 只 ⇒ PASS ✅
```

3. 再跑 A/B。
4. 若涉及新指标，去 `ab_run.py::metrics()` 加字段。

### 3.4 边界口径

真实实现**一律严格不等**（`close < stop` / `fav_profit > k·R`），被 `Trading/Test/test_p61_exit_close_only.py` 用 AST 钉死。实验侧默认跟随（`PCT_GE=False`）。实测在本样本上 `>` 与 `≥` 汇总指标完全一致 —— 价格离散到 tick，"恰好相等"极少出现，不必纠结，但**改真实代码时要保持 `>`**。

## 4. 指标口径（`ab_run.py::metrics()`）

| 字段 | 定义 |
|---|---|
| `n` | 已平仓笔数（未平仓 / 加仓腿不计） |
| `avg_net` | 平均单笔**净**收益（%），已扣双边手续费 + 印花税 |
| `win_rate` | `net > 0` 的笔数占比 |
| `pf` | 盈亏比 = Σ盈利 / |Σ亏损| |
| `sl_pct` / `be_pct` / `tr_pct` | 离场原因分布：止损 / 保本 / 跟踪 |
| `worst` | 最差单笔 |
| `sum_net` | 净收益总和（**不要用它做主判据**，笔数不同不可比） |

**`reason` 只表达"哪一层保护价被跌破"，不表达盈亏** —— 保本离场也可能因滑点净亏。

## 5. 已知坑（按踩坑代价排序）

1. **腾讯接口会限流**。必须用 `ifzq.gtimg.cn`（`web.ifzq.gtimg.cn` 高并发返回 501）。并发 **≤5**，`ab_*.py` 里传 `--workers 12` 只是**跑回测**的线程数，回测不联网；联网抓取只在 `prefetch.py` 里，那里必须低并发。
2. **腾讯前复权对长期高分红股会复权出负价**（实测泸州老窖 −19.02、山西汾酒 −15.47、五粮液、紫金矿业…）。负价让 R / ATR / 收益率全部失真。`fetch_kline.py::_quality_ok()` 已做质量门：任一 OHLC ≤ 0 ⇒ **整只剔除**（不截断）。800 只里通常剔掉 45 只左右。
   > 不加质量门的后果：同一基线平均净收益从 `−1.20%` 变成 `+3.28%` —— **方向不变但幅度差约 3 倍**。
3. **`Backtest/Runner.py` 调 `check()` 时不传 `bars_held`**（恒 0）⇒ 任何基于 `bars_held` 的时间止损在回测侧**静默不生效**。实验侧靠 `ExpExitPolicy._hold` 自计数。
4. **`run_plan()` 的开关是类属性**（全局态）。绝不要跨方案并行；`install/reset/configure` 必须串行。
5. **`signif.py` 的方案名是硬编码**（`TARGETS` 且 `from ab_final import PLANS`）。改了 `PLANS` 的键名要同步改它，否则 KeyError。
6. **`ab_run.py::one()` 吞异常返回 `[]`** —— 某只标的跑挂会**静默变成"没交易"**。跑完要用「有效标的数」核对，数量异常要单独排查。
7. **股票池已按固定种子打散**（`stock_list(shuffle_seed=7)`），所以 `[:400]` / `[400:800]` 的板块分布是均衡的（实测：主板 129 / 创业板 120 / 沪市 151 vs 132 / 118 / 150）。**样本内外的差异不是"深市 vs 沪市"造成的。**
8. `.kcache/_universe.json` 一旦被写入空列表会**一直返回空**，症状是"标的 0 只"。删掉该文件重抓即可。
9. 缓存文件读出来**也会过质量门**，所以旧缓存里的脏标的会直接返回 `[]`，看起来像"接口失败"。

## 6. 基线锚点（用于回归对比）

> 口径：`freq=w`、`n=800` 根、`stock_list(800)` → 有效 **755 只**、取数日 2026-10-05。
> 换数据集或换周期后这些数字会变，但**同一数据集内**可用于判断"这次改动有没有跑偏"。

| 方案 | 全样本净% | 样本内 | 样本外 | 胜率% | 盈亏比 | 止损占比% | 跟踪占比% |
|---|---|---|---|---|---|---|---|
| **基线**（R 口径 1R→+0.5R / 2R→−1R） | **−1.20** | +0.40 | −2.93 | 51.7 | 0.87 | 40.6 | 26.2 |
| 百分比口径 5%→+2% / 10%→−5% | +0.45 | +1.12 | −0.28 | 55.0 | 1.10 | 21.5 | 47.3 |
| 百分比口径 5%→+2% / 10%→−8% | +0.64 | +1.36 | −0.14 | 51.7 | 1.13 | 21.4 | 47.3 |

基线笔数：1080（样本内 561 / 样本外 519）。

**核心结论（改参数前请先接受这个前提）**：8 个方案里样本外**无一转正**，全样本最高 `+0.64%`。
出场改造的作用是把「明显负期望」修成「≈零」，**它不是 alpha 的来源**。若目标是盈利，必须回到信号端。

## 7. 参数落地清单（改真实代码时）

改口径必须同步**三处**，否则 `Backtest/Test/test_bt03_exit_params_contract.py` 会红：

| 文件 | 内容 |
|---|---|
| `Trading/Config.py::ExitConfig` | 出场参数模型（新增字段 + 顺序校验） |
| `Backtest/ExitParams.py::STOCK_EXIT_PARAMS` | 股票档案 |
| `App/AppTPSL.py::_STOCK_EXIT_OVERRIDES` | TPSL 侧覆盖值 |

另外两条硬约束：

- **必须过 `Trading/Test/test_p61_exit_close_only.py`**：AST 断言 `check()` 函数体内不得出现 `.high` / `.low`（只能经 `_fav_extreme()`）、边界必须严格不等、抬价必须早于触发判定。
- `Config._check_exit_param_order` 需为新参数补校验（现有规则是 `breakeven_buffer_r < breakeven_trigger_r` 的镜像）。
- 旧 `state.db` 恢复的持仓：原 R 口径字段建议**保留但置 0 停用**，避免历史持仓因参数缺失走到"保护价退化为入场价外 1 tick"。
