## 一、这个包解决什么

把「改一个出场参数（保本触发、跟踪触发、跟踪距离…）→ 判断它到底有没有用」这件事，
变成一条**可复现、有判决标准**的流水线，而不是跑一遍看个数字就拍板。

**不解决**：信号端（买卖点质量）的验证，那是另一条线。

## 三、开工

**方式 1 · 就在仓库里跑（最省事）**

```bash
unzip chanpy_出场参数回测交接包.zip -d <你的仓库根>
mkdir -p Backtest/Exp/.kcache && cp Backtest/Exp/_universe.json Backtest/Exp/.kcache/
python Backtest/Exp/case_csbm.py sz000158 w 800     # 先跑这一条验证环境
```

然后按手册「阶段 A → E」推进。解释器换成你自己的（需 `requests` / `pandas` / `numpy`）。

**方式 2 · 沙盒里跑（不改仓库）**

把 `Backtest/Exp/` 下的 `.py` 挪到 `<会话目录>/exp/`，仓库克隆到同级的 `<会话目录>/wt_latest/`。
两种布局脚本都认，见手册 §1.3。

> **入库前必做一步**：`.gitignore` 补 `.kcache/` —— 约 60MB K 线缓存绝不能入库。
> 只需入库 `_universe.json`（53KB），它是复现同一 755 只样本的唯一凭据。

## 四、基线锚点（本包数据）

- 代码锚点：`origin/custom-dev @ d5faa84`
- 数据集：周K、每只 800 根、股票池 800 只 → 有效 **755 只**、取数日 2026-10-05
- 基线（现行 R 口径）全样本净收益 **−1.20%**（样本内 +0.40 / 样本外 −2.93）
- 自检命令：`case_csbm.py sz000158 w 800` 的第 6 笔应为 `R=5.940`、净 `−31.6%`、`sl`

**换 commit 或换数据集后这些数字会变，不要直接对比**；请按手册第 6 节口径重跑当次基线。

## 五、两条必须先接受的前提

1. **出场改造不是 alpha 的来源。** 它把「明显负期望」修成「≈零」（样本外 −2.93% → −0.14%），
   但 8 个方案里样本外**无一转正**。要盈利必须回到信号端。
2. **数据有坑**：腾讯前复权对长期高分红股会复权出**负价**（泸州老窖 −19.02、山西汾酒 −15.47…），
   不加质量门会把结论静默污染（实测幅度差约 3 倍）。`fetch_kline.py::_quality_ok()` 已内置剔除，**勿绕过**。

## 六、判决标准（三选一不算过）

| 检验 | 门槛 |
|---|---|
| 样本外方向 | Δ 净收益 > 0 |
| 显著性 | 配对 bootstrap（按标的，10000 次）p < 0.05，理想 < 0.01 |
| 跨子集一致 | 样本内 / 样本外 / 早期 / 近期 **四处方向不打架** |
