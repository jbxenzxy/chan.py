四句话

  1. 你的纠正成立，我上一轮的「同义反复」论断是错的。L1 保护价 = 入场价 ∓ R，而 R = max(A, 1.0×ATR) ⇒ 保护价 ≤ 分型极值；而且保护价可以在 反向笔早已走出之后才被跌破。两个方向都不等价，各有一个数据反例。

2. 勘误：我错在哪 —— 两件事确实不等价

上一轮我在 signal_quality.py 里写过一句 「FAIL（原笔延伸） ⟺ 结构止损被触碰 ⇒ 原笔延伸率不是独立指标」， 并据此说你的判定标准"跟止损定义是同义反复"。这句话是错的，你的反驳成立：它们是两族。

2.1 代码证据：保护价 ≠ 分型极值

Strategy/Exit.py:289   A = max(entry_price − signal.fractal_low, 0.0)   # A = 到分型极值的距离
Strategy/Exit.py:321   R = max(A, B)                                    # B = atr_sl_multiple × ATR
Config.py:313          atr_sl_multiple: float = 1.0
Strategy/Exit.py:353   raw_stop = base − R − stop_buffer_ticks × tick    # ← 保护价在这里

因为 R = max(A, B) ≥ A，所以 保护价 ≤ 分型极值（B 主导时严格更低）。
⇒ 「价格穿过分型极值」（= 口径一的 FAIL）只是「保护价被跌破」的 必要不充分条件。两者不是同一件事。

数据里的反例（exit_fate.py 逐笔记录）：

标的 / 日期AR原笔延伸离场层净收益
sz000601 2014-06-130.1600.239第 2 根就延伸了trailing+9.58%

A < R ⇒ 保护价在分型极值下方，价格破了分型却在中途反弹，最终以跟踪层离场。 「原笔延伸」发生了，但没有止损。

2.2 更致命的是反方向：保护价可以在反向笔之后才被跌破

Backtest/Runner.py:423   if state is State.IN_TRADE and pos is not None:
Backtest/Runner.py:424       chk = pol.check(pos, bar, inst)   # ← 每根闭合 bar 都判，持仓未平就一直判

持仓期间每根 K 线都会重新判定保护价。只要价格最终跌回保护价，就会止损离场 —— 哪怕中途反向笔已经走出来。 此时原笔并没有延伸，口径一根本记不到 FAIL，这一族被整个漏掉。

所以「原笔延伸率」只是「结构止损率」的一个下界，不是等价物：
周K 原笔延伸 35.2%（380 笔） vs 结构止损离场 40.6%（438 笔）—— 差的 58 笔（5.4pp）就是「走出反向笔却仍止损」的那部分。
旧口径把它们全部记成 SUCC（"质量好"），而它们实际平均亏 −26.89%。

7. 回测能不能多进程 —— 能，实测 ×3.0

你问的这一点，之前的代码是错的（慢的那个意思）： ab_run.py::run_plan 把 Runner.run 放进了 ThreadPoolExecutor。而 Runner.run 是纯 Python CPU 活 （缠论递归 + 逐帧状态机），CPython 的 GIL 让多线程在这类活上退化成串行。

7.1 实测：12 个线程不比 1 个线程快

并发方式墙钟时间（3 次实测）相对 1 线程逐笔结果
线程 1 个（串行基线）20.6s / 21.6s1.00×—
线程 12 个（旧默认）22.1s / 24.0s / 25.2s1.07~1.17×（更慢）—
进程 8 个6.8s / 7.3s / 7.6s2.84~3.05×完全一致 ✔

7.3 改法：一处改动，6 个脚本受益

run_plan 是唯一的收口点（被 ab_pct / ab_atr / ab_final / ab_run / ab_run2 / signif 共用）， 所以只改它一个函数：

def run_plan(codes, freq, n, cfg, workers=10, procs=None):
    if procs is None:
        procs = int(os.environ.get("EXP_PROCS", "0") or 0)
    pool = get_pool(procs)                    # 常驻池，跨方案复用（省 spawn 开销）
    if pool is not None:
        if not _CHK["done"]:                  # ← 首次走进程路径时实地对拍线程版
            _CHK["done"] = True
            _selfcheck_once(codes, freq, n, cfg, workers, procs)
        res = list(pool.map(_proc_one, [(c, freq, n, cfg) for c in codes], chunksize=4))
        return [r for sub in res for r in sub]
    ...原线程路径...
⚠ 进程池有一个会静默出错的坑，必须靠护栏而不是自觉：
exp_policy.install() 改的是父进程内存里的模块属性， spawn 出来的子进程不继承。漏了这一步，子进程跑的是原始策略 —— 症状是"结果静默变成基线值，而且看起来更快"，没有任何报错。
两道防线：① ProcessPoolExecutor(initializer=_proc_init) 在每个子进程里重新 install()；② _selfcheck_once() 在第一次走进程路径时， 用前 3 只标的实地对拍线程版逐笔结果，不一致直接打印红灯。
正确用法：python ab_pct.py --procs 8 ...（或设环境变量 EXP_PROCS=8）。 默认是 0（线程），不改变既有行为 —— 需要显式打开。
同一原则已用在：exit_fate.py（5 个周期 17 790 笔，7m12s）、 signal_quality.py（5000 根 × 300 只，18 分钟 → 2 分钟）、 be_ab.py（5 个方案 × 800 只，1m58s）。
不用改的：取数（I/O 密集）继续用线程池 —— 那里线程是对的。
