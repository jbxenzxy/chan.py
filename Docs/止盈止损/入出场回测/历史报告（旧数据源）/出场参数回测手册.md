# chan.py 出场参数回测手册（交接文档）

> **给谁看**：下一个要改 L1-L3 出场参数 / 出场逻辑的人。
> **解决什么**：把「改一个参数 → 判断它到底有没有用」这件事，变成一条**可复现、有判决标准**的流水线，而不是跑一遍看个数字就拍板。
> **不解决什么**：信号端（买卖点质量）的验证。那是另一条线。

---

## 0. 一句话方法论

> **先在单笔上复现现象 → 再统计现象有多普遍 → 再用真实引擎做 A/B → 再做稳健性与显著性 → 最后才看均值。**

四条铁律贯穿全程：

1. **等价性优先**：实验策略必须和真实实现逐笔一致，否则所有 A/B 结论都不作数。
2. **只认代码**：解释现象必须落到「文件:行号 / 函数名」，不靠印象。
3. **不只看均值**：均值会掩盖"削赢家补亏家"，必须同时看胜率、盈亏比、离场原因分布。
4. **不碰用户仓库**：改动只写在沙盒，交付形态由用户决定。

## 2. 标准流程（五个阶段，按顺序做）

### 阶段 A · 取数与质量门

```bash
cd <会话目录>/exp
# 全量预热（低并发！见坑 #1）
$PY prefetch.py w 800 0 800 5
```

- 参数：`<freq> <n根> <起> <止> <并发>`
- 产出：`.kcache/<code>_w_800.json`
- **先跑这一步**，后面的脚本都读缓存，不然每次都要重抓。

### 阶段 B · 在单笔上复现现象（建立直觉，务必先做）

```bash
# 解剖单只标的的全部交易
$PY case_trace.py                       # 默认 sz000158 周K
$PY case_csbm.py sz000158 w 800
# 同一笔在各候选方案下的结果
$PY case_pct.py
```

**为什么必须先做**：如果连那一笔都复现不出来，后面的统计都是幻觉。这一步的输出应当能对上用户描述的数字（入场价、R、最高价、离场价、收益率）。

### 阶段 C · 统计现象有多普遍

```bash
$PY batch_stats.py --freq w --limit 800 --out batch_clean.json --workers 12
# 顺带做 R 的构成诊断（R 由结构距离 A 还是 ATR 主导）
$PY diag_r.py 300 w
```

产出：问题规模表（例如「浮盈 5~10% 却止损」有多少笔、占全部/占止损笔多少、平均回吐多少个百分点）。

**这一步决定值不值得往下做**。如果只有个位数笔数，那是特例不是问题。

### 阶段 D · A/B 对照（用真实回测引擎）

```bash
$PY ab_pct.py --freq w --n 800 --n-in 400 --oos 400 --workers 12 --out ab_pct.json
```

**这一步会完整重跑 `Backtest/Runner.run()`** —— 包含「出场变早 → 持仓期拒收信号变化」的二阶效应，不是离线重放。所以耗时长（800 只 × 8 方案 ≈ 20 分钟），但结论可信。

**改参数就在这里改**：见 §3。

### 阶段 E · 稳健性 + 显著性

`ab_pct.py` 已经内置四切分 + 配对 bootstrap。手工补做时：

```bash
$PY signif.py        # 按标的配对检验（注意：方案名硬编码，见坑 #5）
```

**判决标准（三条全过才算通过）**：

| 检验 | 门槛 |
|---|---|
| ① 样本外方向 | Δ > 0 |
| ② 显著性 | 配对 bootstrap p < 0.05（理想 p < 0.01） |
| ③ 跨子集一致 | 样本内 / 样本外 / 早期 / 近期 **四处方向不打架** |

**只有一条过 = 不通过。** 样本内好看样本外难看，是最典型的过拟合信号。

### 阶段 F · 入场信号质量（把"信号端没 alpha"这件事钉死）

阶段 A~E 全部在回答"**出场**怎么调"；但 §6 已经证明出场改造的极限是"把负期望修成≈零"。
所以必须独立量化**入场信号本身**值不值得做。三个口径（细节见 `signal_quality.py` 模块 docstring）：

```bash
# 覆盖 5 个周期：周K / 日K / 30分 / 15分 / 5分
$PY signal_quality.py --freq w  --n 800  --limit 800 --horizon 30 --procs 8 --out sq_w800.json
$PY signal_quality.py --freq d  --n 800  --limit 800 --horizon 30 --procs 8 --out sq_d800.json
$PY signal_quality.py --freq 30m --n 5000 --limit 300 --horizon 30 --procs 6 --out sq_30m.json
$PY signal_quality.py --freq 15m --n 5000 --limit 300 --horizon 30 --procs 6 --out sq_15m.json
$PY signal_quality.py --freq 5m  --n 5000 --limit 300 --horizon 30 --procs 6 --out sq_5m.json

$PY tab_cycle.py          # 跨周期 × 信号类型(0123) 交叉表
$PY sweep_regret.py       # 被扫率 / 浮盈回吐率（§7.5）
```

**读表纪律（三口径不可互相替代）**：

| 口径 | 回答 | 不能用它回答 |
|---|---|---|
| 一 · 结构（走出反向笔 vs 原笔延伸） | "结构有没有被打穿" | **"信号有没有优势"** —— 它与 L1 结构止损**同义反复** |
| 二 · 事件研究（信号 vs 同标的随机入场） | **"信号本身有没有 alpha"** | "哪一根该离场" |
| 三 · 确认后入场（等反向笔确认了再买） | "钱换确定性划不划算" | 同上 |

⚠ **口径一 ≠ 质量指标**：`原笔延伸 ⟺ 结构止损被触碰`，而 L1 结构止损本来就是按"分型极值被破就走"
定义的 ⇒ "原笔延伸率"只是"结构止损触发率"的另一种说法。它描述**现象规模**，
**不能**用来论证买卖点优劣。

⚠ 跨周期比较时**不要**把"H 根"当成同一段时间：周K 的 H=30 根 ≈ 7 个月，5分 的 H=30 根 ≈ 0.6 天。
口径二只在**同周期内部**减基准，所以跨周期读表是"每个周期各自的信号有没有跑赢该周期的随机入场"。

## 3. 实验策略层：`exp_policy.py`（最重要的一节）

### 3.1 原理

`Backtest/Runner.py` 在函数体内 `from Trading.Strategy.Exit import LayeredExitPolicy`，所以实验侧可以把这个模块属性替换成子类：

```python
import Trading.Strategy.Exit as mod
mod.LayeredExitPolicy = ExpExitPolicy     # install()
```

⇒ **信号、三态状态机、拒收逻辑全部走真实路径，只有 `check()` 被换掉。**

`check()` 的写法是「原文照抄真实实现 + 在扩展点插入分支」，这样才能靠 `verify_equiv.py` 证明等价。

### 3.2 开关一览（类属性，通过 `configure(**kw)` 设置，`reset()` 复位）

| 开关 | 含义 |
|---|---|
| `PCT_ONLY` | **纯百分比替换**：R 口径的保本层与跟踪层**整层停用** |
| `PCT_GE` | `False` = 严格 `>`（与真实实现一致）；`True` = `≥` |
| `PCT_BE_TRIGGER` / `PCT_BE_BUFFER` | 百分比保本：浮盈 > 触发值 ⇒ 保护价 = 入场 × (1 ± buffer) |
| `PCT_TRAIL_TRIGGER` / `PCT_TRAIL_DIST` | 百分比跟踪：浮盈 > 触发值 ⇒ 保护价 = 最好极值 × (1 ∓ dist) |
| `OVR_BE_TRIGGER_R` / `OVR_BE_BUFFER_R` | 覆盖原 R 口径的保本参数 |
| `OVR_TRAIL_DIST_R` / `OVR_WIN_LOSS_RATIO` | 覆盖跟踪距离 / 跟踪启动阈值 |
| `STEPS` | 多级阶梯，元素 = `(触发口径, 触发值, 落点口径, 落点值)`，口径 `"r"` 或 `"pct"` |
| `TIME_STOP_BARS` | 持仓超 N 根且未抬过价 ⇒ 强制离场（**实验侧自行计数**，见坑 #4） |

`PCT_ONLY=False` 时，`PCT_*` 是**附加条件**（与原 R 层并存、取更靠有利侧的落点）；`PCT_ONLY=True` 时才是**替换**。

### 3.3 改一个参数的完整操作

1. 打开 `ab_pct.py`（或 `ab_run.py`），在 `PLANS` 字典里加/改一行：

```python
PLANS = {
    "基线（现状 R 口径）": {},
    "★你的方案": {"PCT_ONLY": True, "PCT_BE_TRIGGER": 0.05, "PCT_BE_BUFFER": 0.02,
                  "PCT_TRAIL_TRIGGER": 0.10, "PCT_TRAIL_DIST": 0.05},
}
```

2. **先跑等价性**（只要动过 `exp_policy.py` 就必须跑）：

```bash
$PY verify_equiv.py      # 期望输出：不一致 0 只 ⇒ PASS ✅
```

3. 再跑 A/B。
4. 若涉及新指标，去 `ab_run.py::metrics()` 加字段。

### 3.4 边界口径

真实实现**一律严格不等**（`close < stop` / `fav_profit > k·R`），被 `Trading/Test/test_p61_exit_close_only.py` 用 AST 钉死。实验侧默认跟随（`PCT_GE=False`）。实测在本样本上 `>` 与 `≥` 汇总指标完全一致 —— 价格离散到 tick，"恰好相等"极少出现，不必纠结，但**改真实代码时要保持 `>`**。

## 4. 指标口径（`ab_run.py::metrics()`）

| 字段 | 定义 |
|---|---|
| `n` | 已平仓笔数（未平仓 / 加仓腿不计） |
| `avg_net` | 平均单笔**净**收益（%），已扣双边手续费 + 印花税 |
| `win_rate` | `net > 0` 的笔数占比 |
| `pf` | 盈亏比 = Σ盈利 / |Σ亏损| |
| `sl_pct` / `be_pct` / `tr_pct` | 离场原因分布：止损 / 保本 / 跟踪 |
| `worst` | 最差单笔 |
| `sum_net` | 净收益总和（**不要用它做主判据**，笔数不同不可比） |

**`reason` 只表达"哪一层保护价被跌破"，不表达盈亏** —— 保本离场也可能因滑点净亏。

## 5. 已知坑（按踩坑代价排序）

1. **腾讯接口会限流**。必须用 `ifzq.gtimg.cn`（`web.ifzq.gtimg.cn` 高并发返回 501）。并发 **≤5**，`ab_*.py` 里传 `--workers 12` 只是**跑回测**的线程数，回测不联网；联网抓取只在 `prefetch.py` 里，那里必须低并发。
2. **腾讯前复权对长期高分红股会复权出负价**（实测泸州老窖 −19.02、山西汾酒 −15.47、五粮液、紫金矿业…）。负价让 R / ATR / 收益率全部失真。`fetch_kline.py::_quality_ok()` 已做质量门：任一 OHLC ≤ 0 ⇒ **整只剔除**（不截断）。800 只里通常剔掉 45 只左右。
   > 不加质量门的后果：同一基线平均净收益从 `−1.20%` 变成 `+3.28%` —— **方向不变但幅度差约 3 倍**。
3. **`Backtest/Runner.py` 调 `check()` 时不传 `bars_held`**（恒 0）⇒ 任何基于 `bars_held` 的时间止损在回测侧**静默不生效**。实验侧靠 `ExpExitPolicy._hold` 自计数。
4. **`run_plan()` 的开关是类属性**（全局态）。绝不要跨方案并行；`install/reset/configure` 必须串行。
5. **`signif.py` 的方案名是硬编码**（`TARGETS` 且 `from ab_final import PLANS`）。改了 `PLANS` 的键名要同步改它，否则 KeyError。
6. **`ab_run.py::one()` 吞异常返回 `[]`** —— 某只标的跑挂会**静默变成"没交易"**。跑完要用「有效标的数」核对，数量异常要单独排查。
7. **股票池已按固定种子打散**（`stock_list(shuffle_seed=7)`），所以 `[:400]` / `[400:800]` 的板块分布是均衡的（实测：主板 129 / 创业板 120 / 沪市 151 vs 132 / 118 / 150）。**样本内外的差异不是"深市 vs 沪市"造成的。**
8. `.kcache/_universe.json` 一旦被写入空列表会**一直返回空**，症状是"标的 0 只"。删掉该文件重抓即可。
9. 缓存文件读出来**也会过质量门**，所以旧缓存里的脏标的会直接返回 `[]`，看起来像"接口失败"。
10. **`signal_quality.py` 的扫描是纯 CPU，必须用进程池**。用 `ThreadPoolExecutor` 会被 GIL 串行化：
    5000 根 × 300 只要 **18 分钟**，换 `ProcessPoolExecutor`（`--procs`）后 **~2 分钟**。
    Windows 是 spawn 启动方式 ⇒ 进程池的函数**必须写在模块级**（lambda 不能 pickle）。
11. **新浪分钟接口 `datalen` 硬上限 5001 根**（传 6000 也只回 5001）。所以：
    5m ≈ 104 个交易日、15m ≈ 156 个、30m ≈ 312 个。**缠论结构深度在 5m 上很浅**，
    跨周期比较时不要忘了这一点。另外分钟线是**不复权**的（新浪），跨分红日有一次跳空。

## 6. 基线锚点（用于回归对比）

> 口径：`freq=w`、`n=800` 根、`stock_list(800)` → 有效 **755 只**、取数日 2026-10-05。
> 换数据集或换周期后这些数字会变，但**同一数据集内**可用于判断"这次改动有没有跑偏"。

| 方案 | 全样本净% | 样本内 | 样本外 | 胜率% | 盈亏比 | 止损占比% | 跟踪占比% |
|---|---|---|---|---|---|---|---|
| **基线**（R 口径 1R→+0.5R / 2R→−1R） | **−1.20** | +0.40 | −2.93 | 51.7 | 0.87 | 40.6 | 26.2 |
| 百分比口径 5%→+2% / 10%→−5% | +0.45 | +1.12 | −0.28 | 55.0 | 1.10 | 21.5 | 47.3 |
| 百分比口径 5%→+2% / 10%→−8% | +0.64 | +1.36 | −0.14 | 51.7 | 1.13 | 21.4 | 47.3 |

基线笔数：1080（样本内 561 / 样本外 519）。

**核心结论（改参数前请先接受这个前提）**：8 个方案里样本外**无一转正**，全样本最高 `+0.64%`。
出场改造的作用是把「明显负期望」修成「≈零」，**它不是 alpha 的来源**。若目标是盈利，必须回到信号端。

### 6.1 信号质量基线锚点（口径二：信号 − 同标的随机入场）

> 脚本 `signal_quality.py`；配对 bootstrap 按标的、10 000 次、seed 7。
> 换股票池/换周期后这些数字会变，但**同一数据集内**可用于判断"这次改动有没有跑偏"。

| 周期 | 根数 | 有效标的 | 信号数 | 均 A% | 走出反向笔 | **全部信号 Δ** | **类型 1 Δ** | 类型 3 Δ | 保本层(5%)触发率 |
|---|---|---|---|---|---|---|---|---|---|
| 周K | 800 | 755 | 1 477 | 14.30 | 63.4% | −1.91% n.s. | −1.68% n.s. | −2.15% n.s. | 88.4% |
| 日K | 800 | 800 | 2 481 | 5.61 | 57.1% | **−1.36% \*\*** | **+6.55% \*\*** | −1.59% ** | 67.1% |
| 30分 | 5 000 | 300 | 8 430 | 2.06 | 58.1% | **−0.22% \*** | +0.24% n.s. | −0.37% ** | 27.2% |
| 15分 | 5 000 | 300 | 8 058 | 1.42 | 60.4% | +0.08% n.s. | +0.16% n.s. | +0.12% n.s. | 14.6% |
| 5分 | 5 000 | 300 | 9 885 | 0.95 | 54.9% | −0.05% n.s. | −0.13% n.s. | −0.04% n.s. | 6.4% |

**三条可回归的锚点**：
1. **全部信号 Δ 没有一个周期显著为正** —— 周K/15分/5分 不显著，日K/30分 显著为负。
2. **类型 1 是唯一稳定的正超额线索**（日K `+6.55% p=0.0018`、周K 做多·类型1 收益 `+14.94%`），
   但样本极少（周K 70 / 日K 79 条）⇒ **只能当线索，不能当结论**。
3. **`走出反向笔后 Δ > 0`、`原笔延伸后 Δ < 0` 在 5 个周期上全部 `p=0.0000***`** ——
   这是**条件于未来**的描述统计（用到 outcome），**不可交易**；可交易的版本是口径三。

⚠ **类型 2 在周/日线上是 0 条**：`Common/CEnum.py` 里 `T2 = '2' # 2类买卖点（待实现）`，
只有 `BuySellPoint/BSPointList.py:1612` 一处产出，分钟周期偶发几条（30分 4 / 15分 6 / 5分 27），**不足以评价**。

## 7. 出场策略的客观评价标准（"什么算好"）

> 这一节回答「回撤控制严格容易被扫掉、控制宽松又容易浮盈变止损 —— 到底怎么算好？」。
> 结论先给：**不存在"普适最优出场参数"，但存在一套公认的评价框架**；核心是把目标从
> "最大化期望" 换成 **"在期望不显著变差的前提下压缩方差"**。

### 7.1 先破一个幻想：出场策略不能凭空造 alpha

设入场信号的 H 根收益期望为 `μ`。任何出场规则产出的期望都形如

```
E[出场收益] = μ − E[被提前终止的机会成本] − E[成本]
```

出场规则只决定"在哪一根离场"，它**重新分配**同一个信号集的收益分布，**不改变分布的方向**。
`μ ≤ 0` 时，出场规则的唯一作用是**截尾降方差**，不可能把期望变正。

本项目已有实证：8 个方案样本外**无一转正**（§6）。
⇒ **"出场策略好不好"必须在"给定入场信号"的前提下评价**，判据是"它把风险调整后收益改善了多少"。

### 7.2 业界标准做法（按机制列，都有出处）

| 机制 | 出处 | 规则 | 目的 | 本项目的落点 |
|---|---|---|---|---|
| **固定分数风险** Fixed-Fractional | Van Tharp；Turtle Rules | 单笔风险 = f%×权益；仓位 = f%×权益 /（入场−止损） | 把"亏多少"从价格波动里解放出来 | 仓位预算（**当前未接**） |
| **风险单位 R** | Van Tharp《Trade Your Way to Financial Freedom》 | R = 初始止损距离；每笔盈亏以 R 计价 | 跨标的/跨周期可比；**期望 R 是统一判据** | `Exit._initial_r`（R 口径，正在退役） |
| **保本止损** Breakeven Stop | 通用 | 浮盈达 X 后把保护价抬到入场价附近 | 把"赢单变亏单"的概率压到 0 | L1（当前：浮盈 5% → 入场×1.02） |
| **Chandelier Exit**（ATR 跟踪） | Chuck LeBeau | 保护价 = 最高价 − k×ATR，k 常取 2~3 | 让利润奔跑又给波动留空间 | L2（当前：最高价×(1−5%)） |
| **Parabolic SAR** | Wilder | 加速因子 0.02→0.2 自适应 | 同上（时间自适应） | 无 |
| **时间止损** Time Stop | Linda Raschke 等 | 持仓 N 根仍未抬价 ⇒ 离场 | 释放被占用的资金 | `TIME_STOP_BARS`（**回测侧静默失效**，见坑 #3） |
| **分批止盈** Scaling Out | Turtle / 通用 | 到第一个目标减半仓，余仓让利润奔跑 | 压低方差、提高"落袋"概率 | 无（**建议下一步做**） |

**没有任何一条出处给出"标准参数值"** —— 业界只有标准**做法**，参数必须自己标定。

### 7.3 决定"严格 vs 宽松"的那个学术结论

> **Kaminski & Lo (2014)，《When Do Stop-Loss Rules Stop Losses?》，Journal of Financial Markets**

结论：**止损只在收益呈正自相关（趋势/动量）的序列上提高期望；在随机游走或均值回复的序列上，
止损系统性地*降低*期望** —— 因为它把噪声当成信息，反复被扫。

⇒ 你说的"控制严格容易被扫掉"，**不是感觉，是被证明的机制**。
⇒ **最重要的推论**：既然止损在无自相关市场降低期望，那出场策略的正确目标就**不是提高期望**，
而是 **"在不显著损害期望的前提下压缩尾部/方差"**。

这就把问题从"哪个参数赚得多"变成了一个**可解的约束优化**：

```
在 {方案 : Δ(对基线期望差) 不显著为负} 中，选 方差 / 最大回撤 / 被扫率 最小的那个
```

### 7.4 本项目的可执行判据（七条，按优先级）

| # | 判据 | 通过条件 | 为什么 |
|---|---|---|---|
| 1 | **`avg_net`（已扣双边手续费+印花税）** | 样本外**不显著为负**，且符号与全样本一致 | 唯一的主判据。**禁止只看胜率或盈亏比** —— 两者可以此消彼长而期望不变 |
| 2 | **期望 R**：`E[R] = 胜率×均赢R − 败率×均亏R` | 跨方案单调可比 | R 口径天然跨标的/跨周期可比（Tharp 框架） |
| 3 | **显著性**：按标的配对 bootstrap（seed=7，10000 次） | Δ 的 `p < 0.05` | 挡住"某方案平均收益高一点"这种噪声 |
| 4 | **稳健性：高原而非尖峰** | 参数邻域（±1 个 tick 比例 / ±20% 的 k）内表现平滑 | 单点最优 = 过拟合，直接弃 |
| 5 | **口径无关性**：写成 `k×ATR` 后在多周期同号 | ≥2 个不同波动量级的周期上同号 | 见 §7.5；**本项目目前只做到周K 最优，跨周期同号未通过，必须诚实标注** |
| 6 | **成本敏感性** | 让离场变快的方案，收益增幅 > 增加的成本 | 已内含在判据 1（metrics 已扣成本） |
| 7 | **风险侧指标**：`worst`、`sl_pct/be_pct/tr_pct`、**被扫率** | 同期望下，方差更低者为优 | Kelly 准则：`g ≈ μ − σ²/2` ⇒ **方差压缩本身就有价值**，哪怕期望没变 |

**判据 7 是"保本层"存在的全部理论依据**：保本层不提高期望（甚至略降，因为提前离场），
但它把"赢单变亏单"那一段分布切掉了 ⇒ `σ²` 下降 ⇒ 复利增长率上升。**所以别用"期望有没有变高"
来否决保本层，那不成立。**

### 7.5 把"严格 / 宽松"从感觉变成数字：被扫率

你困惑的另一半「控制严格容易被扫掉」必须被量化，否则"严格/宽松"永远只是感觉。定义：

```
被扫率(k) = 在结构止损被打穿【之前】已经浮盈 ≥ k×A 的信号占比     （A = |入场价 − 分型极值|）
```

- `mfe_fail_A` 由 `signal_quality.py` 在**打止损那一帧之前**冻结（不含该帧自身最高价）
  ⇒ 它衡量的是"真·事前已经拿到的浮盈"，不是事后诸葛。
- **这类样本有一个不是上界、而是确定的**反事实：L1 保本层若在浮盈 `k×A` 时把保护价抬到
  `入场价 + 0.4A`，那么价格后来既然一路走到 `−1A`（结构止损），**就一定穿过了 `+0.4A`**
  ⇒ 该笔离场价确定从 `−1A` 变成 `+0.4A`。
  （唯一失效条件：跳空直接跳过保护价。）
- **怎么用**：被扫率高 ⇒ **是初始止损（结构位）放得太近**，应该修 "初始止损"
  或 把保本触发门槛降到更早 —— 而不是去收紧"保本/跟踪"的触发门槛。

脚本：`sweep_regret.py`（用法与实测结果见 §6 附 与 `sweep_regret.json`）。

### 7.6 "好出场策略"的完整定义（可直接当验收单用）

在**给定入场信号 + 给定成本模型**下，一个出场方案要算"好"，必须同时满足：

1. **期望约束**：`avg_net` 在样本外**不显著为负**；
2. **无害化约束**：对基线的 Δ 配对检验 `p < 0.05` 为正，**或至少不显著为负**；
3. **方差压缩目标**：在满足 1+2 的候选集里，`sl_pct` / 被扫率 / `worst` 最低者胜；
4. **稳健性约束**：参数落在高原上，且写成 `k×ATR` 后在 ≥2 个周期同号。

- 不满足 1 的方案，**无论胜率多高都不算好**（我们 8 个方案全部止步于此）；
- 满足 1 但**方差没降**的方案，也不比基线好，不值得上（因为判据 7 的价值来源就是方差）。

### 7.7 跨周期怎么定阈值（百分比口径的周期依赖）

百分比是**绝对量纲**，同一个 5% 在不同周期上完全不是一回事。统一做法是改成 `k × ATR%`
（`ATR% = Wilder ATR(14)/close×100`），由 `atr_scale.py` 标定 k。

| 周期 | ATR% | 5% 相当于几个 ATR | 10% 相当于几个 ATR | 同 k 的等价阈值 |
|---|---|---|---|---|
| 股票 周K（**标定基准**） | 9.893 | **0.51** | **1.01** | 保本 5.00% / 跟踪 10.00% |
| 股票 日K | 3.931 | 1.27 | 2.54 | 保本 1.99% / 跟踪 3.97% |
| 股票 30分 | 1.113 | 4.49 | 8.98 | 保本 0.56% / 跟踪 1.13% |
| 股票 15分 | 0.746 | 6.70 | 13.40 | 保本 0.38% / 跟踪 0.75% |
| 股票 5分 | 0.501 | 9.98 | 19.95 | 保本 0.25% / 跟踪 0.51% |
| IF0 1分 | 0.065 | 76.51 | 153.02 | 保本 0.03% / 跟踪 0.07% |
| IF0 日K | 1.529 | 3.27 | 6.54 | 保本 0.77% / 跟踪 1.54% |

⇒ 结论：**同一个 5% 在股票周K 上是 0.51 个 ATR，在股票 5分 上是 9.98 个 ATR（差 20 倍）**。
这就是"不同周期百分比不一样"的精确表述。

`ab_atr.py` 的 A/B 结论（真实回测引擎，配对 bootstrap）：
- **周K**：固定% 优于基线（Δ `+2.63pp`，`p=0.0100*`）；`k=1.5/0.6/3.0/2.0` 的 ATR 组也显著（`+1.82pp`，`p=0.0186*`）；其余不显著。
- **日K**：**全部不显著**（Δ ≤ +0.47pp）—— 日K 上没有任何方案能挣回成本。
⇒ 所以 `k×ATR` 是一个**合理的跨周期起点**（k ≈ 1.0~1.5），但**必须逐周期重新验证**，
不能拿周K 标定的 k 直接套到 5 分钟上当作已验证。

### 7.8 先做亏损归因，再动参数：结构止损的**两族分解**

调参之前先回答一个问题：**亏的钱该算在入场账上，还是出场账上？** 用 `exit_fate.py` 拆：

| 族 | 定义 | 含义 | 周K 占比 |
|---|---|---|---|
| ② 原笔延伸型 | 反向笔没走出来就被打止损 | **入场前提当场破裂** —— 入场问题 | 28.1% |
| ① 走出反向笔型 | 反向笔走出来了，但浮盈没够到保本触发，最终回到初始保护价 | **出场门槛太高** —— 出场问题 | 12.5% |
| ③ 反向笔后保本/跟踪离场 | 正常路径 | — | 40.2% |

判别特征（5 个周期一致，可直接当诊断规则用）：
- ①族 **离场前均浮盈 0.52~0.59R**（＜1.0R 触发线 ⇒ 保本层从未启动）、
  均持仓 20.9 根、均净 **−26.89%**；
- ②族均浮盈 0.30~0.34R、均持仓 6.0 根、均净 −19.07%。

⇒ **①族是"保本触发线定得太高"的直接产物**，与周期无关（占比恒为 11.5%~13.0%）。
周K 端到端验证（`be_ab.py`）：门槛 1.0R → 0.5R，全样本 −0.66% → **+0.61%**、
止损占比 40.6% → **25.5%**、盈亏比 0.87 → **1.01**；
但**样本外仍 −1.10%、Δ 不显著（p=0.14）** —— 与「出场改造不是 alpha 来源」一致。

> 提醒：上一轮曾把①族错误地归入"信号质量好"（旧口径只看"有没有走出反向笔"）。
> 详见《报告_结构止损两族分解与回测并行化.html》。

### 9.1 并行化：回测必须用进程池，不能用线程池

`Runner.run()` 是**纯 Python CPU 活**（缠论递归 + 逐帧状态机），CPython 的 GIL 让
`ThreadPoolExecutor` 在这类活上**退化成串行**。实测（`bench_pool.py`，160 只 × 周K × 1 方案，20 逻辑核）：

| 并发方式 | 墙钟 | 相对 1 线程 |
|---|---|---|
| 线程 1 个 | 20.6s | 1.00× |
| 线程 12 个 | 22.1s | **1.07×（更慢）** |
| 进程 8 个 | **6.8s** | **3.05×**（逐笔一致 ✔） |
| 进程 16 个 | 7.9s | 2.78×（核多≠更快，甜点 8~10） |

⇒ **凡是"每只标的独立跑一遍完整回测"的脚本，都用 `--procs 8`**：
`ab_pct.py` / `ab_atr.py` / `ab_final.py` / `ab_run.py` / `ab_run2.py` / `signif.py`
（都经 `ab_run.run_plan` 这一个收口点）、`signal_quality.py`、`exit_fate.py`、`be_ab.py`。
或直接设环境变量 `EXP_PROCS=8`。**默认 0（线程路径）**，不改变既有行为。

**取数（I/O 密集）继续用线程池** —— 那里线程是对的，别一起改。

> ⚠ **进程池有一个会静默出错的坑**：`exp_policy.install()` 改的是**父进程内存里的模块属性**，
> spawn 出来的子进程**不继承**。漏了这一步子进程跑的是**原始策略** ——
> 症状是"结果静默变成基线值，而且看起来更快"，**没有任何报错**。
> 两道防线（已在 `ab_run.py` 落地）：
> ① `ProcessPoolExecutor(initializer=_proc_init)` 在每个子进程里重新 `install()`；
> ② `run_plan` 首次走进程路径时用前 3 只标的**实地对拍线程版逐笔结果**，不一致直接打红灯。
> 另：进程池要**常驻复用**（`get_pool` / `close_pool`），别每个方案重建一次 ——
> Windows 上 spawn 一次 ~0.5s，10 个方案就是几十秒白费。
