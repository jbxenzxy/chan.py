## 0. 一句话

把成交统计的记账口径从「**仓单级**（每笔平今/平昨成交 = 一笔交易）」改为「**run 级**（每次风控运行 = 一笔交易 = 一对成交：入场 fill + 离场 fill）」，使 R-OPEN 锁仓离场与拆锁的盈亏按信号正确归因；**总净盈亏不变**（对账恒等式见 §3.1），恢复的是胜率 / 盈亏比 / 平均盈亏 / 最大单笔的"每笔"语义。

## 2. 口径勘误（回应讨论 ⑴）

> 前一轮"配对会计不是没设计过，是被删了"的表述**不准确，已更正**。

- `origin / lock_pair_id` 是给**三态判定**用的（"现在是不是锁着"），不是给统计用的。`Engine.py:244-246` 注释明确：曾按"持仓来源标记"判定锁仓——删除原因是"把问题绕复杂的根源"，与统计配对无关。
- 平仓选仓规则从来就是**纯 FIFO**：`PositionBook.oldest_opposite`（PositionBook.py:207-217）——"平仓就是跟持仓序列中反向最早的仓单对冲掉。簿内仓单**没有配对概念**，只有时间先后"。
- 结论：**统计层从未有过配对会计**；run 级会计也不需要恢复 origin / lock_pair_id——run 的入场价 / 离场价直接取成交回报（fill），与"拆锁时选中哪一笔仓单"无关（§6 护栏 [S3] 钉死这一点）。

## 3. 口径定义（SSOT，唯一权威定义）

**一笔 Trade = 一次 run = 恰好一对成交。**

| 概念 | 定义 |
|---|---|
| **入场 fill** | ① 空仓态下信号开仓成交（OPEN，开仓档费率）；或 ② 锁仓态下拆锁平仓成交（CLOSE，**平昨/平今档费率**，不是开仓档） |
| **离场 fill** | ① 今仓离场 = 反向开仓成交（R-OPEN，开仓档）；② 昨仓/两态机离场 = 平仓成交（平昨/平今档）；③ 收盘托管关闭 `shutdown_and_lock_all` 的强制锁仓成交（reason=auto_order_off；**补做重试离场 reason=auto_order_off_retry**，见 §7-④） |
| gross_points | (离场 fill 价 − 入场 fill 价) × side.sign |
| cost_cash | 入场 fill 手续费 + 离场 fill 手续费，**各按自己成交的 offset 档** |
| net_cash | gross × 有效乘数 × 手数 − cost_cash |
| exit_at / reason | 离场 fill 时点；reason = run 的出场计划与阶段（现状 `_run_plan` / `_phase` 已有）；**强制离场时 reason 取强平 reason（auto_order_off / auto_order_off_retry），不得回落到 run 计划名** |

配套不变量（已在现网成立，run 会计依赖它们）：

- **run 与净敞口一一对应、串行**：运行态不加仓（**可执行判据 = `Engine._decide_action:1022-1024`**：`st = self.account_state()` → `if st is AccountState.RUNNING: return None`；调用点 `on_signal:900-903`，跳过时记 `signal_skip / running_ignore_signal`。原文引的 `Records.py:37` 属**买卖点类型过滤门**的注释行，v3.4 起降级为旁证、不再作证据 —— N1，见 §11.1）；手数 = |net_volume|。
- run anchor 现状就是入场 fill 价（实施后 `Engine.py:1497-1498`：`_run_start(o.filled_price, bar, sig, entry_offset=INTENT_TO_OFFSET[act.intent])`），拆锁 CLOSE 成交后 net≠0 同样触发 run_start——**入场侧数据已齐全，无需新增采集**。

### 3.1 对账恒等式（本设计的正确性锚）

每笔真实成交恰好归属一个 run（开仓 fill 或拆锁 fill = 某 run 的入场；反向开仓 fill 或平仓 fill = 某 run 的离场），因此：

```
Σ run.net_cash ≡ Σ 全部真实成交的现金流（含全部手续费）
```

级数裂项相消（telescoping）：前一 run 的离场 fill 价与后一 run 从对侧重新入场的价格，通过锁仓侧仓单的 entry/exit 首尾相接。**总额与仓单级严格相等，只有"切刀位置"不同。**

**成立前提（v3.1 修订，评审 §3.2 + 复审 R2）**：恒等式对**已完全平仓的成交史**成立——无在途 run，且簿内两侧仓单均为空。run 级 Trade 只在 run 结束时才存在，簿级平仓行只在平仓成交时才存在：**未全平仓时两侧同为部分和、不保证相等**——这不是设计错误，是"每笔归因只在收口时存在"的自然结果。两类未收口形态要分开看：**RUNNING 纯持仓态**两侧都还没有任何行、恰好同为 0（相等的合法快照——v3"互不相等"的反例，复审 R2）；**LOCKED 态** run 已随锁仓 fill 收口（实施后 `Engine.py:1500-1520`：结算 `:1505-1508` + `_run_end` `:1520`）而簿内持仓未平，两侧通常不等。[S2] 护栏据此用**结构性前提断言**（簿内两侧仓单数均为 0）做门禁后再比对数值，不把"数值不等"本身当断言；§8 补产品层提示。

## 4. 用户例子逐笔推演（对齐验证）

记号：开 A fill=4000，止盈反向开 B fill=4010；开 C fill=c，20 点止盈反向开 D fill=c+20；第二天平昨 B fill=p₁，止盈平昨 A fill=p₁+5；平昨 D fill=p₂，止盈平昨 C fill=p₂+6。

| # | run | 入场 fill（档） | 离场 fill（档） | gross | cost | 用户记账 | 一致 |
|---|---|---|---|---|---|---|---|
| T1 | D1 信号1（空仓→多） | 开A 4000（开仓档） | 反向开B 4010（开仓档） | +10 | 开A费+开B费 | 盈利10 − 开A − 开B | ✓ |
| T2 | D1 信号2（锁仓拆锁→多） | 开C c（开仓档） | 反向开D c+20（开仓档） | +20 | 开C费+开D费 | 盈利20 − 开C − 开D | ✓ |
| T3 | D2 信号1（锁仓拆锁→多） | **平昨B p₁（平昨档）** | 平昨A p₁+5（平昨档） | +5 | 平昨B费+平昨A费 | 盈利5 − 平昨B − 平昨A | ✓ |
| T4 | D2 信号2（锁仓拆锁→多） | 平昨D p₂（平昨档） | 平昨C p₂+6（平昨档） | +6 | 平昨D费+平昨C费 | 盈利6 − 平昨D − 平昨C | ✓ |

- 拆锁选仓：空仓单 {B,D} 平最早（FIFO）= B ✓；多仓单 {A,C} 平最早 = A ✓——与 `oldest_opposite` 现网行为一致，**无需任何配对标记**。
- 恒等式抽查（真实现金流）：A 仓 (p₁+5)−4000，B 仓 4010−p₁，C 仓 (p₂+6)−c，D 仓 (c+20)−p₂；Σ = 10+20+5+6 = 41 = Σgross ✓（评审独立复演 5 个已收口场景三账全等；复审复演 4 收口全等 + 3 在途部分和）。

**结论：用户表述的口径 ≡ 本文"按 run 记账"，无分歧。** 唯一补充强调的一点：T3/T4 的入场 fill 费率是**平昨档**（用户例子已正确计入"平昨B仓手续费"）。

### 5.2 run 生命周期（改动后）

```
空仓 ──开仓 fill(开仓档)──▶ RUN(入场=fill) ──离场触发──▶
   ├─ 今仓: 反向开仓 fill(开仓档) → _settle_run 写 Trade → 锁仓
   ├─ 昨仓/两态: 平仓 fill(平昨/平今档) → _settle_run 写 Trade → 空仓

锁仓 ──信号→平昨/平今 fill──▶ RUN(入场=拆锁 fill, 平昨/平今档) ──▶ 同上
```

## 8. 坑点备忘

- 拆锁场景下 `_book_close` 的 `pos.entry_price` **不能**再当 Trade 的 entry 用（这正是仓单级口径错误的根源）；run 级 entry 一律取 `_run_start` 的 anchor。
- run 结算必须只在 run 结束点写**一次**：锁仓离场 / 平仓 / 对账强平 / shutdown（含 retry）路径全部收敛到 `_settle_run` 唯一出口，防双写（[S9]+[S7b] 钉住）。
- `by_reason` / equity_curve 的时点语义改为离场 fill 时点——与现状 `now_cn()` 一致；[S1] 断言曲线末值 == total_net。
- 三态判定 / 选仓 / 报单路径**零改动**——本设计只动"记账"，不动"执行"（一进一出原则不受影响）。
- FAK ≡ FOK 是 ExecPolicy 构造期硬断言（Product.py:232-236）——未来若有人放开"FAK + N>1"，既有断言会先拦下；run 会计无需防御性代码。
- **未全平仓的部分和**（v3.1，复审 R2）：RUNNING/LOCKED 态下 Σrun 与 Σ仓单级同为部分和、**不保证相等**（RUNNING 纯持仓态两侧同为 0 是合法相等快照；LOCKED 态 run 已收口而簿内持仓未平，通常不等）；产品层提示——统计面板"总净盈亏"在锁仓态下**天然不含未兑现持仓**，与现状一致（现状同样不计），不是回归；恒等式只在全平仓后成立（[S2] 结构性门禁）。
- **两 broker 的 `meta["offset"]` 语义不等价**（v3.1，复审 R1）：DryRun 写 `INTENT_TO_OFFSET[intent]`（OPEN/CLOSE/CLOSETODAY），SimNow 写 action 标签（open/close）——任何"读 broker meta 选费率档"的新代码都会在 SimNow 路径静默取错档；本设计主路径 `INTENT_TO_OFFSET[act.intent]` 天然规避。

## 12. 缺口场景说明（大白话 · **v3.4 新增**；**v3.5 起仅含 B4**）

> 回答「这几个编号到底在什么场景下咬人」。本节只收录 **B4-1 / B4-2** 两条（原 B1 / B2 两个场景已随 2026-09-22 的裁定移出，见 §10.4 表下注）。两条的共同前提 = **部署配置与执行策略表分叉 / 恢复数据缺字段**，默认部署下都不触发。

### 12.1 B4-1 —— 对账强平该收哪一档手续费，可能取错

- 两个"档"的来源不同：
  - **离场决策（走哪条路）**：品种执行策略表**第 1 列** `today_exit` —— `EXEC_POLICY`（`Product.py:241-250`）里 IF / IH / IC / IM / TA 是 `R-OPEN`（今仓离场 = **反向开仓，开仓档**）、AU / AG / CU 是 `CLOSETODAY`（今仓离场 = **平今档**）；读取点 `Engine._today_exit:1185-1186`。
  - **会计侧取档**：`state.closetoday_first`（今仓成本开关）+ 仓单建仓日 —— `Reconcile.py:353-356`。
- 出问题的样子：配置里把 `closetoday_first` 显式设 `False` → 对账强制结算**一律按平昨档**计费，而该品种真实离场本该按 **开仓档（`R-OPEN`）** 或 **平今档（`CLOSETODAY`）** → 对账那一笔的**费率档与真实离场不同**，表现为金额小幅对不上（不易发现）。
- 可达条件：`closetoday_first` 是部署字段（`Instrument.py:118`，默认 `True`；生产唯一构造点 `Trading/main.py:195`）；**全仓唯一显式置 `False` 的是 `test_p24:201`** → 默认部署下不触发。
- 注：不是 v3.2 新引入 —— `_write_close_event:1641` 早就是同一套判定，新代码只是继承。

### 12.2 B4-2 —— 入场时点缺失时被"顶替"成结算时刻

- 正常：`_run_start` 记下入场成交时点（`_run_entry_at`），结算时写进 Trade 的 `entry_at`（`Engine.py:1610`）。
- 出问题：从 state.db 恢复的 run 记录里 `entry_at` 缺失 → `:715` 恢复成空串 → `:1610` 的 `entry_at=self._run_entry_at or now_cn()` **静默**把"结算那一刻"当成入场时刻。
- 后果：Trade 的**入场时点**错（可能跨日），事后人工核对"这笔拿了多久"会误读；**不影响金额**（`bars_held` 由 bar 序号算，不走 `entry_at`）。
- 对照：同一次 `_restore_run` 里 `entry_offset` 走**启动期 fail-fast**（`:707-714`，缺字段即拒绝启动并提示删库），`entry_at` 没有同等待遇 → 建议改同口径（本次未改）。
