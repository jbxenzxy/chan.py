| ------------------ | -------------------------------------------------------------------------- | --------------------------------------------------- |

## §1 结论先给

**v1.1 的五条结论（前四条由你的第二轮质询改写）：**

1. **架构只有一条路线，不存在"便宜版 vs 严格版"的取舍**（推翻 v1.0）。流式逐根 `step_load` 是**一次遍历**：实测 1393 根日线 **2.27 秒**。它同时满足三件事 —— 与实盘同构、天然无未来函数、成本与"全量跑一遍"同阶。我 v1.0 说的"严格版成本高 1~2 个数量级"是把流式误当成了 as-of 滚动重算，**那个说法作废**。
2. **"首见冻结"不需要单独建机制**（推翻 v1.0）。流式推进到信号产生的那一帧，此时读到的分型极值就是首见态 —— 冻结是流式的副产品（§2.6）。这消解了我 v1.0 里 3/11 信号 A 漂移的那个工作量（漂移本身是真的，但架构上自动规避，代价为零）。
3. **你的 ⑷⑸ 联合解决了一个我漏掉的真问题，且它是决定性的**（§2.7）。实测 0 类买点存在**间隔仅 1 根的连续信号簇**（2025/07/17~22 连续 4 根各生成一个）。本样本 8 个 0 类信号按信号计数是 8 笔，按状态机去重只有 **3 个真实交易机会** —— **虚高 2.7 倍**。所以两态状态机**不是可选口径，是必需项**；这也意味着作者机器上报的"T0 信号 9,677→10,402"里，有一部分可能是这种重复簇而非新机会。
4. **出场组装不用抽也不用抄**（§3.5）。`App/AppTPSL.py` 经查只是 HTTP 壳 —— `LayeredExitPolicy` / `Signal.from_bsp` / `Instrument` / `Position` 全部来自 `Trading/`。Backtest 直接依赖 `Trading/` 即可，`App/` 一行不动；且你说将来会删 TPSL，那样 Backtest 反而**零残留**。

**结论：不会。你担心的那一步（"出场前出现了新 XDXR B，要把前面的 K 线按 B 重算"）在当前代码里不存在。**

**`step_load` 这一侧也印证了**：`Chan.load()` → `CTdxAPI.get_kl_data()` 是**对本请求注入的 `_tdx_data` 逐根 `yield`**，即它只是把一份**已经复权好的 list** 一根根吐出来（`DataAPI/TdxAPI.py` 的 `CTdxAPI.get_kl_data`）。K 线对象一旦构造，OHLC 不再被任何复权逻辑改写 ⇒ **A 入场时按当时价格算出的止损/止盈/保护价，在其持仓期内引用的都是同一批（已定稿的）价格**。

### 2.8.1 那"持仓跨越除权日"怎么办？—— 前复权本来就是为它设计的

`_forward_adjust` 只改 `dt < event_date` 的记录 ⇒ **除权日之前的价格被换算成"除权日之后的货币"**，于是整条序列在除权日**连续**，不会虚假跳空。所以：

- 入场在除权日前、出场在除权日后 ⇒ 入场价被换算、出场价不变，**差值就是含权收益**，这正是前复权的目的；
- 全程在除权日同侧 ⇒ 两侧同受一次变换，差值同比缩放。

⇒ **不需要"同步调整 A 的止损止盈"这一步**。真要那么做反而会引入第二套价格体系。

### 2.8.2 一条对回测特别有用的性质：R 倍数在复权变换下不变

复权是**仿射变换** `p' = a·p + b`。对同一笔交易（入场与出场同在一次复权口径下）：

- 分子 `(出场价 − 入场价)` → `a × (出场价 − 入场价)`（常数 `b` 相消）
- 分母 `R` 本身也是价格差（`max(A, 2×ATR)`）→ `a × R`

⇒ `r = a·Δp / (a·R) = Δp / R`。**R 倍数、胜率、盈亏比、盈利因子全部与复权锚点无关。** 只有**元口径**的绝对金额随 `a` 缩放（这也是"前复权价 ≠ 真实成交价"的既有披露，`App/AppTPSL.py` 模块 docstring 已注明）。

⇒ 定案：**回测的主指标（R 倍数 / 胜率 / 盈亏比）用复权价算即可，无需还原真实价**；元口径金额在报告里标注"前复权价口径"。

### 2.8.3 边界：什么时候它才会变成真问题

只有一种情况会出问题 —— **中途换锚点重算**，即"同一段序列先用锚点 X 复权跑一遍、再用锚点 Y 复权跑一遍，把两段结果拼在一张表里"。这正是 v1.2 里 R2「延伸评估」的形状（R 之后用同一份"以 R 为锚"的复权价，却当作"当时的真实价"用）。

**而你 ⑹ 已经把这条路堵死了**：方式 A 与方式 B 一律流式加载到 R 为止、之后视为无数据 ⇒ **不换锚点、不拼接** ⇒ 该问题不存在（§4.5 R12）。

### 4.6c Q11（你的第五轮 ⑶）：同根平仓后能否再开新仓 —— **你对，我 v1.3 写错了**

你的原话：

> 平仓依赖于止盈止损逻辑，开仓依赖于开仓条件，按我理解这俩是独立的，如果一根K线的收盘价同时满足平仓和开反向新仓，应该是可以开新仓的，不知道这样处理有什么隐含问题？你说的"同根平了又开在回测里意义不大，且会让持仓根数=0的交易混进来"是何意？

**三问逐个回答：**

**（1）"这俩是独立的" —— 对，且代码里就是这么写的。** `Trading/Engine/Engine.py` 的模块 docstring「每根 K 线的处理顺序」把每根分成两步：**① 结算已有持仓**（用刚闭合这根的 close 判 L1-L3）→ **② 才处理落在这根上的信号**（决定开仓）。平仓由 ① 的出场策略决定、开仓由 ② 的信号决定，两条链不共享任何判据。⇒ **同一根上"平掉旧仓 + 开反向新仓"是允许的**，且因为 ① 在 ② 之前，平仓先发生、持仓回到 FLAT，随后新信号才进状态机 —— 反手是自然结果，不需要额外分支。

**（2）"同根平了又开"有没有隐含问题 —— 有两条，都不严重，但必须知道：**

| # | 隐含问题 | 处理 |
|---|---|---|
| 1 | **成本翻倍**：一次平 + 一次开 = 收两次佣金（+ 卖出的印花税）。若平的是多、开的也是多（同根同时有卖点和买点 ⇒ 净效果是"换仓"），则付出了完整双边成本却没换方向 | 不做特殊处理，但报告单列**交易成本合计**。若发现这类"同根换仓"占比高，再考虑加抑制 |
| 2 | **它依赖 T+0**：真实 A 股 T+1，当日买入不可当日卖出 ⇒ 同根反手在实盘**做不到**。回测允许它，等于假设了一个实盘不可达的操作 | 这是 §5.3 那条"回测按 T+0、不建模 T+1"的既有偏离，报告统一披露，不单独为它加规则 |

**（3）"持仓根数=0的交易混进来"是何意 —— 我 v1.3 的表述错了，撤回。**

我当时的担心是"同一根开仓又平仓 ⇒ 持仓 0 根、盈亏恒为负（只亏手续费），进胜率分母会拉低胜率"。**这个情形在本设计里不可能发生**：

### 4.7.2 放行判据：照抄，不许自造

### 4.7.3 ★ 落点必须是「事前过滤信号」，不是「事后过滤成交」

这是本节最关键的一条。两种落点在**独立逐信号**口径下等价，但在**两态状态机**下**不等价**：

| 落点 | 位置 | 被过滤类型的信号 | 后果 |
|---|---|---|---|
| **PRE 事前过滤（必须）** | 信号进入状态机**之前**，照抄 `Engine.py:924`（在 `_decide_action` 之前 `return`） | **根本不出现**，也不占用持仓期 | 被放行类型在同期可自由开仓 |
| POST 事后过滤 | 全跑一遍，再从统计里剔除不允许类型的成交（`TradeStats.py:146` 的落点） | 仍会开仓、仍占用持仓期 | 持仓期内出现的**被放行类型**信号被拒收，**这笔损失事后补不回来** |

⇒ **回测必须走 PRE**。理由不只是"与引擎同位置"，而是：选 POST 会让"取消勾选 3 类"这个动作**间接改变 0 类的结果**（因为 3 类空出来的持仓期本可让 0 类进场）——这正是用户无法预期的静默耦合。

**实测（本样本）**：PRE 与 POST 结果**完全相同**（放行 `0` / 放行 `3` 两种配置下都是 3 笔、逐字段一致）。原因是本样本里 **0 类与 3 类在时间上完全不重叠**（所有 3 类信号 idx ≤ 336，所有 0 类信号 idx ≥ 561），被过滤类型的持仓窗口内**没有出现过**被放行类型的信号（重叠次数 = 0）。

### 5.2 核心循环：一次遍历同时做完三件事

不再拆成"先采集、再评估"两步 —— 拆开就会被迫引入"最终态 vs 首见态"的问题。合在一起则问题消失：

```python
pol = LayeredExitPolicy(STOCK_EXIT_PARAMS)   # ★ 全程唯一实例，ATR 从头连续累积
state = FLAT
for snap in chan.step_load():                # 逐根流式推进
    kl = snap[0]
    bar = Bar.from_klu(kl[-1])               # 刚闭合的这根

    # ① 先结算已有持仓（用刚闭合这根的 close 判 L1-L3）
    #    —— 顺序照抄 Trading/Engine/Engine.py:39「每根 K 线的处理顺序」
    if state == IN_TRADE:
        pol.on_bar(bar, inst)
        chk = pol.check(pos, bar, inst)
        if chk is not None:
            if chk.plan is not None:
                pos.exit_plan = chk.plan     # 先抬价（进保本/跟踪）
            if not chk.only_update:
                record(exit_date=bar.date, fill=chk.fill_price,
                       reason=chk.reason, r_mult=(fill-entry)*side/R)
                state = FLAT                # ★ T+0：当根即平，不等次日
                # ★ 不 continue（Q11 定案）：平仓后落到 ② 的信号处理，同根允许开新仓

    # ② 再看本帧新出现的信号（只有 FLAT 态接收 —— 你 ⑸ 的规则）
    if state == FLAT:
        for bsp in new_bsp_this_frame(kl):
            # ★ 类型过滤：事前过滤，照抄 Engine._bsp_type_allowed（§4.7.3）
            #   未放行 ⇒ 不进状态机、不占持仓期，不是事后剔除成交
            if not bsp_type_allowed(bsp.type2str()): continue
            sig  = Signal.from_bsp(bsp_dict, symbol, freq)
            entry = bsp.klu.close                 # 入场价 = 信号K线收盘价
            plan  = pol.plan(sig, entry, inst)    # ★ 此刻读到的分型 = 首见态
            pos   = Position(..., exit_plan=plan)
            state = IN_TRADE
            break                                 # 一帧最多开一笔
```

**三个"顺序错了结果就错了"的点**：

1. **① 在 ② 之前** ⇒ 自动满足"入场那根不判出场"（`App/AppTPSL.py:156` 步 9 的同口径），无需额外判断。
2. **`pol` 全程唯一** ⇒ ATR 从头连续累积，不需要每次入场前预热 60 根。
   ⚠️ 这与 `AppTPSL` 的做法不同（后者每次 HTTP 请求新建 `pol` 并预热 60 根）。两者在开局前 ~60 根内 ATR 会有微小差异，之后收敛。若要与右键推演**逐笔对账**，需加开关走"每次预热 60 根"模式（Q-E）。
3. **冻结发生在 `pol.plan()` 这一行** ⇒ 分型是"信号首次出现那一帧"的值，天然是首见态（§2.6）。
4. **类型过滤在 `state == FLAT` 之内、且在开仓之前**（§4.7.3）。放在这里才等于 `Engine.py:924` 的位置；放在开仓之后就退化成事后过滤，会引入"被过滤类型间接影响被放行类型"的静默耦合。
   （注：v1.2 此处曾有 `if not bsp.is_buy: continue  # 只做多`，已随 Q10 作废删除 —— 现双向处理，买点做多、卖点做空，§4.6。）

实测成本：**1393 帧 / 2.27 秒**（sz002190 日线，含逐帧快照）。单标的单周期 ⇒ 前端按钮**同步返回即可**。

### 5.3 你的 ⑸：两态状态机规格（采纳，钉死）

| 项 | 规格 | 依据 |
|---|---|---|

| `FLAT + 卖点` | → **开空仓**（v1.2 改：双向） | 你的第三轮 ⑵ + §4.6（`Side.SHORT` 原生支持） |
| `IN_TRADE(多) + 卖点` | → **拒收**（Q13 已定案，你的第五轮 ⑴） | 开关照抄 `EntryConfig.reverse_on_opposite_signal`（默认 False，§4.6）。注：拒收会压低做空侧笔数，但**不影响口径正确性**（§4.6b：主口径合并，笔数用标签披露即可） |

| T+1 | **不建模**（股票按 T+0、按平今处理）⇒ **这是回测对真实 A 股 T+1 的偏离**，报告必须披露 | 你的 ⑸ + 你的 ⑻ |

**与 `Trading/Engine/Engine.py` 的关系**：同构但**不复用**。

- 同构：Engine 的 `EngineState` 是 `IDLE / OPENING / IN_TRADE / EXITING`（`:146-155`），其中 `OPENING/EXITING` 是"下单到成交之间"的瞬态 —— 回测里撮合是瞬时的，这两个态退化，**剩下的就是 IDLE ⇄ IN_TRADE 两态**，与你说的完全一致。

**5.3.1 T+0 的准确口径（你的 ⑻，R15）**

我 v1.3 写的"当根成交"**把一种极端情况当成了规格**。准确表述是：

### 5.4b 股票 vs 期货：统计项逐项核对（你的 ⑼，R16 —— 别继承错误）

**先回答你的两个问题：**

| 你的问题 | 回答 |
|---|---|
| 股票期望值应该是"元/手"吧？ | **对**。期货：报单一次 = 1 笔 = `lots_per_order` 手（当前 N=2）⇒ 面板写"元/笔"，一笔含 2 手。股票：报单一次 = 1 笔 = **1 手 = 100 股** ⇒ 一笔 ≡ 一手 ⇒ **写"元/手"**。两个市场的"笔"不是同一个量，标签不许混写 |
| 改成 200 股/手后，"元/手"可以不变吧？ | **对，单位不变**。每手股数 100→200 只让**数值**翻倍（同样价位下盈亏翻倍），量纲仍是"元/手"。⚠ 真正会随股数变的是另一件事：**单笔最低佣金 5 元**的摊薄 —— 股数越大，5 元占成交额比例越低（见下方费率表） |

**逐项核对表**（"⚠"＝不能照抄期货的项）：

| 统计项 | 期货（现役面板） | 股票回测 | 差异根因 |
|---|---|---|---|
| 一笔的定义 | 一次报单 = `lots_per_order` 手（当前 2；TA 因 FAK 恒 1） | 一次报单 = **1 手 = 100 股**（可配，须 100 的整数倍） | 股票无"一笔多手" |
| 期望值量纲 | **元/笔**（笔含 N 手） | **元/手**（笔 = 手） | ⚠ 标签必须区分 |

### 5.4c 期望 R 倍数：定义与算法（你的 ⑽，R17）

**单笔**（与 `App/AppTPSL.py` 的 `exit.r_multiple` **同式**，可逐字段对拍）：

```python
r_i = (fill_price_i - entry_price_i) * side.sign / R_i
#   side.sign: 做多 +1 / 做空 −1（Trading/Infra/Records.py 的 Side）
#   R_i      : 该笔入场时刻算出的 R = max(A, 2×ATR14)（Exit.py 的 _initial_r）
#   fill     : 触发那根的收盘价（出场触发只读 close）
```

**期望 R 倍数** = 已平仓笔的 `r_i` **算术平均**（未平仓不进分母）：

```python
expectancy_r = sum(r_i for i in closed) / len(closed)
```

**它的意义**：把盈亏换算成"多少个初始风险"。**1R = 这笔交易一开始打算承担的风险**。
于是 `r = +2.0` 读作"赚了当初愿意亏的钱的 2 倍"，`r = −1.0` 读作"刚好亏掉初始止损"。
它**与价格、股数、合约乘数全部脱钩** ⇒ **跨标的、跨周期、跨价格可直接比较** —— 这是"元/手"做不到的
（30 元的票和 300 元的票，同样的策略，元/手会差 10 倍，R 倍数相同）。

**为什么用毛口径（不扣成本）** —— 三条理由，按重要性排：

1. **可与右键推演逐字段对拍**：`App/AppTPSL.py` 的 `exit.r_multiple` 就是毛口径。改成净口径后 P0 的"逐笔对账"判据失效（§6 P0 判据 ①）。
2. **保持跨标的可比**：成本是"元"量纲的绝对量，混进 R 倍数会让高价位标的天然占优，正好破坏它存在的唯一目的。
3. **R 是价格尺子**：`R = max(分型距离, 2×ATR)` 是纯价格量，分子分母保持同一量纲才自洽。

⇒ **代价**：毛 R 会**系统性高估**一点点（本样本约 0.05R~0.12R/笔）。处理方式不是改口径，而是
**在报告里同时给出"净期望值（元/手）"这一行**（那才是扣完成本的真金白银），并在 R 倍数旁标注"（毛，未扣成本）"。

**配套口径**（这三项**仍然按净额**，与统计面板一致）：胜率 / 平均盈利÷平均亏损 / 盈利因子 / 总净盈亏 —— 全部读
`net_cash`（净额）。⇒ **报告里毛与净并存是刻意的**：R 倍数回答"策略质量"，元口径回答"赚多少钱"。

### 5.5 两种口径（v1.1 修订：主次反转）

| 口径 | 定义 | v1.1 定位 |
|---|---|---|
| **组合时序**（状态机去重） | 有持仓时新信号被拒 | **主口径**，决策依据。样本实测 8 信号 → 3 笔 |

### 5.7 类型过滤实测（v1.3 新增：`sb/probe_filter.py`）

## §8 风险与边界

1. **样本边界**：§2 所有数字来自 **1 只票 / 1 个级别 / 11 个信号**。3 个漂移全是 3 类点，8 个 0 类点未观测漂移但不等于免疫。**漂移巡检（P4）必须常驻**，不能"测过一次就放心"。
1b. **信号簇是比漂移更普遍的风险**（§2.7）：连续右肩簇在单样本 8 个 0 类信号里就占了 5 个（3 簇）。**任何按"信号数"计数的统计都不可信**，必须按状态机去重后的交易笔数。这条适用于本文之外的所有现有统计（含作者机器上报的 9,677→10,402）。
1c. **去重后样本量会骤降**：本样本 11 信号 → 状态机去重后仅 **5 笔买点交易**（155/235/561/1098/1120），0 类仅 3 笔。**单标的回测没有统计意义**，结论必须来自多标的汇总 —— 这是 P3（全市场）不可省略的理由。
2. **前复权价 ≠ 真实成交价**（`App/AppTPSL.py:11-12` 已注明）：股票 K 线是前复权价，回测基于它，与真实成交有差。这是性质不是缺陷，但报告里要写明。
3. **停牌 / 涨跌停未建模**：保护价可能不可成交。同上，注明即可，不要试图建模（会引入更多假设）。
4. **回测不得复用实时分析的缓存与锁**：这是你"不碰 App/"的核心理由，设计上通过"Backtest 直接调 Chan + DataAPI，不经过 App 层"保证。
5. **不要为了回测改缠论核心**：回测只消费信号，不参与信号生成。
6. **T+1 偏离（v1.4 新增）**：回测按 T+0 处理（你的 ⑸ + ⑻），真实 A 股当日买入不可当日卖出 ⇒
   **靠左/日内型信号的回测结果在实盘不可达**。报告必须披露；若将来要做"只能做多 + T+1"的
   保守版，那是另一套状态机（不是开关），单独排期。
7. **前复权价的二重性（v1.4 新增，§2.8）**：R 倍数 / 胜率 / 盈亏比在复权变换下**不变**（可放心用）；
   **元口径金额随复权系数缩放**，与真实账户金额不等（真实除权会收到现金红利/送股）。
   ⇒ 金额口径只用于"同一份数据内部比较"，不要拿去对账真实账户。
8. **方式 B 下的静默延伸风险（v1.4 新增，§4.5e）**：`full_records` 里 R 之后的数据**在内存里**。
   实现时必须在 `Runner.py` 入口显式截断到 R，否则会悄悄变成已作废的 R2 口径且无人察觉 ——
   这条要写进契约测试。
9. **成本口径依赖外部事实（v1.4 新增）**：印花税 / 过户费 / 规费是**国标、会变**（印花税 2023-08-28 刚减半）。
   费率应集中在 `Backtest/ExitParams.py`（或同级常量）一处定义并带出处与取数日期，
   **不要散落在计算里**；且报告要打印"本次使用的费率"。
