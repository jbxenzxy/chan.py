# 盘中量能（沪深京 · 盘中实时）

> 按钮名演进：需求提出时叫「预测量能」，2026-11-26 改名 **「盘中量能」**；
> 同一天「市场量能」改名 **「盘后量能」**，顶栏顺序调整为
> **盘中量能 → 盘后量能 → 两融余额**。面板内部文字**不变**（标题「市场量能」、
> 「今日｜预测量能 NNNN亿」、底部注释仍是开盘红截图的原文，1:1 复刻的一部分）。

顶栏「盘中量能」按钮 → 左下角面板：按「历史同时段累计占比」推算当日沪深京
三市全日成交额，并画出从开盘到当前时刻的预测曲线。

与「盘后量能」（`App/AppAMO.py`，读本地 `vipdoc` 日线，只看日频历史）是**两个
不同口径的功能**，只是面板长得像。

## 2. 算法

```
P(t) = C(t) / r(t)
C(t) = 当日截至第 t 根 1 分钟 bar 的累计成交额
r(t) = 过去 N 个交易日「同 bar 序号累计 / 全日总量」的加权均值
```

- **按 bar 序号（0..239）对齐，不按时间标签**：盘中 11:30 那根 bar 服务端会
  标成 `13:00`，按时间对齐会让整张 r 表错位。
- 权重 `0.5 ** ((N-1-i)/halflife)`，默认 `N=20`、`halflife=10`。
- 收盘（240 根走完）直接令 `P = C`，避免末根占比 <1 带来 +0.1% 的假偏差。
- 非交易日（周末 / 法定假日）：面板展示「最近一个交易日」的收盘态，
  「昨日」= **该交易日的前一个交易日**，不是日历上的前一天。
  例：周日打开 → 标题是周五、实际量能是周五全天、「昨日|总量能」是周四全天；
  周中遇法定假日 → 标题是假日前最后一个交易日、「昨日」是它的前一交易日。
  「周六」「假日当天」永远不会出现在这个字段里 —— 基准只可能取自 r 表样本中
  真实存在的交易日（`yesterday_total` = 样本末日总量，`prev_total` = 样本倒数
  第二天总量），两条路都来自有分钟线的日子。
- 基准选择规则（`call_energy`）：`trade_date == 展示日` ⇒ 取 `prev_total`；
  否则取 `yesterday_total`。这覆盖三种时序：盘中（样本末日=昨天）、
  收盘后（样本末日=今天）、周末与假日（样本末日=最近交易日）。

回测（2026-10-15 ~ 11-25，30 个交易日，r 表用前 20 日）：

| 时点 | 09:50 | 11:00 | 11:30 | 14:00 | 收盘 |
|---|---|---|---|---|---|
| MAPE | 8.4% | 7.1% | 5.7% | 3.3% | 0.1% |

参数敏感性：`N` 取 20~40、halflife 10 与等权差异都在 0.2pp 内；`N=3~5` 明显更差。
**开盘前 30 分钟误差最大，属不可信区间**。

## 3. 与开盘红 App 的已知差异

App 那条曲线左端从 **-33.22%** 起步，本实现从 **-6%** 左右起步。原因：

- App 的左端点对应「**只有 09:25 集合竞价**」那一刻（三市竞价约 118 亿），
  除以竞价占比 ~1.27% 得到 9300 亿 → -33%；
- 通达信 1 分钟 K 线的第一根（09:31）**已包含集合竞价 + 首分钟连续竞价**
  （约 600 亿），起点天然高得多；
- 本实现不伪造竞价点，也不做 EMA 平滑（平滑会让 11:30 的终值滞后 ~0.8%）。

终值精度不受影响：11:30 复现 13185 亿 vs App 13140 亿（+0.34%），
隐含上午占比 60.81% vs App 61.02%。

## 4. 接口

`GET /api/energy/read`（无参数，与标的/周期无关）→ `orch.call_energy()`

```json
{
  "date": "11-26", "trade_date": "2026-11-26", "status": "break",
  "actual": 8017.80, "predict": 13185, "yesterday": 13928.30,
  "pct": -5.34, "delta": -743, "shrink": true, "bars_done": 120,
  "points": [[1, -7.73], [2, -9.85], "..."],
  "marks": [{"k":0,"label":"09:30"}, "..."]
}
```

`status` ∈ `pre / trading / break / closed`，前端据此决定轮询节奏
（trading 3s、break 30s、pre/closed 停）。

## 5. 缓存与性能

| 层 | TTL | 说明 |
|---|---|---|
| 实时快照 | 2s | 主站实测约 1.3s 刷新一次（见下）；2s 兼作多客户端合并窗口 |
| 当日分钟线 | 60s | 曲线是分钟粒度，拉一次要 3 次 `bars` 调用；末点由快照覆盖，不吃这个 TTL |
| r(t) 表 | 每个交易日收盘后重建一次 | 落 `App/energy_ratio.json`；周末/假日当天只试一次 |

**主站刷新频率实测**（2026-11-26 13:00:10 起 60s 窗口，0.4s 轮询、0.45s 有效分辨率，
三市 `amount` 合计任一变化即计一次）：

- 检出 **45 次变化**，平均 1.33s 一次；
- 间隔呈 `0.45 / 0.91 / 1.37 / 1.82s` 的量化台阶 —— 这是**轮询分辨率造成的下限而非
  主站上限**，即主站实际刷新快于 0.45s 也能被看成 0.45s；
- 间隔中位 **1.37s**、最小 **0.45s**。

据此把快照 TTL 从 3s 收紧到 2s、前端盘中间隔从 5s 收紧到 3s：
盘中端到端最坏滞后从 ~8s 降到 ~5s（3s 轮询 + 2s TTL + 网络）。

- **r 表重建要 3~10s**（3×2400 根分钟线，分页拉），故必须落盘；盘中直接用昨日样本，
  只有收盘后第一次请求才重建。冷启动实测 10.4s，因此前端首屏提示写「约 10 秒」。
- **周末 / 法定假日只重建一次**：这两天行情源不产生新分钟线，重建也推不动样本末日。
  过期判据（`_is_stale`）因此带 `built_at` 兜底 —— 今天收盘后已经建过就不再判过期，
  否则 15:00 之后**每个请求**都会重拉 3×2400 根（3~10s），长假里天天如此。
  反向条件同样保留：`built_at` 是今天**收盘前**的（盘前冷启动建过），15:00 后仍重建一次。
- 缓存命中时整条链路 **0.00s**（实测连续两次调用：首次 14.0s 含 r 表重建，
  第二次 0.000s）；快照 TTL 2s 生效时，1.2s 间隔连打 6 次 `actual` 呈两两相同的
  阶梯（`8210.00 / 8210.00 / 8211.99 / 8211.99 / 8212.59 / 8212.59`），
  证明 2s 合并窗口按预期工作。
- **连接必须常驻**：eltdx 首次请求含 TCP + 7709 握手，实测 3.2s；握手完成后
  单次快照 0.05s。用 `threading.local` 让每个线程各持一条连接，无共享状态、
  无需加锁。若每次新建连接，前端 3s 轮询会退化成每次都 3 秒。

## 6. 前端

- 按钮 `#btn-amo-pred`（盘中量能）在 `#btn-amo`（盘后量能）**之前**，
  `#btn-margin`（两融余额）在 `#btn-amo` **之后** —— 顶栏顺序
  「盘中量能 → 盘后量能 → 两融余额」。本按钮**不进 `syncDataBtnState()` 的
  灰化名单** —— 期货页、任意周期都可点（面板内容是市场级数据，与当前标的无关）。
- 面板 `#energy-panel`：`position: fixed; left: 10px; bottom: 40px`，
  **白底**，刻意不跟随站内深色主题（照 App 截图复刻）。
- 文案口径：`沪深京｜实际量能 13261亿` —— 实际量能**只留整数亿**（`Math.round`，
  13261.46 → 13261），与「预测量能 13114亿」「缩量667亿」的整数口径一致；
  只有涨跌幅保留两位小数（`-4.79%`）。后端 `actual` 仍是两位小数的原始值，
  取整只发生在渲染层。
- 画布：y 轴按「曲线在 0 的哪一侧」选映射 —— 缩量时 0 贴顶、向下 4 等分到最小值
  （因此刻度形如 `-8.30% / -16.61% / -24.91% / -33.22%`）；放量时镜像成 0 贴底、
  向上 4 等分到峰值、刻度带 `+` 号；跨 0 时按整段 4 等分。0 轴蓝色实线 +
  「昨日|总量能」图例（0 轴在顶贴其下、在底则翻到其上），缩量绿 `#0aa53c`、
  增量红 `#e33b3b`。
- **曲线末端指示点**（`#energy-dot`）：钉在曲线最后一点上（与曲线同用 `xOf/yOf` 算坐标）。
  **平时完全不可见**，只有「这一轮真拿到新数据、曲线被重画了」才闪一次 —— 实心点 5px
  `#f5222d` 亮住前半程再淡出，外圈 16px 径向渐变换边扩散边淡出
  （`.en-dot.flash::before` / `.en-dot.flash::after` + `@keyframes en-dot-core` /
  `en-dot-pulse`，900ms）。它只表示「刚刷新」，**不跟红/绿趋势色走**（放量态补一圈
  1.5px 白描边，免得糊在红线上）。

  「有没有新数据」按指纹判：`actual | points.length | 末点值` 三样任一变化才算新；
  相同就连 `.flash` 一起摘掉。因此后端 2s TTL 把两次轮询合并成同一份数据、午休或
  收盘行情静止这些情况都不会闪，用户不会误以为一直在刷新。关闭面板时把指纹清成
  `null`，重开必定按最新数据重画一次、该闪照闪。

  尺寸与素材不是估的，是从截图反解的（截图整卡 1080px = 360dp@3x ⇒ 1dp = 3px）：
  实心核心直径 ≈12px ⇒ 4dp；光圈外径 ≈42px ⇒ 14dp；本面板 `plotW` 348 对截图 300，
  放大 1.16 倍 ⇒ 5px / 16px。径向透明度剖面（以绿通道反解 alpha，`a=(255-G)/(255-34)`）：

  | r（dp） | 1.0 | 2.3 | 2.7 | 3.1 | 4.0 | 5.0 | 5.8 | 6.6 | 7.3 | 8.1 |
  |---|---|---|---|---|---|---|---|---|---|---|
  | 截图 | 1.00 | 0.77 | 0.48 | 0.25 | 0.21 | 0.25 | 0.24 | 0.17 | 0.10 | 0.04 |

  即「内圈实心 → 一段 ≈0.24 的平台 → 线性收敛到 0」，所以必须用 `radial-gradient`
  而不是 `box-shadow`（后者只有高斯衰减、没有平台，且外沿有硬边感）。
  渐变半径写 `circle closest-side`：默认的 `farthest-corner` 会把 taper 甩到元素框外、
  再被 `border-radius:50%` 切出一道可见的圆圈边。

  用 CSS 动画而不是 canvas 逐帧重绘：为闪一个点重画整条曲线不值，也省掉
  `requestAnimationFrame` 的生命周期管理（面板关闭/切页都不用手动收尾）。
  动画默认 `fill-mode: none`，末帧 opacity 0 与基础态一致，播完即不可见，不需要
  JS 定时摘 class。重播靠「摘 `.flash` → `void offsetWidth` 强制重排 → 再加 `.flash`」，
  否则 class 一直在，浏览器认为没变化、第二次刷新不动。
