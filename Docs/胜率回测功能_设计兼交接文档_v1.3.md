### 0.4 术语与易混点（改代码前必读）

| 术语 | 含义 | 易混点 |
|---|---|---|
| **A 分量** | 结构止损距离 = \|入场价 − 终结笔端点分型极值\| | 不是"入场到最近低点的距离"，取的是 **`bsp.bi.get_end_klu()`** 的高低 |
| **B 分量** | 波动率止损距离 = `atr_sl_multiple × ATR(14)` | 默认 2.0 × ATR |
| **R** | 初始风险距离 = `max(A, B)`，取大不是二选一 | 出场所有阈值都以 R 为单位 |
| **L1/L2/L3** | 分层出场：L1 结构 R、L2 ATR、L3 保本+跟踪 | **没有"固定止盈单"**（TP 已删） |
| **首见态 / 最终态** | 信号第一次出现的那一帧 / 全部数据跑完后的状态 | 回测必须冻结**首见态**（§2.3） |
| **达标 vs 触发** | 达标读**根内有利极值**（high/low）；触发读**收盘价 close** | 两层口径不同是设计，不许"顺手统一" |
| **视口 vs 加载序列** | 视口 = 前端可见 233 根（`VIEW_COUNT`）；加载序列 = 后端 `records`（d=500 根等） | **回测用加载序列，不用视口**（§4.4）。两者解耦，混用会丢样本 |
| **未来函数 vs 回测评估** | 未来函数 = 用当时不可知信息**生成信号/决定入场**；回测评估 = 用后续走势**评估已冻结的信号** | 后者**不是**未来函数。v1.1 曾把两者混为一谈（R7） |
| **PRE vs POST 过滤** | PRE = 信号**进状态机之前**过滤（`Engine.py:924`）；POST = 全跑完再剔除成交（`TradeStats.py:146`） | 两态机下**不等价**。回测必须 PRE。本样本实测一致属巧合（§4.7.3） |
| **未平仓 vs 强行结算** | 未平仓 = 到 R 仍未触发任何出场 ⇒ **不计入盈亏、不进分母**；强行结算 = 按 R 收盘价算一笔盈亏 | 后者是凭空造盈亏，**禁止**（§4.5 R9） |
| **方向拆分 vs 类型拆分** | 方向 = 做多/做空；类型 = 0/1/2/3 类 | **方向降为可选下钻**（§4.6b）；**类型拆分必须保留**（§5.7 结论 3）。两件事别一起砍 |

**判据是"策略是否对称"，不是"样本量是否对称"。** 我 v1.2 拿"10 买 / 1 卖 ⇒ 做空会被稀释"当理由，是把样本量问题误当成口径问题。查证后：

### 4.7.2 放行判据：照抄，不许自造

```
filter 为 None                    → 全部放行
否则 按 type2str() 的逗号串拆段   → 任一段显式为 True 即放行
```

- 引擎侧实现：`Trading/Engine/Engine.py:989-1013` `_bsp_type_allowed`
- 统计侧实现：`Trading/Infra/TradeStats.py:146-176` `filter_trades_by_bsp_type`（docstring 明写"刻意与 `_bsp_type_allowed` 完全一致"）
- `type2str()` = `",".join(x.value for x in self.type)`（`BuySellPoint/BS_Point.py:41-42`）⇒ 同一右肩可合并出多类型，如 `"1,11"`。

### 4.7.3 ★ 落点必须是「事前过滤信号」，不是「事后过滤成交」

这是本节最关键的一条。两种落点在**独立逐信号**口径下等价，但在**两态状态机**下**不等价**：

| 落点 | 位置 | 被过滤类型的信号 | 后果 |
|---|---|---|---|
| **PRE 事前过滤（必须）** | 信号进入状态机**之前**，照抄 `Engine.py:924`（在 `_decide_action` 之前 `return`） | **根本不出现**，也不占用持仓期 | 被放行类型在同期可自由开仓 |
| POST 事后过滤 | 全跑一遍，再从统计里剔除不允许类型的成交（`TradeStats.py:146` 的落点） | 仍会开仓、仍占用持仓期 | 持仓期内出现的**被放行类型**信号被拒收，**这笔损失事后补不回来** |

⇒ **回测必须走 PRE**。理由不只是"与引擎同位置"，而是：选 POST 会让"取消勾选 3 类"这个动作**间接改变 0 类的结果**（因为 3 类空出来的持仓期本可让 0 类进场）——这正是用户无法预期的静默耦合。

**实测（本样本）**：PRE 与 POST 结果**完全相同**（放行 `0` / 放行 `3` 两种配置下都是 3 笔、逐字段一致）。原因是本样本里 **0 类与 3 类在时间上完全不重叠**（所有 3 类信号 idx ≤ 336，所有 0 类信号 idx ≥ 561），被过滤类型的持仓窗口内**没有出现过**被放行类型的信号（重叠次数 = 0）。

> ⚠️ **本样本区分不了 ≠ 两者等价。** 这是单样本的巧合（该股 2023 年后就没出过 3 类点）。全市场下 0/1/2/3 类信号交错是常态，届时 PRE/POST 必然分叉。**所以按 PRE 实现，不要因为"实测一样"就选更好写的 POST。**

### 4.7.4 一个已知的口径缺口（既有设计，回测须沿用，不要"修好"）

`BSP_TYPE` 枚举有 **10 个值**（`Common/CEnum.py:126-136`）：`0 / 1 / 2 / 3 / 11 / 11p / 22 / 22s / 33a / 33b`，而勾选框只有 **4 个**（`0/1/2/3`）。

- 默认配置 `bs_type = "0,1,2,3"`（`ChanConfig.py:295`）⇒ 只产出 0/1/2/3，**与勾选框恰好对齐**，本样本实测类型只有 `0` 与 `3`。
- 若用户把 `bs_type` 改成含 `11 / 11p / 22 / 22s / 33a / 33b`，这些类型**不在 `BSP_TYPE_CHOICES` 内** ⇒ 一旦过滤被设置（非 None），它们**一律被忽略**，哪怕勾了"1"（`11` 是"原 1 类·趋势背驰"）。
- `Engine.py:994-997` 的 docstring 明写这是**刻意行为**。

⇒ **回测照抄同一判据，不要自造 `11 → 1` 的映射**。否则回测与实盘自动下单对同一勾选给出不同结果 —— 那才是真 Bug。若将来要支持细分类型，应改 `BSP_TYPE_CHOICES`（连带前端复选框），**三处一起改**，不能只改回测。

### 4.7.5 与「口径标识」的关系

统计面板已有 `statsCaliberHtml`（`app.js:4962-4976`），会显示 `bsp_types_included`；未启用过滤时显示"（未启用买卖点类型过滤）"。**回测面板必须同款显示当前生效的勾选**，否则用户改了勾选却不知道数字为什么变。

### 5.2 核心循环：一次遍历同时做完三件事

不再拆成"先采集、再评估"两步 —— 拆开就会被迫引入"最终态 vs 首见态"的问题。合在一起则问题消失：

```python
pol = LayeredExitPolicy(STOCK_EXIT_PARAMS)   # ★ 全程唯一实例，ATR 从头连续累积
state = FLAT
for snap in chan.step_load():                # 逐根流式推进
    kl = snap[0]
    bar = Bar.from_klu(kl[-1])               # 刚闭合的这根

    # ① 先结算已有持仓（用刚闭合这根的 close 判 L1-L3）
    #    —— 顺序照抄 Trading/Engine/Engine.py:39「每根 K 线的处理顺序」
    if state == IN_TRADE:
        pol.on_bar(bar, inst)
        chk = pol.check(pos, bar, inst)
        if chk is not None:
            if chk.plan is not None:
                pos.exit_plan = chk.plan     # 先抬价（进保本/跟踪）
            if not chk.only_update:
                record(exit_date=bar.date, fill=chk.fill_price,
                       reason=chk.reason, r_mult=(fill-entry)*side/R)
                state = FLAT                # ★ T+0：当根即平，不等次日
                continue                    # 平仓当根不再开新仓（Q-D）

    # ② 再看本帧新出现的信号（只有 FLAT 态接收 —— 你 ⑸ 的规则）
    if state == FLAT:
        for bsp in new_bsp_this_frame(kl):
            # ★ 类型过滤：事前过滤，照抄 Engine._bsp_type_allowed（§4.7.3）
            #   未放行 ⇒ 不进状态机、不占持仓期，不是事后剔除成交
            if not bsp_type_allowed(bsp.type2str()): continue
            sig  = Signal.from_bsp(bsp_dict, symbol, freq)
            entry = bsp.klu.close                 # 入场价 = 信号K线收盘价
            plan  = pol.plan(sig, entry, inst)    # ★ 此刻读到的分型 = 首见态
            pos   = Position(..., exit_plan=plan)
            state = IN_TRADE
            break                                 # 一帧最多开一笔
```

**三个"顺序错了结果就错了"的点**：

1. **① 在 ② 之前** ⇒ 自动满足"入场那根不判出场"（`App/AppTPSL.py:156` 步 9 的同口径），无需额外判断。
2. **`pol` 全程唯一** ⇒ ATR 从头连续累积，不需要每次入场前预热 60 根。
   ⚠️ 这与 `AppTPSL` 的做法不同（后者每次 HTTP 请求新建 `pol` 并预热 60 根）。两者在开局前 ~60 根内 ATR 会有微小差异，之后收敛。若要与右键推演**逐笔对账**，需加开关走"每次预热 60 根"模式（Q-E）。
3. **冻结发生在 `pol.plan()` 这一行** ⇒ 分型是"信号首次出现那一帧"的值，天然是首见态（§2.6）。
4. **类型过滤在 `state == FLAT` 之内、且在开仓之前**（§4.7.3）。放在这里才等于 `Engine.py:924` 的位置；放在开仓之后就退化成事后过滤，会引入"被过滤类型间接影响被放行类型"的静默耦合。
   （注：v1.2 此处曾有 `if not bsp.is_buy: continue  # 只做多`，已随 Q10 作废删除 —— 现双向处理，买点做多、卖点做空，§4.6。）

实测成本：**1393 帧 / 2.27 秒**（sz002190 日线，含逐帧快照）。单标的单周期 ⇒ 前端按钮**同步返回即可**。

### 5.3 你的 ⑸：两态状态机规格（采纳，钉死）

| 项 | 规格 | 依据 |
|---|---|---|
| 状态集 | `FLAT`（空仓）⇄ `IN_TRADE`（持仓），**只有两个** | 你的 ⑸；股票无锁仓，不需要 `Trading/Engine` 的 LOCKED 第三态 |
| `FLAT + 买点` | → 开仓，`IN_TRADE` | 你的"买入后" |
| `IN_TRADE + 任何新信号` | → **拒收** | 你的"这一交易没结束前，不再处理新的买卖点信号" |
| `IN_TRADE + 出场触发` | → 平仓，回 `FLAT`，**当根成交** | 你的"按 T+0 直接处理" |
| `FLAT + 卖点` | → **开空仓**（v1.2 改：双向） | 你的第三轮 ⑵ + §4.6（`Side.SHORT` 原生支持） |
| `IN_TRADE(多) + 卖点` | → **拒收**（默认）或**反手**（Q13 待拍板） | 你的第二轮 ⑸ 原话是拒收。注：拒收会压低做空侧笔数，但**这不影响口径正确性**（§4.6b：主口径合并，笔数用标签披露即可） |
| 入场价 | 信号 K 线 **收盘价** | `App/AppTPSL.py:135-137` 硬校验 |
| 出场价 | 触发那根的 **`chk.fill_price`**（收盘价口径） | 触发只读 close（§3.4） |
| T+1 | **不建模**（股票按 T+0、按平今处理） | 你的 ⑸ |

**与 `Trading/Engine/Engine.py` 的关系**：同构但**不复用**。

- 同构：Engine 的 `EngineState` 是 `IDLE / OPENING / IN_TRADE / EXITING`（`:146-155`），其中 `OPENING/EXITING` 是"下单到成交之间"的瞬态 —— 回测里撮合是瞬时的，这两个态退化，**剩下的就是 IDLE ⇄ IN_TRADE 两态**，与你说的完全一致。
- 不复用：Engine 的账户三态 `FLAT/RUNNING/LOCKED`（`:8-13`）里 **LOCKED（锁仓）是期货专有**（多空互锁），股票不存在；Engine 还耦合了 `PositionBook`、对账、资金闸门、CTP 报文。回测不需要这些 ⇒ **`Backtest/state.py` 自己写一个约 30 行的两态机**，比复用 Engine 更干净。

> 注意 Engine 判据是"净敞口"，而回测里 volume 恒为 1、无锁仓 ⇒ 净敞口判据退化为"有无持仓"，两态等价。

## §8 风险与边界

1. **样本边界**：§2 所有数字来自 **1 只票 / 1 个级别 / 11 个信号**。3 个漂移全是 3 类点，8 个 0 类点未观测漂移但不等于免疫。**漂移巡检（P4）必须常驻**，不能"测过一次就放心"。
1b. **信号簇是比漂移更普遍的风险**（§2.7）：连续右肩簇在单样本 8 个 0 类信号里就占了 5 个（3 簇）。**任何按"信号数"计数的统计都不可信**，必须按状态机去重后的交易笔数。这条适用于本文之外的所有现有统计（含作者机器上报的 9,677→10,402）。
1c. **去重后样本量会骤降**：本样本 11 信号 → 状态机去重后仅 **5 笔买点交易**（155/235/561/1098/1120），0 类仅 3 笔。**单标的回测没有统计意义**，结论必须来自多标的汇总 —— 这是 P3（全市场）不可省略的理由。
2. **前复权价 ≠ 真实成交价**（`App/AppTPSL.py:11-12` 已注明）：股票 K 线是前复权价，回测基于它，与真实成交有差。这是性质不是缺陷，但报告里要写明。
3. **停牌 / 涨跌停未建模**：保护价可能不可成交。同上，注明即可，不要试图建模（会引入更多假设）。
4. **回测不得复用实时分析的缓存与锁**：这是你"不碰 App/"的核心理由，设计上通过"Backtest 直接调 Chan + DataAPI，不经过 App 层"保证。
5. **不要为了回测改缠论核心**：回测只消费信号，不参与信号生成。
