# 大文档原子多点改稿

目标：在一个**很大、很重要、会被反复改**的文档上做散点修改，
并且让「改坏了」的可能性为零 —— 宁可整批不改，也不要改到一半。

## 适用与不适用

- **适用**：`>500` 行的 `.md` / `.txt`，需要 **3 处以上分散**修改。
- **不适用**：单点小改（直接用 Edit 工具）；结构化文档（`.docx`/`.xlsx` 走专用技能）。

## 铁律

1. **绝不一处一处改**。写一个脚本，把全部 `(old, new)` 放进列表，**先全量预检、再原子落盘**。
2. **预检必须断言 `count == 1`**。任何一处 `!= 1` → 打印完整报告并 **ABORT，一个字节都不写**。
   这条救过一次：错字锚点被当场拦住，没把半成品写进用户文档。
3. **锚点用真实中文字符，不要手写 `\uXXXX` 转义**。错一个码点就 `hits=0`
   （血泪：`\u6491`=撑 vs `\u6492`=撤；`\u5151`=兑 vs `\u515c`=兜）。
4. **锚点要"短到不含易错字，又长到全局唯一"**。别把整行当锚点（标点/引号风格易变），
   也别只用一个词（会命中多处）。含引号的行尤其危险 —— **先探测引号风格**。
5. **先探测文档元信息**：BOM、CRLF/LF、行数、字节数、引号风格
   （`text.count("\u201c")` vs `text.count('"')`）、现有最大编号。
6. **保留原始换行与 BOM**：`utf-8-sig` 读，回写时若原来有 BOM 再加回去；
   不要把 CRLF 文档改成 LF（会污染整份 diff）。

## 编号分配：先查再定

写新决策 / 风险 / 问题 / 测试编号前，**先正则扫描已有最大编号**
（`\bD(\d+)\b` / `\bR(\d+)\b` / `\bQ(\d+)\b` / `\bp(\d+)\b` …），不要凭印象。
同时确认新编号的**引用点**是否也要同步 —— 常见漏网：索引表、「最高优先级」清单、
交接清单、"剩余未决问题"汇总、变更历史。

## 插入位置的三种典型坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **插表格行落在空行后** | 表格被打断，新行变成独立段落 | 把**上一行末尾的换行**一起纳入锚点：`…自证 \|\n\n\| p42` → `…自证 \|\n\| p42` |
| **插整节后出现连续空行** | `…\n\n\n## 6. 下一节` | 锚定到 `## 6. 下一节标题`，新节文本末尾自带 `---\n` |
| **交叉引用只改了一处** | 读者按图索骥找不到新节 | grep 列出该编号/标题的**全部**引用点，逐条决定是否同步 |

## 必跑的收尾校验（脚本化，输出写 `.txt` 再 `Read`）

1. **锚点报告**：每处 `hits=`，全 1 才落盘。
2. **落盘报告**：`BEFORE / AFTER bytes & lines`，以及每个新标记的最终 hits。
3. **表格完整性**：列出所有新增表格行，断言其**上一行以 `|` 开头**；
   再全局扫「上一行为空行 且 本行以 `| ` 开头 且 含 `**`」的疑似孤儿行。
   **对照旧版时要比「内容集合」而不是「行号区间」**：把每个列数不一致的表格块取
   `set(tuple(block_lines))`，跑一次 `新集合 - 旧集合` 与 `旧集合 - 新集合`。
   只比行号会被插入行的位移误判成"新增异常"（实测：插了 23 行，两处**既有**异常块
   行号各 +23，被误报为"本轮引入"）。顺带在报告里打印该既有异常的**成因行**
   （通常是单元格里含裸 `|`，如 `` `OrderIntent.LOCK|UNLOCK` ``、`` `open|close` ``），
   以证明它不是结构错误。
4. **结构定位**：打印每个新增标题的**实际行号**，确认落点符合预期。
5. **可选**：改动前后各节标题列表 diff 一遍，确认没误删小节。

## 口径反转（改结论）时的额外一步

用户反问 / 改主意，把文档里**已写定的结论**翻过来（例：方案从 **A** 改为 **A′**）时，
改动量远大于"重写那一节"。**除重写主节外，必须再全局 grep 旧结论的标签词**，
把散落各处的引用点一次性同步 —— 否则同一份文档里新旧口径并存。

必做：
1. **列出旧口径的标签词**（方案代号 `A（推荐）`、开关名 `instrument_autofetch`、
   取值 `quote_first` / `config_first`）、以及旧措辞片段（`建议 A +`、`待拍板`）。
2. **全局 `count` 一遍**，作为收尾校验的**残留检查（全部应为 0）**。
   —— 残留 0 才算真的反转干净。
3. **同节相邻项要一起审**：改完主节后，同章节里"顺带提到旧方案"的小项会变成过时表述。
   实测：主节改完后，同节的落地清单第 8 项仍写"作为 **A 案**无行情时的兜底"，
   需追加一次替换（第 13 处，靠第 2 步的 grep 抓到）。
4. **历史记录不要改**：变更历史表里"vX.Y 做了 A/B/C 三案"属于**事实陈述**，
   保留原样；只在表尾新增一行说明本次反转。
5. **旧版本留备份**：落盘前 `copy2` 出 `.bak_v<旧版本号>`，便于 diff 对照与回退。
   ⚠️ **备份要放在交付范围之外**（被改文档若在交付包里，放同目录的 `.bak` 会被当成新增文件 —— 见坑 7）。

### 残留检查的关键词要用「精确锚点」

残留检查（`count == 0`）的候选词**必须足够长、带上下文**，否则会被**同名前缀的其它标识符污染**，
产出假阳性、让人误判"没改干净"。

- 实测：查 `prefer` 想确认"宽容档已删"，结果命中了**另一个毫不相干的开关**
  `prefer_lock_over_close_today`（平今开关 D6）共 4 处 → 全被报成 `!!`。
- 正确做法：查**完整标识符或带引号的字面量**（`` `instrument_fetch_policy` ``、
  `` `strict` / `prefer` / `off` `` 这种整串档位列表），而不是裸词。
- 报告里**每条命中都打印原文行**并标注"是否为预期语义"（如必须含 `已删除` / `不设宽容档`），
  让人一眼判断而不是只看计数。

## 先判定「改动属于哪一层」

用户可能只授权其中一层，越界改另一层会被要求回退。

| 层 | 内容 | 落点 |
|---|---|---|
| **决策 / 规格层** | 选哪个方案、开关保留哪几档、默认值是什么 | **只改文档**（ADR / 未决问题 / 落地清单的表） |
| **实施层** | 写代码、加字段、加测试 | 属于某个 Phase |

- 实测：用户问「降级档只留 `off`、删掉 `prefer`，**这个属于 Phase 8 吗？**」→ 答案是**不属于**：
  开关的**代码实体**要到 Phase 8 才创建，本轮只是把规格定下来 → **只改文档，一行代码不碰**。
- 判定话术：问自己「这个改动会新增/修改**任何可执行文件**吗？」不会 → 决策层。
- 若用户说「XX 我以后再做」，**把该 Phase 的状态留在原样**（如 `⬜ 未开始`），
  并在回复里明确"本轮未启动 Phase N"。

## 压缩类改稿：删的是"装饰"，元信息要迁到附录（2026-09-22 实测）

用户说「这些日期/注记删掉能省字数」时，**先分清哪些是装饰、哪些是溯源信息**，再动刀：

1. **可删**：正文里重复的日期括注（`（09-17 拍板）`）、与规则语义无关的版本尾注 —— 删后
   规则仍自洽，只是"什么时候定的"不再写在索引里。
2. **不可删**：括注里**含文件名 / 节号指针**的（`（09-17 瘦身；历史全文 → memory-xxx.full-2026-09-17.md）`）——
   删了会丢指针，是净损失。
3. **迁出而非丢弃**：把日期/出处汇总成一张台账表，写进**不常驻上下文的子文件**（附录 / `memory-*.md`），
   在索引里留**一行 ≤30 字符的指针**。净省字数，可追溯性不减。
4. **未确认的日期写 `—`**，不要为了表格好看编一个（同日：3/4/5 三条只标"实测 / 见子文件"，
   1 与 6 的日期取自子文件既有记载）。
5. **删任何一条注记前，先确认它有第二处载体**（台账另一行 / 子文件头部 / 交叉引用）——
   只有一处承载的日期删掉就是永久丢失。同日实测：标题「（2026-09-15 拆分）」删得掉，是因为
   台账第 7 行与 7 个子文件头部都写了同一日期，删的纯属冗余。
6. 收尾：**残留检查 token 用带括注的整串**（`（09-17 拍板）`，不要裸 `拍板` —— 指路行里就有"拍板"二字，
   裸词会假阳性），并断言索引里的规则正文关键词一个都没丢。

## 本环境实操要点

- **`Read` 报「File does not exist」但同一文件其它 offset 能读到** → 大概率**路径错了**，
  工具做了模糊匹配。先 `Glob` 确认真实路径。
  （实测：用户给的短路径不存在，真实文件在子目录 `chan.py/Docs/` 下。）
- **PowerShell 的 `[System.IO.File]::WriteAllLines` 会静默不落盘**（exit 0 但文件不存在）。
  输出一律**让 Python 脚本自己写 `.txt`**，再用 `Read` 读回。
- Python 用托管运行时：`C:\Users\river\.workbuddy\binaries\python\envs\default\Scripts\python.exe`。
- 脚本本身用 `Write` 工具写（UTF-8，必成功）；**不要把长脚本塞进 PowerShell here-string**。
- 脚本放沙盒：`<workspace>/sandbox/`，不要污染用户目录。

## 坑（2026-09-14 实测新增，三条都真踩到）

### 坑 1（最危险）：子串替换会改变行数 —— 整行替换绝不能沿用预检的旧行号

危险写法：先跑完所有子串替换（某条锚点插入了 100+ 行），再按**预检时算出的行索引**去
`nl_list[idx] = newline` —— 行号早已漂移，结果是**覆盖掉一批无关行**，
而预检报告**全绿**、完全看不出异常。

**正确顺序**：① 先做全部子串替换；② 再在**替换后的文本**上，用行首前缀**重新定位**每一行；
③ 定位数 `!= 1` 就**中止且不写盘**（落盘期定位失败也要 abort）。

**怎么被发现的**：脚本自带的"残留检查"报出"旧口径仍存在"，同时 grep 结果显示
**同一事实出现了两份** —— 两个副本正是行号错位的指纹。
**所以收尾的残留检查不是可选项，它是这类错位的唯一探测器。**

推论：**凡是"预检在文本 A 上算位置、落盘在文本 B 上写位置"的脚本，无论看起来多合理，都要怀疑一遍。**

### 坑 2：并行发多个 `Edit` 改**同一个**文件会丢改动

本轮同时发两个 Edit（一个改预检段、一个改落盘段），两者都返回 "Successfully edited"，
但**后写覆盖前写**，第一个改动实际丢失 —— 直到重跑脚本报 `TypeError` 才发现。
**改同一文件必须串行；只有改不同文件才能并行。**改完先 `Read` 确认真的落盘，别只信返回文案。

### 坑 3：文档里同一事实常有多个副本 —— 别一刀切全改

同一事实会散在**正文表 / 汇总表 / 附录证据索引 / 变更历史**里。
实测一份 1811 行的文档中，`max_order_volume`、`42/42 通过`、`48/49 全绿`、`p42 ⬜` 各出现 2~4 次。

处置原则：
- **现状口径** → 必须改；
- **历史记录**（变更历史表、A/B 实测表、"vX.Y 当时 42/42"）→ **保留原样 + 加一行注**，
  否则等于伪造记录。

判据一句话：**这句描述的是"现在是什么"，还是"当时发生了什么"？**

做法：先 `grep` 出全部副本 → 建"残留检查"清单（旧口径 token 期望 `count == 0`）
→ 落盘后逐条验证 → 对**故意保留**的历史 token，把期望值写成 `1` 而不是 `0`，并在报告里注明原因。

### 坑 4：优先「全唯一子串替换」，能不按行号定位就不按

坑 1 的**根治**办法不是"把行号更新对"，而是**取消按行号定位**：每处改动都表达成
`old`（唯一子串，带足够上下文）→ `new` 的纯替换，落盘就是 `t.replace(old, new, 1)`。

实测同一份 1800+ 行文档的 **12 处改动全部可用唯一子串表达**（含跨 4 行的段落、整张表格行），
于是"行号错位"这一整类风险**直接消失** —— 预检期只断言 `t.count(old) == 1`，任一不符整体 abort。

**代价**：锚点要写长一点（带上下文的整句 / 跨行段落），但比事后查错位便宜得多。
**例外**：需要按"行首前缀"定位的场合（同一行内容在文中出现多次且无法用上下文区分）——
这时才退回行号法，并严格照坑 1 的顺序（先子串、后在**替换后**的文本上重新定位）。

### 坑 5：**别把"临时状态的产物行号"写进文档**（2026-09-14 实测）

做注入式反测（往某个源文件追加一段真违规代码，验证护栏会报红）时，护栏通常会**指名文件与行号**。
**那个行号只在注入状态下成立** —— 把它原样写进文档，正常状态文件行数不同，
就会**触发文档自带的"行号越界"检查**（本轮真踩到：`InstrumentSpec.py:453`，而该文件正常只有 451 行）。

**规则**：记录这类证据时**只写文件路径 + 注入方式**（如"注入点 = 文件末尾新增的函数"），
或明确标注"（注入态行号）"。同理适用于：临时复现脚本的报错行号、中间产物的行数/字节数。

**顺带一条自检**：改动完了，把文档里**新增的** `文件.py:行号` 全部过一遍
"该行号 ≤ 目标文件实际行数"—— 一条命令即可，比事后被人发现便宜。

**还有一条**：文档类项目常有**自带的核验脚本**（本轮 `verify_doc.py` 的 E 段就有一组
token 断言）。**刷新文档口径时，要顺手扫一遍这些脚本里的 token 是否过期**
（如把 `"49 绿 / 2 红"` 改为 `"51/51 全绿"`）—— 否则会留下一批"下次跑必然误报"的脚本，
比没有脚本更误导。

### 坑 6：**新增文本（`new`）里的 ASCII 双引号会截断 Python 字符串字面量**（2026-09-14 实测，语法错）

改稿脚本本质是"`old` → `new` 的 Python 字符串"，而写中文文案时打引号是本能。
一旦在**双引号字符串**里写 `"今仓"` / `"墙钟依赖"` / `"2-3 个 commit"`：

```python
"- 三字段没有从 Config.py 里"消失"，而是下沉到新子类 `ExitPolicyParams`\n"   # ← 字符串在此截断
```

症状：`py_compile` / 直接跑都报 **SyntaxError: unterminated string literal**，
且报错行**指向看起来完全正常的一行**（因为截断点在中部）。

规则：
- **脚本里的中文文案引号一律用 `「」`**（目标文档本来就用 `「」` 时最省事，风格也统一）；
- 或整段改用三引号 —— 但三引号可能与内容里的三引号撞，**首选 `「」`**；
- 落盘前先 `py_compile` 一遍脚本，2 秒成本。

> 与本技能上半部分"锚点先探测引号风格"的**分工**：探测引号风格管的是 **`old`（锚点，取自原文档）**；
> 本条管的是 **`new`（你要写进去的新文本）**。两者都会炸，但炸的位置和修法不同。

### 坑 7：**`.bak` 备份不能留在被交付的仓库树里**（2026-09-16 实测，会污染交付包）

本技能「口径反转」一节第 5 条要求落盘前 `copy2` 出 `.bak_v<旧版本号>`。若**被改的文档本身
在交付范围里**（`Docs/*.md` 是仓库内文档、要按目录层级打进 zip 覆盖给用户），把备份写在
**同目录**（`Docs/xxx.md.bak_v...`）会被"改动文件全集"扫描当成**新增文件**——它既可能被打进
zip，又会让"新增文件清单"多出一条噪声。

规则：
- 备份一律写到**交付区之外**（本环境 = `sandbox/_tmp/`），文件名保留原标题便于回溯；
- 落盘后立刻 `find <repo> -name '*.bak*'` 自查一次；
- 打包脚本里把 `*.bak` 加进**排除清单**，并让脚本**对"待打包清单含排除项"直接报错退出**
  （比事后人工核对可靠）。

> 同族问题（同一教训的另一面）：**实验/取证脚本**（`verify_*.py`、`changed_files.py`、`patch_doc*.py`）
> 也要放在 `_tmp/`、不要放仓库树，且默认不进包。

### 坑 8：**改稿脚本自身写在 shell 双引号里时，`\\\\0` 会被吃掉一层反斜杠 → 写出真实 NUL 字节**

用 `python -c "..."` 传脚本体时，bash 双引号把 `\\\\0` 折成 `\0`，Python 再解释成**NUL 字符**并写进
目标文件 → 文件变成 "binary"、`grep` 直接罢工（报 `binary file matches`）。

规则：
- 改稿脚本一律用 `Write` 工具写成 `.py` 文件再执行，**不要塞进 `python -c`**（本技能上半部分
  已有同样建议，这里给出"不遵守会怎样"的具体症状）；
- 万不得已要提到 NUL 时，**写成 `NUL` 字面词**，别写转义序列；
- 收尾自查：`open(p,'rb').read().count(b'\x00')` 必须为 0。

### 坑 9：**整节删除要用「起止锚点 + 切片」，且终点锚点可能被后续替换抢先改掉**（2026-09-22 实测）

删一整节（几十行）时**不要手打整块文本当 `old`** —— 几百字符里错一个标点就 `hits=0`，还白烧 token。
做法：`i = t.index(start); j = t.index(end); t = t[:i] + t[j:]`，两个锚点各断言 `count == 1` 且 `i < j`，
起止都选在**目标块外的稳定行首**（起点 = 要删小节的首行，终点 = **下一节的标题行首**）。
切片边界取"下一节标题"的好处：中间的 `</ul>` / 结尾空行会被一并吃掉，天然不留孤儿空行。

⚠️ **顺序陷阱**：同一轮里既删「§12.1 / §12.2」又要把它后面的「§12.3」重编号成「§12.1」时，
终点锚点 `### 12.3 B4-1` 会在替换后**消失**（变成 `### 12.1 B4-1`）→ 脚本里必须
**先做全部区间删除、再做全部子串替换**。反之则 `index(end)` 抛异常或定位到错误位置。
（本轮同时踩到这条：8 处删除锚点 + 19 处替换锚点，靠"先删后替"一次通过。）

### 坑 10：锚点要避开引号 —— `.md` 与 `.html` 对同一句话的引号风格常常不同（2026-09-22 实测）

实测同一份文档的两个版本：`.md` 用 ASCII `"…"`，`.html` 用 `「…」` —— 同一句话两版引号不同，
拿整句当锚点会一边命中、另一边 `hits=0`。

- **处置**：锚点只取**不含引号的那一段**（如 `证据怎么引 / 描述怎么写 / 交付面怎么记`），
  引号在两端、不在子串里 → 两种风格都能命中，替换时把引号部分留给原文不动。
- **探测**：三个计数一起打 —— `t.count("\u201c")` / `t.count('"')` / `t.count("「")`，
  一眼看出该文件用哪套、有没有混用。
- 顺带：`.md` 与 `.html` 即使讲同一件事，措辞也可能微差（`>` 引用块 vs `<div class="callout">`、
  `**粗体**` vs `<b>`），**别指望一份锚点两用** —— 两套 operation 列表分开写、各自断言。

### 坑 11：长文档局部渲染核验 —— 无 Pillow 时用「iframe 负偏移」截任意区段（2026-09-22 实测）

改完尾部章节要**看渲染**确认无破版，但 `--window-size=900,20000` 的整页图缩略后看不清细节，
而沙盒 Python 往往没有 Pillow（`import PIL` 直接失败）。两步解决：

1. **量高度**：探针页放 `<iframe id="f" src="<文档 as_uri()>" style="width:900px;height:120px;border:0">`，
   `window.addEventListener("load", …)` 里把 `f.contentDocument.documentElement.scrollHeight` 写进页面上的大字，
   用 `--window-size=900,160 --allow-file-access-from-files` 截图 → 读出总高 `H`。
2. **切区段**：探针页改成 `<style>iframe{position:absolute;top:-TOPPX;width:900px;height:Hpx;border:0}</style>`，
   窗口 `900×(区段高)` 截图 → 得到的就是长文档中任意 `[TOPPX, TOPPX+区段高]` 的画面。
   区段位置按"节标题在源码里的行数占比 × H"估，一轮估偏了再调一次即可。

`--allow-file-access-from-files` 只有第 1 步（要读 iframe 文档高度）必需；第 2 步纯定位截图不需要它。

### 坑 12：**"版本成组锚点"最容易漏页脚**（2026-09-22 实测，本轮真漏了一次）

按需求方裁定删掉某几条结论时，改动面往往不止被删内容，还有一圈**元信息**：
`<title>` / 版本行 / 日期行 / 作者行 / 状态栏 / 章末页脚 —— 它们各自写着旧版本号与旧内容摘要。

- 本轮实测：md 5 处 + html 8 处锚点全部命中，**唯独漏了 html 页脚**（它物理上在被删的 §12 之后，
  不在我预设的锚点清单里），靠"grep 旧版本号"才发现。
- 因此收尾校验**必须同时 grep 两样东西**，缺一不可：
  1. **被删内容的标识**（章节号 / 条目编号）→ 逐处人工确认残留是否合理（版本沿革行里出现是合法的）；
  2. **旧版本号本身**（如 `v3.5`）→ 每一处的行首标签必须是「历史沿革」或已同步，页脚/`<title>` 不允许留旧号。
- 口诀：**删内容 → 顺手把"版本号所在的那一圈"也列成锚点**，特别是页脚（它离正文最远、最没存在感）。

## 引用的漂移：行号 / 路径（2026-09-14 实测）

文档里的 `文件.py:行号` 会在**别的批次改动同一个文件**后整体后移。
实测：一期文档 75 处行号引用，二期在 `Engine.py`（≈1987 行）/ `Broker/SimNow.py`（≈1883 行）
插入代码后，**约 20 处现状引用失准**，个别偏移数百行（`:811` → `:1230`）。

**处置三件套**（低风险优先，别一上来就逐条重写行号）：

1. **加声明**：在文档开头写清两类引用的性质 ——
   ①**现状引用**（锚定某基线，随后续改动漂移 → **以函数名/标识符定位为准**）；
   ②**历史快照**（记录"当时长什么样"，如"删掉 X 的过程" → **有意保留，不要按现状解读**）。
2. **关键证据双标注**：`` `Base.py:44-55` ``（改造前）→ 写成
   `` `Base.py:44-55`（⚠️ 改造前行号；现为 `:68-72`，且已三值化） ``。
3. **其余不逐条重定位**：每处都要先判"现状 vs 历史"，**判错反而把正确的历史记录改错、制造新的不一致**。
   列为可选精进项告知用户，比擅自全改更安全。

**自动排查脚本思路（本轮实测有效）**：
- `doc_scan.py`：① 文档引用的 `test_*.py` 与磁盘比对；② 文档引用的路径是否存在；③ 过期数字 token 扫描。
- `doc_reloc.py`：取文档行里的**反引号标识符**（如 `INTENT_TO_OFFSET`）到目标文件里 grep 真实行号，
  按"距旧行号最近"给建议 → 输出 `[OK]/[DRIFT]/[NOTOKEN]` 三分类，**只看 `DRIFT`**。
  ⚠️ 两个已知**误报源**：(a) 按 basename 索引文件会把同名 `__init__.py` 匹配错
  （`Risk/__init__.py:7` 被误报"越界"，实际文档是对的）→ 要用**路径别名表**限定；
  (b) 文件查找条件写错会误报"文件未找到"（`Trading/Broker/Base.py` 明明存在）。
  **凡脚本报的异常，先用 `grep`/`sed` 手工复核一条再信它。**
- 关键：`NOTOKEN` 多半是**历史引用**（描述已删代码），**不是错误，别去"修"它们**。
