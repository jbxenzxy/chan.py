# 前端展示字段契约改造 + 双层护栏

展示层改动的风险不高，但**极易回潮**：改动只写进交付说明 = 下次重构必然退回原样；
而"改对了"又很难自证 —— 你看到的截图可能只是那一份 fixture 恰好没带脏数据。

## 何时用 / 不用

**用**：用户对某个面板提出「显示什么 / 顺序 / 不显示什么」的明确诉求
（品种名 vs 合约名、删某行、字段改名、行序调整、去掉时间戳…）。
**不用**：纯逻辑/数值口径改动（走引擎验证那类技能）；纯 CSS 尺寸（走 `frontend-pixel-verify`）。

## 标准流程

### 1. 先确认"基线到底是哪一棵树"

别假设本地 == 远端。开干前用 md5 逐字节比对（本仓常见情况：本地就是远端某提交）：

```python
for rel in ["Frontend/app.js", "Frontend/index.html", "Test/run_all.py"]:
    print(rel, md5(local/rel) == md5(remote_worktree/rel))
```

比对结果决定**能不能整份覆盖交付**（本地无私改 → 可以；有私改 → 只给目标区块补丁）。
顺带能发现「上一轮的交付到底有没有落地」——本次就是这样发现远端缺了上一轮的前端实现。

### 2. 改动走「Python 补丁脚本 + 命中次数断言」，不要手改

CRLF 仓库 + 大文件，直接 Edit 多行块会失配（见 `~/.workbuddy/memory-env.md`）。
脚本骨架：

- 读 bytes → `decode` → `replace("\r\n","\n")` 得到规范文本
- **锚点取整行唯一串**（如 `// ③ 明细行`），替换前 `assert 该锚点出现次数 == 1`
- 替换区间用「锚点行 … 收尾行」定位，**块首要包含在替换区间内**（否则重复执行会多加一行）
- 写回时 `s.replace("\n","\r\n")`，并 `assert 裸 LF == 0`
- 每次替换后打印命中的 `hit()` 断言表，**全过才算成功**

> 幂等性自检：**连跑两遍**脚本，第二遍的 CRLF 总数必须与第一遍相同。

### 3. 双层护栏用例（新文件放 `Test/`，并在 `Test/run_all.py` 注册）

**静态层**（不需要浏览器，任何环境都跑）：
从渲染函数抽出区块 → 用正则取标签序列 `class="stats-label">([^<]+)</span>` → 断言序列 == 期望数组。
两个必须做的动作：

- `assert 区块长度 > N`（防正则只捞到半截，护栏静默失效）
- 禁用串在**区块内**判零命中，不是全文件 —— 同一符号在别处仍可能合法使用
  （本次 `exit_at` 在自动下单成交列表里仍然要用）

**真渲染层**（无头 Chrome；浏览器不在位降级 SKIP）：
起 `SimpleHTTPRequestHandler` + `page.route("**/api/**", …)` 打桩，然后**喂脏数据**：
把用户不想看到的东西**全部塞进响应里**（不要的合约名 / 时间戳 / 被删的分支数据），
再读真实 `innerHTML` 断言它们一个都没出现。

> 这一层才是真正的保证：静态层只证明"源码里没有那段拼接"，
> 真渲染+脏数据证明的是"后端发过来也不上屏"。**不要喂干净数据**，那等于没测。

**浏览器启动顺序**：本机 Chrome（`channel="chrome"`）优先 → 捆绑 chromium → ms-playwright 缓存。
本机捆绑 chromium 在 `close()` 时会挂住 Playwright driver，令用例收尾卡死。

### 4. 基线对照：证明失败项与自己无关

```bash
git worktree add --detach ../chanpy_base <同一提交>
# 在 base 上逐个复跑失败组件，收集 rc
# 关键：如果新用例是"护栏"，还要把它拷到 base 上跑 → 必须 FAIL（否则恒绿、拦不住回退）
```

跑全量前先确认解释器：跑 `Test/run_all.py` 用带 pandas/fastapi 的 venv
（`~/.workbuddy/binaries/python/envs/chanenv/Scripts/python.exe`），
跑含浏览器的用例用带 playwright 的 managed python。用错会大面积假红 / 真渲染层静默 SKIP。

### 5. 打包交付

只打改动文件、保持仓库原始目录层级、`__pycache__`/`.md`/`.pyc`/运行时产物一律不进；
解压到临时目录做 md5 往返比对；再抽查一批关键标记（新标记在、旧标记无残留、CRLF 无裸 LF）。
`.md` 交付说明单独放 zip 同目录，不进包。

### 3.5 特例：字段「跨区域搬家」（如明细区 → 核心区）

用户说「把 X 提到上面来显示」时，只做加法是错的 —— 必须**同时**做减法，
否则同一个字段上下各出现一次，会被读成两个不同指标。护栏要**双向**钉：

- 目标区：① 标签序列 == 目标顺序；② 容器格数 `hero.count("stats-cell") == 4`
  （只断序列抓不到「多加了一格」）；③ 取值来源仍是同一字段（`d.profit_factor`）
- 源区：④ 断言该字段名**不在明细区标签序列里**（`"盈利因子" not in detail_labels`）
- 真渲染层同样四条各来一遍，并断言目标区出现**具体数值**（`"3.40" in hero_html`），
  证明搬过去的不是空壳

**搬家会连带作废「紧随其后」类断言**：本轮需求原是「期望值 移到 盈利因子后面」，
盈利因子一上移，那条 `labels.index("期望值") == labels.index("盈利因子") + 1` 直接失效。
搬家时必须扫一遍已有断言，把引用被搬字段的判据改写成新邻居，否则要么恒红、要么悄悄漏测。

**格数变化（3 格 → 4 格）不必先改 CSS**：若容器是 `display:flex; justify-content:space-between`，
浏览器自均分间隙。但要用真渲染 `getBoundingClientRect` 量出证据，且**必须跑两个场景**：
常规值 + 极端长值（故意喂 `-1234567.89 元` / `1234.56`）。判据四项：
`hero.scrollWidth - clientWidth <= 1`、相邻格 `x+w` 不重叠、标签与数值的 `scrollWidth <= 格宽`、
标签/数值高度未增高（未换行）。

### 3.6 特例：只改「标签文案」的缩词 / 改名

用户给一对「改前 / 改后」文案时（如 `平均每笔盈利 / 平均每笔亏损` → `平均每笔盈利/亏损`）：

- **以「改后」的字面串为准，含空格**。用户的「改前」往往是从屏幕上顺手敲的转录、
  空格会被吞掉，所以空格是**歧义点**：只缩词就别顺手改空格。照字面实现，并在回复里
  一句话说明"按你给的字面串、斜杠两侧没加空格"，让对方一眼能纠正。
- **只动标签，别动值**：值里的分隔符（`</span> / <span …>`）保持原样，钉一条断言防连坐。
- **必须扫的引用面（漏一个就要么恒红要么悄悄漏测）**：
  ① 断言里的 `in` / `==` 字面串；② `EXPECT_ORDER` 之类的目标列表；
  ③ **对该文案做负向匹配的正则** —— 这是最容易漏的一类。本轮实例：
  `re.search(r'class="stats-label">最大单笔盈利(?! /)')` 是用来拦「拆成两行」的，
  但它把**旧文案的空格写死**了；标签缩成无空格后它会把新标签判成旧写法 → 必须改
  `(?!\s*/)`。凡是对显示文案做**负向先行 / 长度 / 字符集**约束的断言，改文案时都要一起审。
  ④ 测试文件自己的文档头、`run_all.py` 的组件说明串（它们也写着旧文案，同样会误导）。
  ⑤ 注释里引用旧文案的那几行 —— 注释留旧写法，静态检查该一起拦（"注释里也不留"）。
- **「旧标签无残留」断言要覆盖两种写法**：带空格与不带空格都扫一遍（用户可能就是
  想加/去空格，两种都算旧口径），且扫**整个文件**而不是只扫渲染函数段。
- 多处分散改动仍走 Python 补丁脚本（读字节 → 归一 `\n` → 逐条替换 + 命中次数断言 →
  还原 CRLF → 写回），并追加一条「旧长文案零残留」的全文件自检；命中数不对整条 abort。
- 别忘了抬 `index.html` 的资源版本号，否则用户覆盖后看着像没生效。

### 3.7 「这个数含不含 X？」—— 数值口径核查 + 反恒真护栏

用户问「平均每笔盈利算手续费了吧？」「这个金额是税前还是税后？」时，**不要只回一句"是的"**，
按三步走：

1. **给口径链，逐环给 `文件:行`**。典型是三层：① 值怎么算出来的
   （谁减谁：`net = gross − cost`）；② 减掉的那项由什么构成（`cost = 档A + 档B × 手数`，
   注意**两边都收**这种细节）；③ 展示层读的是哪个字段（stats 里的取数函数）。
   最后点明**分类也走同一口径**（"毛盈净亏"那笔算亏损笔）——这是用户最容易忽略、
   也最能证明口径统一的证据。
2. **顺手把边界找出来**。凡是"某条件下不扣"的分支都要说：档案缺失 → 返回 `0.0`（等于不扣）。
   再说清**这条分支实际走不到**的原因（有白名单闸门）——"理论上不扣 + 实际上必然扣"，
   两句话都要有。
3. **钉一条护栏，并证明它不恒真**。⚠️ 关键陷阱：**现有样本常常两种口径恒等**
   （测试工厂函数里 `gross_points == net_cash`、`cost_cash == 0` → 90 多条断言
   全都区分不出"读毛还是读净"）。所以必须**专造两字段符号相反的样本**，再补一条
   **非恒真对照**（同一批数据按另一口径算，结果必须不同）。

   **反恒真的最快做法 = 原地变异自检**（不必拷基线副本）：
   读目标文件**原始字节** → 用 `bytes.replace` 把决定口径的那一处改成另一种写法
   （如 `t.get("net_cash")` → `t.get("gross_points")`，**先断言命中次数**）→ 跑测试
   **必须变红**（并确认新护栏的断言名在变红列表里）→ 用**原始字节**写回 →
   **md5 逐字节确认复原** → 再跑一次**必须回到基线**。全过程 `try/finally` 包住，
   任何一步不符预期就报错退出。

   **源码契约断言要用 AST 取「内嵌函数本体」**：直接对整段 `getsource` 搜字段名会被
   **docstring 里列 schema 字段的那几行**骗到（那里本来就写着 `gross_points`、`cost_cash`）
   → 假红。用 `ast.walk` 找到名为 `_net` 的 `FunctionDef`，
   `ast.get_source_segment(src, node)` 只取函数体再断言。

### 3.8 一处文案的两个「写入口」：静态属性 + 脚本覆写（必须一起改、一起钉）

同一个提示（`title` / `placeholder` / 标签）常常**有两个写入口**：`index.html` 里的静态属性是首屏默认值，
`app.js` 的轮询 / 渲染函数随后**整句覆写**同一属性。只看到（或只改）其中一处，结果就是同一个控件
两种说法 —— 用户鼠标在同一个开关上左右挪几像素，看到的提示都不一样。

本仓实例（自动下单开关）：
- `label.auto-order-switch` 的 `title`（`index.html:51`，**静止**）—— 指到开关本体时浏览器取它；
- `#auto-order-wrap` 的 `title`（`app.js` 里拼句子，每 5s 轮询覆写）—— 指到容器其它部位时取它。

两处写的是同一句话（关闭自动下单后持仓的去向），必须同口径。做法：

1. **先枚举写入口再动手**：`grep -n "\.title *=" <js>` ＋ `grep -n 'title="' <html>`，
   把"同一 DOM 节点 / 子树"的所有写入点列出来。
2. **钉「两处逐字相同」的断言**（比分别断言两个字面串更能拦回退）：
   从 `index.html` 抽出 label 的 `title`，从 `app.js` 正则抽出那句拼接的后半段，
   断言**去掉分隔符后逐字相等**：
   ```js
   const labelTitle = /<label class="auto-order-switch" title="([^"]*)"/.exec(html)[1];
   const jsTail = /tip \+= '；([^']*)';/.exec(src)[1];
   check("两处同口径（少改一处即变红）", jsTail, labelTitle);
   ```
3. **别指望原生 `title` 的渲染结果**（无头浏览器弹不出原生 tooltip）：验收对象是**属性值**，
   但「首屏值」和「运行时值」都要量 —— 只量首屏会漏掉"到底哪个写入口最后赢"。

#### 运行时值怎么取：让真定时器跑一轮，而不是自己调函数

轮询函数一般挂在 IIFE 闭包里、`page.evaluate` 取不到。**不要**为了验收把它挂到 `window`
（等于为测试改产品代码）。正确姿势是**满足它的前置条件，然后等真定时器**：

```python
# app.js 只对带 .visible 的容器轮询（syncAutoOrderWrap 平时负责加它）
page.evaluate("() => document.getElementById('auto-order-wrap').classList.add('visible')")
for _ in range(40):                      # 最多等 8s；真实周期 5s
    page.wait_for_timeout(200)
    tip = page.evaluate("() => document.getElementById('auto-order-wrap').getAttribute('title')")
    if tip and tip.startswith("交易引擎："):
        break
```

实测拿到 `交易引擎：已停止，账户状态：空仓；关闭时，锁仓或平仓（平今/昨）`：
这是**端到端**证据（真文件、真定时器、真覆写顺序），同时证明了"静态 title 确实会被覆写"
和"覆写后的整句正确"。前置条件要对着代码找（本仓是 `wrap.classList.contains('visible')`），
`fetch` 用 `add_init_script` 打桩喂一条状态载荷即可。

### 3.9 术语/指代有歧义时：grep「产出点」定死口径，不要读注释猜

改可见文字 / 日志文案时最常卡住的一类：某处只写了简称或裸词（本仓实例：裸写「引擎」），
**指代哪一侧说不清**。读注释、读函数名都不可靠（注释会过时）。唯一可靠的做法是
**找那个值的产出点（生产者）**—— 产出点集合是唯一的，指代就唯一。

本仓实例：`app.js` 在 SSE `init` 回调里打印 `引擎未就绪: + data.error`，光看前端无法判断
指的是 `Trading/`（交易引擎）还是后端行情侧。查法只有一步：

```bash
grep -rn '"error"' App/ FrontAPI.py        # 先找所有可能的产出点
```

结论：`init` 帧的 `error` 字段**全仓只有 4 个产出点**，全在 `App/AppSSE.py`（`:377` / `:415` /
`:791` / `:818`），上游是 `init_chan_symbol(...)` + `_extract_realtime_snapshot(...)`
= K线拉取 + 缠论分析，与 `Trading/` 侧**零调用关系** → 口径必为「缠论引擎」（`Trading/` 之外）。

判据链（缺一不可）：
1. **穷举**：该字段 / 该文案的**全部写入点**（`grep` 到零残留才算穷举完，结论里附 `文件:行`）；
2. **上游**：每个写入点由谁调用、算的是哪一侧的数据；
3. **反向**：确认与另一侧**没有**调用关系（"看起来不像"不算）。

定不下来就别改 —— **错误的全称比裸词更糟**（等于把猜测写成了事实）。正例：上一轮把
`app.js:6735` 标成"指代无法唯一确定、需先定口径"而搁置，这一轮用产出点才定性；
**搁置本身是对的**，补的是证据不是勇气。

> 术语口径（本仓 `memory-chanpy.md` 2026-09-17 拍板）：**交易引擎** = `Trading/` 目录（自动下单）；
> **缠论引擎** = `Trading/` 之外（K线/笔段/买卖点）。补全称按这条分，**不要一律补「交易引擎」**。

#### 补全称之后加一条「反向扫描」断言

正向断言（"含新串"）拦不住"别处又新写了一个裸词"。补一条**反向扫描**：遍历 JS/HTML 的
**非注释行**，出现裸词即失败；`交易引擎` / `缠论引擎` 视为已限定，`//` 与 `<!-- -->` 行豁免
（注释属另一个口径，用户没点名时不动）。这条断言在改完 4 处之后立刻能拦住第 5 处。

#### 顺带：同一面板的「入口按钮」与「内部标题」是一对

入口按钮的 `title` 往往早就写全称了，面板内部标题却省写（本仓 `index.html:57` 全称 vs `:65`/`:69` 省写）。
补全称时两处都要看，写一条**跨节点同口径断言**（入口 title 含 `交易引擎账本` **且** 面板标题含同一串），
比分别断言两个字面串更能拦回退。

### 6. 变体：**canvas 画出来的东西**（坐标轴 / 曲线 / 图上标注）也是展示契约

用户说「纵坐标和横坐标都没有显示出来」时，DOM 里什么都没有可断言的东西 ——
文字是用 `ctx.fillText` 画进画布的。这时 DOM 断言、`innerHTML` 正则**全部失效**，
必须换手法：

**证据手法：打桩 `CanvasRenderingContext2D.prototype.fillText`**，记录每一次文字绘制的
内容 / 坐标 / `this.measureText(t).width`，即可精确回答"画了什么、画在哪、有没有越界"。

```js
const P = CanvasRenderingContext2D.prototype;
const mine = (ctx) => !!(ctx.canvas && ctx.canvas.id === "<目标画布id>");
P.fillText = function (t, x, y) {
  if (mine(this)) spy.texts.push({t: String(t), x, y,
    w: this.measureText(String(t)).width, align: this.textAlign});
  return _ft.apply(this, arguments);
};
```

- **必须按 `ctx.canvas.id` 过滤**：主图与面板里的画布共用同一个原型，
  不过滤会把 K 线 / MACD / 成交量柱的绘制全收进来，断言全乱。
- 用户报"没显示"时，先跑**修复前**的同一套打桩拿到"改前记录"（几张表 + 画布外坐标），
  再跑修复后 —— 前后同尺度对比才是证据，「改后是对的」本身不构成"改前确实缺"的证明。

**静态层用 node + canvas 桩**（不依赖浏览器）：

- 把画布函数从源文件**整段抽出**（`index("        function f(")` —
  注意锚点要带前导缩进，否则 `^` 正则数不到第一个函数），在 node 里跑，
  再把记录 JSON 回给 Python 做几何断言。
- 桩的 `measureText` 宽度模型要**略宽于**真实字体（先量真值再定系数：
  10px system-ui 下数字 ≈ 5.9、`-` ≈ 3.6），走保守一侧 —— 桩里放得下，真浏览器一定放得下。
- 数据用 `module.exports = <json>` 而不是 JSON 文件：坏值场景里可能有 `NaN`，
  那是合法 JS 但不是合法 JSON（真渲染层则把坏值写成字符串 `"?"`，
  靠 `Number("?") === NaN` 走同一条代码路径）。

**几何断言清单**（每一条都对应一类真实缺陷）：

| 断言 | 拦的是 |
|---|---|
| 文字盒子（按 align 推 left/right）不越出画布 | 写死左留白 46px 时 `-1200000` 的负号被裁 |
| 刻度值**互不重复** | 单边行情下 `0` 被画两遍（相差 5px 糊成一处） |
| 刻度值随 y 增大而递减 | 纵轴画反 |
| 首尾刻度包住数据范围 | 曲线顶出可视区 |
| 横轴有轴线 + 刻度线 + 时间标签 | 整条横轴一个字都没有 |
| 标签内容 == 该点数据的真实字段（如 `exit_at`） | 标签是"看起来像日期"的假数据 |
| 文字/网格线数量 ≥ N | 只有 max/min 两个数，等于没有刻度 |
| **标签/刻度条数 == 固定值（与数据量无关）** | 条数由"可用宽度"推出来 → 数据量一变表示法就变 |

**「条数」本身也可以是契约**（2026-09-19 补）：用户问「以后有 1000 笔，横轴咋显示？
是不是借鉴 X 面板的设计？」时，真正的缺陷往往不是"会挤"，而是**条数由可用宽度算出来**
（`want = clamp(floor(plotW / 72), 2, 5)`）、落点又由条数算出来 → 同一张图在不同宽度下
给出不同的时间刻度，没法做视觉回归。改法：**条数写死、落点取 `[0, (n-1)//2, n-1]`**。
配套护栏两件套：

- 加一个**最大规模场景**（如 1000 点，日期铺开跨年），断言 `len(ticks) == 3`、
  `len(labels) == 3`，并在断言名里写上「与笔数 N 无关」—— 这是用户那一问的正面回归项；
- 用 x 坐标**反推 index**（`round((x-padL)/plotW*(n-1))`）比对 `[0, mid, n-1]`，
  证明落点没被偷偷换掉。

**要求「借鉴 X 面板的设计」时，别照着重写一份 —— 直接调 X 的函数**：
抽出目标面板的格式函数（如 `fmtAxisDate`）注入 node 桩，再逐样本断言两者输出**逐字相同**。
只断言"格式看起来像 `YY-MM-DD`"是拦不住两边慢慢漂移的。

**画布类的坑**：

- **条数断言不能写死**：刻度条数由数据跨度与"好看步长"共同决定，
  固定样本上可能只有 3 条。要拦旧实现就断言「值不重复」「有网格线」这类**性质**。
- **小数位要跟着轴步长走**：步长 0.1 时若刻度值统一取整，`0/0.1/0.2/0.3` 全写成 `"0"`；
  反之步长带小数时整数刻度别拖 `.0`（`0` 不该写成 `0.0`）。写测试时才会暴露这一对。
- **标签要防"同字并排"**：同一天的多笔成交会让横轴并排三个 `09-18` ——
  位置对了、信息量为零。按数据跨度切换粒度（同日给 `HH:MM`）并跳过与前一个同字的标签。
- **NaN 会静默清空整张图**：某个值是 `NaN` 时 `max/min → NaN → yOf()` 全 NaN，
  画布一片空白且不报错。绘制前把非有限值**只丢那一个点**，别让它污染范围计算。
- **测试的截图输出目录不能取仓库内相对路径**：会凭空在工作树里建目录、
  污染交付包；改成读环境变量（如 `STATS_SHOT_DIR`），不设就完全不落盘。
- **刻度线不能靠「竖且短」来认**：数据量大时（1000 点）每步只有零点几像素宽，
  曲线段本身也满足 `|dx| < 0.6`，会被误判成刻度线。改成按**位置**认 ——
  刻度线从绘图区底边往下伸 4px，判据用 `|y0 - plotBottom| < 1 and |y1 - (plotBottom+4)| < 1`。
- **数值格式化契约要按「量级档位」逐个真渲染核对**：过万→万元 / 过百万→百万元 这类
  需求，只断言源码里有 `1e6` / `1e4` 是不够的（顺序写反就全错）。做法：把 fixture 放进
  一个 list 兜住（路由闭包要看得见），每档关面板 → 换 fixture → 再点开（`toggleStats` 打开时
  走 `force=true` 强制重取）→ 读单元格 `textContent` 核字面值。
  另配一条静态断言：`body.index("1e6") < body.index("1e4")`（先判大档，否则 3.4e6 会被
  写成 `340.00 万元`）。
- **缩位口径要写清"哪些字段缩、哪些不缩"**：总量字段（总净盈亏）缩位是为了排版不撑破窄格；
  每笔量级字段（期望值 / 平均每笔 / 最大单笔）缩了反而读不出数（5000 元 → `0.50 万元`）。
  两个方向各钉一条断言，别只钉缩的那一侧。
- **轴上的单位/缩位必须与面板**同源（2026-09-19 用户：「纵坐标需要添加单位，也按照
  不过万→元、过万→万元、过百万→百万元」）**：最容易犯的是**在轴里再写一份
  `if (a >= 1e4) return "万元"`。做法：把档位判定提成 `moneyScale(v) → {div, unit}`，
  面板与轴都调它；**护栏**三件套 —— ① `全仓 count('"万元"') == 1 && count('"百万元"') == 1`
  （多抄一份就红）；② `eqAxisNum` 函数体里不许出现 `1e4/1e6/1e8`；③ 旧的局部
  `var money = function` 不许回潮。再加一条**跨实现**比对：node 桩里对同一批量级同时输出
  JS 的 `money()` 与 Python 侧重写的规则，逐字核。
- **单位要按「整条轴」选一档，不要逐根刻度各自判档**：否则一条轴上出现
  「`0 元` / `50.00 万元` / `1.00 百万元`」混单位，刻度之间反而不能比大小。
  档位取 `max(|lo|, |hi|)`（刻度边界已包住数据，这就是轴上会出现的最大量级）。
- **缩位之后，小数位不能用「step < 1」判**：缩位会改变**显示步长**（5000 元 → 0.5 万元），
  位数要由 `step / div` 推，而且必须**能把这个步长写准** —— 步长 0.25 只给 1 位小数会把
  0.25/0.5/0.75 写成 0.3/0.5/0.8，**刻度值全是错的**。护栏：断言**相邻刻度等距**
  （真实刻度等距，被四舍五入就会不齐），这条比"标签看起来像数字"强得多。

## 踩坑清单

- **Edit 报 success 但文件没变**（本会话踩过 2 次）：改完必须 Grep 新字符串命中数，别信返回值。
- **行序断言别把无关区块算进来**：面板常有 hero/概要区，标签序列要先切掉它们再比。
  切分锚点用**带引号的整行写法**（`'<div class="stats-rows">';`），否则会切到空态分支里的同名容器。
- **注释里别写字面禁用串**：想解释"旧标签叫什么"时，把字面串写进注释会让禁用串断言自己失败。
  改成「再缀一个「/笔」是重复限定」这种不含被禁字面的说法。
- **同名标签的守卫用例可能已被别处引用**：改标签文案前先 grep 全仓测试，避免撞别人钉的契约
  （如 `Trading/Test/test_trade_stats_ratio_naming.py` 钉死了「盈利因子」等标签）。
- **`grep -c` 数的是子串出现次数**，不能用来证明"锚点唯一" —— 用整行相等判断。
- **同一字段在两个区块用字符串拼装时，锚点必须带区块特征**：核心区是
  `class="stats-cell"`、明细区是 `class="stats-row"`，`盈利因子` 这个字面串本身不唯一。
  锚点取整行（含 `stats-cell`/`stats-row`）才能保证 `assert 命中 == 1`。
- **交付包用「同名累积覆盖」比新名字更省事**：多轮改同一功能时同名覆盖，用户一次覆盖即得全部；
  说明文档开头必须写明「本包是累积包，不需要先装上一版」。
- **新写的测试文件不是 CRLF**：Write 工具落盘是 LF，而这类仓库是 CRLF 检出。
  打包自检里那条「全 CRLF（裸 LF=0）」会当场抓到 —— 转换后再复跑一遍用例再打包。
- **修一条需求时顺带删掉的范围要写进说明**：本轮「去正号」把 `yuan()` 里
  `x >= 0 ? "+" : ""` 改成 `x > 0 ?`，影响的不只是最大单笔那一行，
  而是面板上**每一个**金额 —— 交付说明要列全受影响的位置，别只写需求里提到的那一个。
- **`''` 在 Python 三引号字符串里会被吃掉**：往生成文本里塞中文引号时用
  `「」`，别用 `''`/`""`（在 `'''…'''` 里会被当成字符串拼接后的空串，
  落盘变成 `''现在累计多少''` 这种怪写法）。
- **幂等替换的「new 包含 old」陷阱**（2026-09-22 一天踩中两次）：若 new 串里原样包含 old 串（典型：在锚点后**追加**内容），第二遍运行时 old 仍命中 → 再插一份。追加类改动不要走通用 patch()，单独判断目标内容是否已存在；already 锚点选纯 ASCII唯一标识符（如 `fmtAolPx1(t.exit_price)`），别选含中文/箭头的串（shell 内联传参可能转码失配）。
- **「先 `open(p,'wb')` 再 `open(p,'rb').read()` 恢复」= 自毁清零**（2026-09-22 实测）：
  恢复原始字节必须**先读完存进变量**再写回；`wb` 一打开就截断，同文件再读已是空 →
  文件变 0 字节。变异自证的恢复路径务必用 `orig = open(p,'rb').read()` 预存 + `finally` 写回 +
  md5 断言复原；沙盒树坏了就从 raw 通道重拉该文件重放补丁，别手救。
- **`Test/run_all.py` 用的解释器可能没有 playwright** → 用例里的真渲染层会静默
  `[SKIP]`，回归照样"全绿"但你其实只跑了静态层。交付前必须**另用装了 playwright 的
  解释器单独复跑一遍这两个用例**（本机：`…/envs/chanenv` 有 pandas/fastapi 无 playwright，
  `…/versions/3.13.12` 有 playwright 无 pandas）→ 两个数字都写进交付说明
  （`run_all 46/52` + `单独跑 626 项全绿`）。
