# 静默故障根因定位

针对一类特别难查的 bug：**没有任何报错**，功能却大面积失效。

典型形态是"接口返回 HTTP 200，但响应体是个空壳" —— 代码把它当"正常无数据"，
于是错误被当成事实沉淀进缓存/落盘，**越刷新越坏，重启也不恢复**。

## 铁律

1. **HTTP 200 ≠ 成功。永远先看响应体，再看状态码。**
   很多行情/开放接口对非法请求不回 4xx，而是回 200 + 一句 `"FAILED"`。
2. **"整体覆盖率骤降"一律按链路故障处理**，不能按"个别数据取不到"处理。
   判据：失败数 ≈ 总数（如 5367/5367）→ 链路级；失败是个位数/几% → 数据侧。
   静默接口会把逻辑 bug 伪装成数据缺失，用户（和你）都会第一时间误判。
3. **二分要在"最底层"做**。直接对原始 URL 发一次请求（不经过任何项目代码），
   再调一次项目函数。两者结果不同 → 逻辑侧；都失败 → 接口侧。**一步定位，别猜。**
4. **最高频根因是参数顺序**。对照「调用方 append/传参的顺序」与「被调方 for 解包/f-string 的顺序」。
   命名与真实顺序不一致（`for m, c in batch` 里 m 其实是 code）是重灾区。
5. **修复必须三件套，缺一不可**：
   ① 正确实现（且对两种入参顺序归一，容错）；
   ② **失败可见性** —— 整批无效返回必须打出 WARNING，否则下次还是静默；
   ③ **数据质量门槛** —— 落盘/换表前校验新数据量级，残缺数据不得覆盖完好数据。
6. **护栏测试不联网**：monkeypatch 底层请求函数，断言"请求参数形态"而不只是"返回值"。
   返回值可以偶然对，参数错了迟早再炸。

## 流程

| 步 | 动作 | 判据 |
|---|---|---|
| ① | 量化现象：失败数 / 总数、影响面 | 比例≥50% → 链路故障 |
| ①′ | **看缺失集合的构成**：是否全部集中在同一类标的（同一市场 / 同一前缀 / 同一品种） | **按类聚集 → 立刻怀疑「该类被划给了不覆盖它的源」**，而不是接受「该类本来就没有」 |
| ② | 抓**原始响应**：`urllib.request` 或 curl 直打接口，打印 `status` / `len(bytes)` / `repr(raw[:300])` | 200 + 极短 body = 空壳 |
| ③ | 若②正常而项目函数返回空 → **逐行复刻函数内部**，打印中间量（拼出的 URL、decode 后的文本、解析结果） | 断点定位到具体一行 |
| ④ | 参数顺序对照：调用方 vs 被调方 | 顺序写反 → 根因 |
| ⑤ | 最小修复 + 入参归一（容忍两种顺序） | 实测 N/N 命中 |
| ⑥ | 补失败可见性：整批无效 → WARNING；失败率过半 → 升级日志级别 | 下次能一眼看见 |
| ⑦ | 加质量门槛 + 不联网护栏 | 残缺数据无法覆盖好数据；契约被测试锁死 |

> **①′ 是本清单里最贵的一条**（2026-09-12 实测教训）。当天把 PE 单源化到 eltdx 后，
> 差异清单显示「旧有新无的 144 个**全部是指数 / 板块代码**」，当时判定为「指数本来就没 PE」并放过。
> 次日用户报「指数没有 PE」—— 真相是 eltdx 统计文件根本不含指数，**这一类被分流规则错误地划给了不覆盖它的源**。
> **判据：缺失按类别整齐聚集时，「全是 X 类」是分流写错的指纹，而不是 X 类无数据的证据。**
> 反过来说，若缺失是**散乱**的（各市场、各前缀都有），才更可能是接口/网络层面的普遍故障。
> 验证成本极低：拿 3~4 个该类的标的 + 1 个正常标的，各喂给两个候选源做对照（见下"双源对照法"）。

## 双源对照法（判"到底是哪一端的问题"）

一次调用就能把"数据源边界"与"分流写错"分开：

```python
# 同类 3~4 个 + 异类 1 个对照，两个源各跑一遍
src_a.fetch(该类样本 + [异类样本])   # → 若只回异类，说明该源不覆盖这一类
src_b.fetch(该类样本 + [异类样本])   # → 若该类有值，说明原本可达，是分流把它送错了
```

2026-09-12 实测输出即为此形态：`eltdx(3指数+1股票) → {股票: 19.57}`（指数一条未回），
`腾讯(3指数) → {上证指数:16.93, 沪深300:13.51, 中证500:32.56}` —— 一测即定性，不必读代码推断。

## 附带必查：坏数据有没有被"沉淀"

静默失败最恶劣的不是"这次没取到"，而是**残缺结果被写进了缓存**：

- 落盘：`if result:` 只要非空就写 → 残表覆盖好文件；
- 换表：`replace_names()/replace()` 是**整体替换**，一次坏刷新就永久破坏内存态；
- 表现：用户会发现"我点了一下刷新，数据反而没了""重启也不好"。

**必须加门槛**：新数据条数 < 旧数据 × 阈值（经验值 0.5）→ 拒绝覆盖、拒绝落盘，并打 WARNING。

## 另一类静默失败：键设计不周导致「互相覆盖」

**症状**：某个标的莫名消失 / 名字张冠李戴，且**不报错、无日志**。

**机理**：把「复合键」拆成纯代码后建**反查映射**，而纯代码在跨市场/跨品种时**不唯一**：

```python
compound_key_map[bare_code] = compound_key          # ✗ 纯代码单键
# sh000001(上证指数) 与 sz000001(平安银行) 的 bare_code 同为 "000001"
# → 建表时后者覆盖前者 → 上证指数的名称被写到平安银行条目上，
#   前者永远无名 → 在「过滤无名」步骤被删除。
```

2026-09-12 实测后果：搜 `000001` 从「上证指数 + 平安银行」两条变成只有平安银行；
与深市股票同号的 `sh000xxx` 指数系列（上证指数 / 上证50 / 中证500）静默失踪，
而 `sh000300`（无 `sz000300` 与之撞号）**安然无恙** —— 这种"有的在有的不在"的自洽性正是该 bug 的指纹。

**判据与修法**：
- 凡 `{纯代码: 复合键}` 形态的映射，键必须带足判别维度 → 改用 `(market, bare_code)` 二元组；
- **能用 `market + bare_code` 直接还原的，就不要建反查映射**（少一层可错的地方）；
- 回归护栏：造一组「同号不同市场」的输入（`sh000001` + `sz000001`），断言各归各位。

## 已知静默面清单（持续补充）

| 接口 / 组件 | 非法请求或缺失标的的返回 | 后果 |
|---|---|---|
| 新浪 `hq.sinajs.cn/list=` | `200` + `var hq_str_sys_auth="FAILED";`（≈30B） | A股名称/行情全空 |
| 腾讯 `qt.gtimg.cn/q=` | `200` + 空/`v_pv_none_match` 标记 | 港股名称/PE 全空 |
| 通达信 eltdx 统计文件 | 无接口级错误，但**整文件下载**：取单只 = 取全市场耗时 | 别指望"只取单只更快" |
| 通达信 eltdx 统计文件（`0x06B9`）| 对**指数 / 北交所**整条不返回：无错误、无日志、不抛异常 | PE 静默为空；**须按标的类别分流**，指数走腾讯（2026-09-12 实测） |

**前缀匹配陷阱**：解析 `hq_str_xxx` 时用 `startswith("hq_str_sh")`，
注意 `hq_str_sz...` / `hq_str_sys_auth` 的边界；marker 顺序写错会互相误吞。

## 探针模板（可直接改）

```python
import urllib.request, json
url = "http://hq.sinajs.cn/list=BADFORM"
req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0",
                                           "Referer": "https://finance.sina.com.cn/"})
resp = urllib.request.urlopen(req, timeout=15)
raw = resp.read()
print("status:", resp.status, "| bytes:", len(raw))
print("raw repr:", repr(raw[:300]))          # ← 关键：看空壳到底长什么样
print("decoded:", repr(raw.decode("gbk", errors="ignore")[:300]))

# 再走项目函数做对照
from DataAPI.SinaAPI import fetch_a_names
print("project func ->", json.dumps(fetch_a_names([("600519", "sh")]), ensure_ascii=False))
```

> 在 Windows/PowerShell 下**不要**用 `>` 重定向 Python 输出再读（会变 UTF-16 或被 console
> 代码页重编码成乱码）。让脚本自己 `open(path, "w", encoding="utf-8").write(...)`，
> 再用文件读取工具看。
