# 全量符号改名 + 契约护栏

改名**不是文本替换**。真正的难点在三件事：**消费方在代码之外**、
**名字承载的语义已经变了**、**旧数据/旧调用会静默降级**。

## 第一步：先判定"这个名字到底还承不承载语义"

用户投诉"名字不准确"时，先量化回答：**这个符号还有几处是真正的判定性使用？**

```bash
# 判定性使用（is / is not / == / !=）与"写入/贴标签"要分开数
grep -rn "EntryMode\.OPEN_FIRST" --include=*.py . | grep -vE "Trading/Test/"
```

实战结论模板（本次实例）：
```
判定性比较：0 处
写入点：3 处（构造/赋值/序列化默认值）
所有判定只问一个问题：is not EntryMode.LOCKED
→ 该枚举只剩 1 个值有决策语义，另 2 个已退化为审计标签
```

**这一步决定了改名的性质**：
- 若判定性使用为 0 → 改名是"可安全机械替换 + 改注释"，重点在防回潮；
- 若仍有判定 → 改名会改变行为，必须逐个判定点过一遍。

⚠️ 不要跳过这步直接替换。也**不要**先入为主认为"名字错"——常是**注释错了**，
名字的字面义仍成立（本次：`OPEN_FIRST` 指"入场来源"，仍准确；
错的是"OPEN_FIRST → 锁仓软离场"这条已废的联动注释）。

## 第二步：把消费方找全（最容易漏）

字段改名必须扫**代码之外**：

```bash
# 全仓、全文件类型（含前端/文档/配置），排除虚拟环境
grep -rn "entry_mode" . 2>/dev/null | grep -v "__pycache__\|/\.venv/\|/\.git/"
```

本次就靠这一步抓到 `Frontend/app.js:7449` 的
`p.entry_mode === 'locked'` —— 前端在过滤锁仓腿数量。
只改后端 = 前端静默显示"已锁仓 0"。

同时确认**哪些目录不需要改**：本次 `App/` 虽序列化 positions，
但不引用该字段（只是透传 `store.get_json("positions")`），故不动。

## 第三步：区分"可安全全局替换"与"歧义字面量"

| 类型 | 处理 |
|---|---|
| 标识符 `EntryMode.OPEN_FIRST` | 全局替换，安全（带前缀先替换长串） |
| 类型名 `EntryMode` | 上一步做完后再全局替换 |
| 字段名 `entry_mode` | 全局替换（注意别误伤 `entry_date` 之类的邻居——它们不含 `entry_mode` 子串，安全） |
| 值字面量 `"open_first"` | 全局替换，安全（无第二含义） |
| **歧义字面量** `"locked"` | **必须逐处甄别！** |

本次 `"locked"` 有两类含义，混淆会改坏代码：
- 枚举值 → 应改为 `"soft_exit_lock"`
- **sqlite 报错文本**（`if "locked" not in str(exc).lower()`，`App/AppScanStore.py`）
  → **绝不能动**

做法：脚本里加 `VALUE_SKIP` 文件集合，跳过与目标无关的文件，改完 `grep` 复核。

## 第四步：脚本化替换（写文件再跑，别用 heredoc）

⚠️ **血泪坑：`bash heredoc` 传中文会乱码**，导致 `assert old in s` 锚点匹配失败、
替换静默不发生（表现为"以为改了其实没改"）。**改代码一律用 Edit 工具，
或用 Write 工具写脚本文件再执行**，不要在 heredoc 里塞中文/反斜杠。

替换顺序（顺序敏感）：带前缀长串 → 类型名 → 字段名 → 值字面量 → 正则处理裸 token。

裸 token 用负向断言避免误伤：

```python
BARE_LOCKED = re.compile(r"(?<![A-Z_])LOCKED(?![A-Z_])")  # 不匹配 UNLOCKED
```

## 第五步：不兼容变更必须配"拒绝启动"闸门

即使用户说"无需 db 兼容"，也要问：**旧数据静默降级会怎样？**

本次实例（真实隐患）：
```
旧 state.db 的锁仓腿（entry_mode="locked"）
  → 新代码读 origin 读不到 → 静默回退 SIGNAL_OPEN（敞口腿）
  → 引擎把它当真实净敞口 → 接进止盈止损 → 可能对锁仓腿发平仓单
```
而既有对账逻辑只在"真实持仓 > 引擎持仓"时**告警**、不纠正 → 兜不住。

**正确做法：fail-fast**。在恢复入口加闸门，检出旧键就抛错并给出可执行处理方式：

```python
@staticmethod
def _legacy_position_records(records) -> list:      # 纯函数，便于单测
    return [d for d in records if isinstance(d, dict)
            and any(k in d for k in TradingEngine._LEGACY_POSITION_KEYS)]

def _reject_legacy_state(self, records) -> None:
    legacy = self._legacy_position_records(records)
    if not legacy:
        return
    self.ev.write("state_schema_incompatible", ...)
    raise RuntimeError("state.db 仍是旧 schema（含 entry_mode 键）… 处理：删除 …")
```

交易/金融类系统尤其如此：**"猜错的持仓类别"比"起不来"危险得多**。

## 第六步：防回潮护栏（把"已解耦"变成可执行契约）

注释拦不住后来人。用测试钉死，**三层**：

1. **行为等价**：矩形矩阵。`字段 ∈ {A, B} × 日期 ∈ {今日, 跨日}` 四组合下，
   目标函数结果**只随日期变、不随字段变**。
2. **源码契约**：`inspect.getsource` 取目标函数，**先用 AST 剥掉 docstring**
   再断言不含那两个值名。
   ⚠️ 坑：不剥 docstring 会误报——docstring 里"为什么废弃旧联动"必然提到旧名。
3. **全仓扫描**：正则禁止非测试代码对这两个值做 `is`/`is not`/`==`/`!=`
   （允许赋值与 `.value`）。
4. **迁移闸门**：旧键被识别 / 新键不误伤 / 抛错路径实弹（RuntimeError + 事件 + 提示）。
5. **持久化往返**：各值 to_dict→from_dict 不变。

**必须做变异测试验证护栏有效性**：临时注入旧耦合，
断言护栏变红且**比旧测试多抓到项**（本次：P25 挂 5 项，旧测试只挂 1 项）。

## 第七步：复验的判据要可靠

⚠️ **两个统计陷阱**（都真实踩过）：

1. **shell 循环里 `grep -c` 计数会跨迭代污染** —— 同一命令里先 `printf` 出多个
   文件名（含 `Test` 等字母），再 `grep -cE "✗|FAIL"`，会把文件名当输入行计入，
   误报 `✗=10`。**统计测试结果用 python `subprocess` 落盘统计，别在 shell 里数**。
2. **`grep -qE "FAIL"` 会命中日志/JSON 里的字面词**（如 `[safe-delete] FAIL_CLOSED`）。
   用精确判据：`✗` 计数 + `[FAIL]` 计数 + 退出码。

复验流程（交付前必跑）：真实项目 **新建干净目录** → 覆盖 zip → **执行随包删除步骤**
（改名的测试文件被重命名后，旧文件不会因覆盖而消失，不删就会 import 失败拖垮全套）
→ 跑全套 + 冒烟脚本。

## 第八步：改名会改变"字母序"，连带改测试

⚠️ 坑：测试常写 `sorted(p.origin.value for p in ...)` 并与**硬写的期望列表**比较。
改名后字母序变了（`signal_open` < `soft_exit_lock`，但原来 `locked` < `open_first`），
期望值必须同步调整。**顺手加一行注释说明"期望值须按字母序书写"**，避免下次再踩。

## 交付清单

- 改名映射表（旧→新，含**值**的映射，不只是标识符）
- 影响面：改了哪些文件 / 哪些文件经核查**不需要**改
- ⚠️ 应用步骤（覆盖 + **必须删除的文件** + **必须清理的旧数据**）
- 闸门的行为说明 + 实弹验证输出
- 未改的部分及理由（如 `Docs/` 带日期的审计快照，改了就是篡改历史）

## 第九步：改名要连"注释与文案"一起管（否则必然回潮）

**只扫标识符是不够的。** 真实教训：某次已把全仓废弃术语清为 0（155 处，写了对照表），
**但随后两轮改动新写的注释又带回了 15 处**，用户直接质问"不是已经全部清理了吗？"。

根因：约束只写在文档里，**不在任何可执行断言里**——后来人（或 AI）写新注释时，
没有任何信号提醒他这个词已废弃。

### 两层做法

1. **改名当时**：把"废弃词 → 新表述"做成映射脚本，改完**立刻跑一次禁用词扫描**
   （注释 / docstring / 打印文案都要在内），确认残留 0。
2. **永久护栏**：新增"术语护栏"测试，扫描全仓 `.py` / `.js` 禁止废弃词。

护栏本身要**三段式**，别只做一件事：

```python
# [0] 元护栏：先证明检测器有效，否则"零命中"可能是假绿
assert _RE.search("_is_today_leg")   # 应命中（含下划线前缀的旧标识符）
assert not _RE.search("legacy")      # 不误伤
assert not _RE.search("legal")
assert not _RE.search("privilege")
# [1] 全仓扫描：禁用词零命中
# [2] 覆盖面自检：断言关键文件确实在扫描集合里（防有人把范围改窄 → 护栏静默失效）
```

禁用词表设计要点：

- 中文词直接 `in` 判定；**英文词必须用负向断言**：
  `re.compile(r"(?<![A-Za-z])legs?(?![A-Za-z])", re.I)`
  否则 `legacy` / `legal` / `privilege` 全部误报。
  注意 `_leg` 这种下划线前缀**应被命中**（`_` 不是字母，负向断言满足）。
- 护栏文件自身必然含禁用词（它就是定义处）→ 扫描时 `os.path.abspath(p) != __file__` 排除自身。
- **不要扫带日期的历史文档目录**（如 `Docs/`）—— 那是审计快照，改了等于篡改历史；
  它的正确定位是"读旧文档时对照新表述"。
- 若某个辅助脚本**必须**含禁用词字面量（例如作为变异注入样本），
  **不要让它以被扫描的前缀命名**（否则会被自身扫到误报）—— 本次就只能叫
  `mutation_test_*.py` 而不能叫 `verify_*.py`。

交付前**必须做变异测试**：注入 1 处中文 + 1 处英文禁用词 → 断言护栏变红且
**精确报出 `文件:行号`** → 还原 → 确认逐字节一致且复绿。

### 顺带：改名后要扫"辅助脚本"

本次漏掉的是**根目录的验证/探针脚本**——它们仍 `import` 已删除的旧类型名、
并使用旧字段名，实际已 `ImportError` 却没人发现（因为它们不在测试套件里）。

**规律**：测试套件会因改名而红，所以你会修；但**散落在仓库根目录的工具脚本
不在 CI 里，最容易漏**。改名后请显式 `grep` 一遍 `verify_*.py` / `tools/` /
`scripts/` 之类的辅助脚本，或写个冒烟脚本逐个执行一遍。

## 第十步：改名对象是**文件名 / 模块名**时，额外两件事

上面的步骤都适用，但文件改名在**判据**与**交付**上各多一条。

### 10.1 判据 = 同目录多数派，不是 PEP8，也不是通用惯例

「这名字不规范」在文件/目录层先要回答"跟谁比"。正确判据是
**同目录 / 同类既有文件的多数派**：

- 实例（2026-09-16 chan.py）：`Trading/Infra/trade_stats.py` 混在 7 个 PascalCase
  （`Clock.py` / `EventLog.py` / `Instrument.py` / `Period.py` / `Product.py` /
  `Records.py` / `StateDB.py`）里 ⇒ 违规 → 改 `TradeStats.py`。
- **同一仓库里函数/变量层却是 snake_case**（`compute_trade_stats`、`load_trades_report`）
  ⇒ **那是正确的，不要顺手一起改**。

⚠️ **一刀切把全仓 snake_case 都改了是错的**（`Common/cache.py`、`DataAPI/ccxt.py` 这类
历史文件改了只会扩大与上游 pull 的冲突面）。**只改被点名的那个 + 以后新文件不再犯。**

**先写"刻意不改"清单再动手**，比事后解释便宜：函数名、测试文件名前缀
（`test_pNN_主题.py` 是既有惯例）、历史快照（当时的交付记录里确实叫旧名 →
**只加注不改写**）。

### 10.2 交付要多一步：**旧文件不会被覆盖解压干掉**

这是符号改名没有、文件改名才有的坑：

- 交付习惯是「按目录层级整文件覆盖」⇒ zip 里只有**新路径**，
  用户仓库里的**旧文件原封不动留着**；
- 后果：多一个**无人 import 的死模块** —— 功能无影响，但污染 `grep`、
  目录里多一个异类命名（下一个人照着它再犯一次）；
- **必须显式给用户「需删除清单」**，并把它做成打包脚本里的可检查项：

```
需删除清单：<旧路径>        ← 直接来自「上游存在 / 沙盒不存在」的 missing 集合
自检 A：旧路径不得进 zip
自检 B：新路径必须在 zip
解压后探针：NEW_OK（新模块可导入）+ OLD_GONE（旧模块 ImportError）
```

最后那个探针是关键：只有 `ImportError` 才算"真没了"。
若旧名仍可导入 ⇒ `__pycache__/*.pyc` 残留，或有人偷偷建了转发 shim。

> 顺带：**清掉旧模块的 `__pycache__/<old>.cpython-*.pyc`**（虽不打包，
> 但本地会让人误以为"旧名还能用"）。实测命令：`os.rename` 后遍历该目录删掉
> 以 `<old>.` 开头的 pyc。

## 十一、「同名不同义」的改名：不是 A→B，而是把两个语义重新分配给两个名字

上面所有步骤默认是"一个符号换一个名字"。还有一类更隐蔽的情况：
**同一个字段名在两个模块里指两种算法**，此时要改的是**其中一个**，
判据不是"多数派"，而是「**让字段名去对齐它本来就对的中文标签**」。

实例（2026-09-17 chan.py 成交统计）：

| 文件 | 字段名 | 实际算法 | 中文标签 |
|---|---|---|---|
| `Infra/TradeStats.py` | `profit_factor` | 总盈 ÷ 总亏 | 面板「盈利因子」|
| `Tool/Recorder/Analyze.py` | `profit_factor` | `abs(avg_win/avg_loss)` | 命令行打印「盈亏比」|

同一个名字、两种算法。**中文标签早就把它们区分开了**（一个叫盈利因子、一个叫盈亏比），
错的是字段名 —— 所以改 `Analyze.py` 那个：`profit_factor` → `pl_ratio`，
让它跟自己的标签对齐。改完两个名字各管一个口径，不再交叉。

### 这类改名的三个要点

1. **先建"名称 × 算法"矩阵**，把每个名字在每个模块里实际算什么列出来。
   矩阵里出现"同名字段 → 两行不同算法"就是它。
2. **改哪个？** 改那个"字段名与它自己的中文标签不一致"的；标签一般是对的
   （它面向用户，早被用户纠正过），字段名是内部随手起的。
3. **护栏要覆盖"中文名 ↔ 字段名"的对应**，不能只断言字段名存在：
   ```python
   # 名字对了、中文名贴错了，同样会让用户误读
   check_true("docstring 中 pl_ratio 一行写着「盈亏比」",
              "盈亏比" in [l for l in doc.splitlines() if "pl_ratio" in l][0])
   check_true("docstring 中 profit_factor 一行写着「盈利因子」", ...)
   ```
   再加一条**反向样本**断言两个口径"必须可区分"（数值不相等、甚至符号倾向相反），
   这样"实现串了"（把 A 式写成 B 式）也能被抓住 —— 只断言键存在永远抓不到。

### 附带：同一个中文词可能属于两个语境，别一起统一

本次「盈亏比」在仓库里有两处含义：
- **统计**：平均每笔盈利 ÷ 平均每笔亏损（`pl_ratio`）← 本次统一的对象
- **止盈止损**：止盈距离 ÷ 1R，如"盈亏比 1:2"（`r_multiple_tp`）← **不是同一个东西，不要动**

统一口径前先划清"说的是哪个语境"，否则会把策略参数误当统计字段改掉。

## 十二、改名的降级面是「在线接口」时，失败是静默的

上面第五步讲的是**持久层**改名要用 fail-fast 闸门。如果改的是
**HTTP/JSON 响应字段**（前端直接消费的 key），性质不同：

- 旧前端（浏览器缓存）+ 新后端 → 前端读一个不再存在的键；
- JS 的 `x != null` 判定对 `undefined` 是 `false` → 常见写法会**静默显示占位符**
  （`—` / `0` / 空白），**不报错、控制台干干净净**。

所以这类改名的交付说明里必须写一句可执行的重启/刷新步骤：

```
解压覆盖 → 重启后端 → 浏览器硬刷新（Ctrl+F5）
```

并说明"不刷新会看到什么"（本次：统计面板那格显示「—」），让用户一眼能对上号。

## 十三、新文件命名：同目录多数派 **vs** 项目是否在「去过程编号」

§10.1 说判据是"同目录多数派"。但有一个例外要优先于多数派：

**项目正在做「清理开发过程坐标」时，新文件不要新增编号。**

实例：`Trading/Test/` 里多数派是 `test_pNN_主题.py`（p5…p58），
但该仓库同期刚做过一轮"清掉注释里 Phase / P 编号 / 轮次"的治理
（见 skill `code-comment-coordinate-cleanup`）。此时再新建 `test_p59_*.py`
等于**亲手把刚清掉的那类坐标又加回去**。

做法：改用**主题式命名**（同目录已有先例：`test_period_consistency.py`、
`test_product_fee_table.py`、`test_engine_config.py`），本次落地为

## 十四、「契约靠自觉」→ 改名自带告警 + **默认拒绝**扫描

一类特殊的改名：用户说「**这个出口的契约只写在注释里，没人拦得住后来人**」。
官方文档里常给两个选项 —— (a) 改成返回副本/不可变视图；(b) 改名 `*_raw_unsafe` +
静态扫描禁止下游引用。**先别选，先找证据。**

### 14.1 判据是实验，不是偏好

本次（chan.py `AppData` 8 个裸 `@property`）仓库自己的守卫文件里写着一条实测结论：

> 「把 `pe_cache` 改成 `return dict(self._pe)` 后，**本检查反而"通过"了**。」

原因：那份护栏的判据是「函数体必须是且仅是一句 `return self.<字段>`」。一旦返回副本，
该条就**不满足判据、从被检查集合里静默消失** —— 护栏被绕过且不报错。

再加上第二条证据：下游模块级别名靠「同对象 `clear()`+`update()`」拿零漂移，
返回副本会让别名**永远读到旧表**（静默数据过期）。

⇒ **两条证据一起就能否掉 (a)**，而且这不是"我觉得"，是可复现的。写进交付说明。

### 14.2 改名的落点是「命名自带告警 + 默认拒绝」，不是"禁止引用"

- 出口统一加后缀（本次 `_raw_unsafe`）：**返回值语义不变**（活引用是零漂移的要求），
  只是让读代码的人当场看见"这不是给你随便用的"。
- 静态扫描要把契约从「启发式非原子判定」升级为**默认拒绝**：
  **除白名单外，全仓任何引用都失败**——包括新增模块。白名单每条必须写理由。
- 白名单要**计数校验**（`RAW_EXIT_EXPECTED_N = 8`）：出口被删/改名/去后缀会让扫描
  静默缩水，计数校验把它变成显式失败。
- 扫描器**自带正负探针**：写一个真实探针文件证「该报的报」，并证「白名单内零误报」
  （后者防护栏自身假红）。两者都进 `[PASS]` 列表。

### 14.3 三个必踩的坑

1. **CRLF：改名脚本用 `newline='\n'` 写，会把 CRLF 文件整份翻掉。**
   本次 `App/AppOrch.py` 321 行 CRLF 被一次写成 LF —— 净改动 1 行，diff 却是整份文件。
   正确姿势：**写前探测原文件行尾**，`open(...,'wb')` 按原样写
   （`nl = b'\r\n' if raw.count(b'\r\n') else b'\n'`），改完打印 `CRLF=旧值` 自证。
   ⇒ 交付前**逐文件比对"变动行数 vs 净增行数"**，整份文件级差异一眼看得出。
2. **注释/docstring 里的"叙述性引用"也要同步，但残留扫描必须先剥注释与 docstring。**
   这两件事方向相反，**两件都得做**：
   - 不做前者 → 旧名在仓库里已不存在，却还被 `# 已删 x = app_data.pe_ cache`、
     `原写法是 len(app_data.float_mc_cache)` 这类留档叙述引用着 → **悬空符号**，
     照着 grep 一无所获、照着抄 AttributeError；
   - 不做后者 → 这些留档叙述被当成"残留实引用"，本次一次假报 13 处。
   实现：`tokenize` 把 COMMENT 换成等长空白（保行号）+ `ast.get_docstring` 把 docstring 行置空。
3. **原本"红着"的复现脚本，改名后不是自然转绿，而是 AttributeError。**
   （"方案 a 会自然转绿、方案 b 不会"—— 这点文档常写错。）
   它的门禁语义要按新现实重写为**三重**：**自证**（故意走裸出口，仍会撞
   `RuntimeError`，证明"为什么必须叫 `_raw_unsafe`"）+ **对照**（走快照无恙）
   + **收口断言**（旧名消失、新名在位）；三者齐备才返回 0。

### 14.4 顺带一定会捞到的"真缺陷"

改名会强迫你逐个读引用点，常见收获是**同型缺陷**。本次：
`AppSSE._get_saved_point` 是 `d.get(code, {}).get(col, "")` 的**无锁两步读**，
而写者持锁且可在两步之间改表 —— 与仓库里另一个 `get_saved_point_time` 的 docstring
（它正是为同一个 check-then-act 窗口而建的**加锁单步出口**）完全同型。
直接改为调用那个既有出口，语义等价（无条目返回 `""`），顺手少一个裸引用。

**规律**：改名时凡看到「两步读同一个共享容器」，先问"仓库里是不是已经有加锁单步出口"——
多半有，而且它当初就是为这个缺陷建的。
