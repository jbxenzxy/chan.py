0. 一句话

把成交统计的记账口径从「仓单级（每笔平今/平昨成交 = 一笔交易）」改为「run 级（每次风控运行 = 一笔交易 = 一对成交：入场 fill + 离场 fill）」，使 R-OPEN 锁仓离场与拆锁的盈亏按信号正确归因；总净盈亏不变（对账恒等式见 §3.1），恢复的是胜率 / 盈亏比 / 平均盈亏 / 最大单笔的"每笔"语义。

1. 背景与问题

1.1 现状（代码证据，评审已逐条核实 26/26）

事实位置
Trade 只有两条写入路径_book_close（Engine.py:1503-1554，save_trade@:1546）；对账补记（Reconcile.py:361-374，reason=reconcile_external_partial）
_book_close 仅在 CLOSE 意图成交时调用Engine.py:1462-1465：if act.intent is OrderIntent.OPEN: _book_open(...) else: _book_close(...)
R-OPEN 锁仓离场走 OPEN 意图Records.py:125："④ 反向开仓锁仓也走它"
锁仓离场成交后只做 toast + run_end，不写 TradeEngine.py:1470-1473（net_before!=0 && net_after==0 分支）
统计面板读 trades 表TradeStats.load_trades_report（TradeStats.py:40+，纯只读 SELECT）

旁证（评审补）：_execute 的 net 变化分支二值互斥（==0→!=0 与 !=0→==0），不存在第三分支——这正是 §3「run 与净敞口一一对应、串行」的代码级保证。

1.2 后果（用户推演 + 今日实盘）

用户例子（IF，第一天 4000 开多 A → 4010 反向开空 B 锁仓；第二天 3990 平昨 A、3970 平昨 B）：
现网会记成两笔 Trade：A 仓 4000→3990（−10 点）、B 仓 4010→3970（+40 点），胜率 50%；而经济上这是"多 4000→4010（+10）+ 空 4010→3970（+30）"两笔全胜的交易。Σ 不变，每笔归因全错。

今日实盘已发生两笔锁仓离场（空 4442.4→4442.6 = −0.2pt、空 4439.8→4442.6 = −2.8pt），trades 表中均无记录；将来拆锁时多仓单会以 4442.6 为 entry 记账，空仓单的真实盈亏永远不会以独立 Trade 出现。

2. 口径勘误（回应讨论 ⑴）

前一轮"配对会计不是没设计过，是被删了"的表述不准确，已更正。
  • origin / lock_pair_id 是给三态判定用的（"现在是不是锁着"），不是给统计用的。Engine.py:244-246 注释明确：曾按"持仓来源标记"判定锁仓——删除原因是"把问题绕复杂的根源"，与统计配对无关。
  • 平仓选仓规则从来就是纯 FIFO：PositionBook.oldest_opposite（PositionBook.py:207-217）——"平仓就是跟持仓序列中反向最早的仓单对冲掉。簿内仓单没有配对概念，只有时间先后"。
  • 结论：统计层从未有过配对会计；run 级会计也不需要恢复 origin / lock_pair_id——run 的入场价 / 离场价直接取成交回报（fill），与"拆锁时选中哪一笔仓单"无关（§6 护栏 [S3] 钉死这一点）。

3. 口径定义（SSOT，唯一权威定义）

一笔 Trade = 一次 run = 恰好一对成交。

概念定义
入场 fill① 空仓态下信号开仓成交（OPEN，开仓档费率）；或 ② 锁仓态下拆锁平仓成交（CLOSE，平昨/平今档费率，不是开仓档）
离场 fill① 今仓离场 = 反向开仓成交（R-OPEN，开仓档）；② 昨仓/两态机离场 = 平仓成交（平昨/平今档）；③ 收盘托管关闭 shutdown_and_lock_all 的强制锁仓成交（reason=auto_order_off；补做重试离场 reason=auto_order_off_retry，见 §7-④）
gross_points(离场 fill 价 − 入场 fill 价) × side.sign
cost_cash入场 fill 手续费 + 离场 fill 手续费，各按自己成交的 offset 档
net_cashgross × 有效乘数 × 手数 − cost_cash
exit_at / reason离场 fill 时点；reason = run 的出场计划与阶段（现状 _run_plan / _phase 已有）；强制离场时 reason 取强平 reason（auto_order_off / auto_order_off_retry），不得回落到 run 计划名

配套不变量（已在现网成立，run 会计依赖它们）：

  • run 与净敞口一一对应、串行：运行态不加仓（Records.py:37——信号门只放行"空仓开仓 / 锁仓拆锁"）；手数 = |net_volume|。
  • run anchor 现状就是入场 fill 价（Engine.py:1468 _run_start(o.filled_price, ...)），拆锁 CLOSE 成交后 net≠0 同样触发 run_start——入场侧数据已齐全，无需新增采集。

3.1 对账恒等式（本设计的正确性锚）

每笔真实成交恰好归属一个 run（开仓 fill 或拆锁 fill = 某 run 的入场；反向开仓 fill 或平仓 fill = 某 run 的离场），因此：

Σ run.net_cash ≡ Σ 全部真实成交的现金流（含全部手续费）

级数裂项相消（telescoping）：前一 run 的离场 fill 价与后一 run 从对侧重新入场的价格，通过锁仓侧仓单的 entry/exit 首尾相接。总额与仓单级严格相等，只有"切刀位置"不同。

成立前提（v3.1 修订，评审 §3.2 + 复审 R2）：恒等式对已完全平仓的成交史成立——无在途 run，且簿内两侧仓单均为空。run 级 Trade 只在 run 结束时才存在，簿级平仓行只在平仓成交时才存在：未全平仓时两侧同为部分和、不保证相等——这不是设计错误，是"每笔归因只在收口时存在"的自然结果。两类未收口形态要分开看：RUNNING 纯持仓态两侧都还没有任何行、恰好同为 0（相等的合法快照——v3"互不相等"的反例，复审 R2）；LOCKED 态 run 已随锁仓 fill 收口（Engine.py:1470-1473 _run_end）而簿内持仓未平，两侧通常不等。[S2] 护栏据此用结构性前提断言（簿内两侧仓单数均为 0）做门禁后再比对数值，不把"数值不等"本身当断言；§8 补产品层提示。

5. 实现草案（只列改动点，本轮不改代码）

5.1 改动点

  1. 把"写 Trade"从 _book_close（仓单事件）挪到 run 结束点：
    • 离场 = 平仓（两态机 / 昨仓）：_book_close 保留"移除仓单 + close 事件"，Trade 改由 run 结算写——entry 取 run 的入场 fill（不是被平仓单自己的 entry_price——拆锁场景下二者不同：被平的 A 仓 entry=4000 是前一天的价，run 入场是平 B 的 p₁）。
    • 离场 = 反向开仓（R-OPEN）：在 Engine.py:1470-1473 分支（net→0 经 OPEN）新增 run 结算写 Trade——这就是本设计要新增的写入点。
    • 离场 = 强制锁仓（shutdown_and_lock_all / on_bar 补做 retry）：同样走 run 结算，reason 取强平 reason。
    • 四个离场路径收敛到一个结算函数 _settle_run(exit_price, offset, reason, at)，防双写（评审 P0；run 结算只在此唯一出口发生）。
  2. run 元数据扩充（_run_start）：现 anchor=fill 已够价；补记 entry 成交的 offset 档与 entry fill 时点。offset 取值无需新增采集（v3，评审 §3.3）：_execute 作用域内已有 act.intent（:1462-1473），offset = INTENT_TO_OFFSET[act.intent] 直接可得。旁证修正（v3.1，复审 R1）：DryRun.py:70/:83 确写 meta["offset"] = INTENT_TO_OFFSET[intent]；SimNow.py:1381 写的 meta["offset"] 实为 action 标签（:1161/:1266 硬编码传 open/close，不含 CLOSETODAY，与 CTP offset 档语义不同），不可当 offset 档旁证。⚠️ 本设计一律以 INTENT_TO_OFFSET[act.intent] 为准、不依赖任何 broker meta；禁止在 Engine 里复制第二份 INTENT_TO_OFFSET 映射（SSOT 仍在 Broker/Base.py:84）；[S5] 对应缩小为"_persist_run 新增字段恢复"。
  3. Fee 计算：cost = 单边费(入场 fill, 入场档) + 单边费(离场 fill, 离场档)。现 state.cost_cash(entry, exit, closetoday) 是双边语义（Instrument.py:424/:458-459），需拆为单边 ×2 或加参；费率档 SSOT 仍在 Instrument/Fee 品种档案，不得出现第二处费率表。
  4. _book_close 的仓单级 gross 事件字段保留（events.jsonl 供对账/回放），但 trades 表不再由它写入。⚠️ close 事件的 trade_id 字段必须一并处理（v3，评审 §3.4）：现状 ev.write("close", ..., trade_id=t.trade_id)（:1552）——run 级后 _book_close 不产 Trade，落点为"run 结算先行、拿到 trade_id 再写 close 事件"（回填），不得留下悬空引用；[S10] 护栏断言 events.jsonl 中每个非空 trade_id 都能在 trades 表命中。
  5. 对账补记（Reconcile.py:361-374）：并入 run 结算（已拍板，§7-②）——删的是 run 对应仓单 → 以对账参考价（ref_price = last_bar.close or pos.entry_price，:339）对该 run 强制结算；删的是锁仓侧仓单 → 不影响 run。不再保留独立的仓单级补记行。⚠️ 结算触发点 = run 对应仓单被删除的那一刻（:337 循环体内），不是两侧循环收尾（v3，评审 §3.5）：对账按 side 逐侧跑，两侧同时被清零时先删的可能是 run 对应仓单，延后统一结算会把时点/参考价算错；[S6] 补"两侧同时清零"用例。
  6. Frontend / main.py 日终打印 / TradeStats 公式：零改动（继续读 trades 表，公式已被 test_trade_stats_formulas 钉住；评审已核实 compute_trade_stats 只读 net_cash）。

8. 坑点备忘

  • 拆锁场景下 _book_close 的 pos.entry_price 不能再当 Trade 的 entry 用（这正是仓单级口径错误的根源）；run 级 entry 一律取 _run_start 的 anchor。
  • run 结算必须只在 run 结束点写一次：锁仓离场 / 平仓 / 对账强平 / shutdown（含 retry）路径全部收敛到 _settle_run 唯一出口，防双写（[S9]+[S7b] 钉住）。
  • by_reason / equity_curve 的时点语义改为离场 fill 时点——与现状 now_cn() 一致；[S1] 断言曲线末值 == total_net。
  • 三态判定 / 选仓 / 报单路径零改动——本设计只动"记账"，不动"执行"（一进一出原则不受影响）。
  • FAK ≡ FOK 是 ExecPolicy 构造期硬断言（Product.py:232-236）——未来若有人放开"FAK + N>1"，既有断言会先拦下；run 会计无需防御性代码。
  • 未全平仓的部分和（v3.1，复审 R2）：RUNNING/LOCKED 态下 Σrun 与 Σ仓单级同为部分和、不保证相等（RUNNING 纯持仓态两侧同为 0 是合法相等快照；LOCKED 态 run 已收口而簿内持仓未平，通常不等）；产品层提示——统计面板"总净盈亏"在锁仓态下天然不含未兑现持仓，与现状一致（现状同样不计），不是回归；恒等式只在全平仓后成立（[S2] 结构性门禁）。
  • 两 broker 的 meta["offset"] 语义不等价（v3.1，复审 R1）：DryRun 写 INTENT_TO_OFFSET[intent]（OPEN/CLOSE/CLOSETODAY），SimNow 写 action 标签（open/close）——任何"读 broker meta 选费率档"的新代码都会在 SimNow 路径静默取错档；本设计主路径 INTENT_TO_OFFSET[act.intent] 天然规避。
