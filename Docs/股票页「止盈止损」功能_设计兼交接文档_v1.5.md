### 0.5 术语与易混点（改代码前必读）

1. **「引擎」必须写全称**（术语护栏 `Trading/Test/test_p26_terminology_guard.py`）：
   **交易引擎** = `Trading/`（期货自动下单）；**缠论引擎** = `Trading/` 之外的 K 线/笔段/买卖点部分。
2. **风控锚 ≠ 会计锚**：期货 `Position.entry_price` 是会计锚（供 pnl 对账），`ExitPlan.params["risk_anchor"]`
   才是风控锚（保本/跟踪/止损全部以它重算）。**股票本次两者都是「买卖点 K 线收盘价」**（见 §2）。
3. **保护价只有一条线**：`ExitPlan.stop_price` 被「初始止损 → 保本价 → 跟踪价」**逐级改写同一个字段**，
   不另立字段（见 `Trading/Strategy/Exit.py` 模块 docstring）。所以需求 ⑸ 的「三条线」在实现上是
   **同一条线在不同时间段的三个取值**；终态后仍是同一条线，只是**离场后末段要继续画到图最右**（§3.8）。
4. **层 / 相位（phase）**：`params` 的 `_phase` 键**初始缺失**（`None`，非空串 `""`，见 `Exit.py:254` 的 `str(get("_phase") or "")`）；归一读法 `str(params.get("_phase") or "") == ""` 表示**初始止损**（P2-2，v1.3 订正），其余为 `breakeven`（保本）/ `trailing`（跟踪）。
   前端标签文案由它派生（期货侧已如此，见 `Frontend/app.js:8576-8578`）。
5. **盈亏比 `win_loss_ratio` 在这套代码里是「进跟踪层的触发阈值」**，不是「跟踪距离」；
   跟踪距离是 `trailing_trigger_r × R`（`Trading/Config.py:310`）。名字与语义历史错位，读代码按语义看。
6. **禁用词**（p26 护栏，新增注释/日志/菜单文案都要过）：腿 / leg / legs / 双仓 / 丢仓 / 腿态 / 挑腿 /
   `open_first` / `unlock_first`。本文与后续代码一律不出现。
7. **终态（outcome）＝ `ExitCheck.reason`**：离场在这套代码里只有**一种**形式 ——
   收盘价跌破当前保护价。`reason` 记的是「被跌破的那条线属于哪一层」，取值**恰好三选一穷举**
   （`Trading/Strategy/Exit.py:241-255` `_phase_reason()`）：
   `sl` = 初始止损线 ⇒ 用户口径的「**已止损**」；`breakeven` = 保本层保护价 ⇒ 「**保本止盈**」；
   `trailing` = 跟踪层保护价 ⇒ 「**跟踪止盈**」。
   ⇒ 需求 ⑸ 的「三监控态 + 两终态」**不需要新增任何状态字段**，只是把 `reason` 暴露给前端（§3.8 有实测）。
8. **代码里没有「涨到止盈价就止盈」这个事件**（**Q12 已确认**，非待确认）：名义止盈价
   `params["_tp_nominal"]` = 入场价 ± 盈亏比×R **只写进计划快照供事后对照，不落单、不参与触发**
   （`Exit.py:388-390`、`:403`）。行情涨到 2R 只是**启动跟踪层**，离场仍要等收盘价跌破保护价。
   用户提到的「止盈」在实现上就是「**在保本层 / 跟踪层被保护价扫出局**」——止盈**只有保本、跟踪两个出口**，
   不存在「到 2R 即离场」的第三条规则。
9. **卖点推演 = 对称做空（Q2 已采纳）**：`side = 'long' if bsp.is_buy else 'short'`（此为**序列化/响应**约定；后端计算盈亏符号用 `sig.side.value`，勿用此字符串比较，见 P2-3/§4.2），
   算法与期货 L1-L3 **完全一致、零分支**。A 股不能融券只影响「能否真实下空单」，不影响「图上推演」的性质
   （推演本就不下单，见 §8-S8）。
10. **ATR 用的是 True Range，不是简单高低差（回答 Q5 的「跳空」疑问）**：
   单根 True Range `TR = max(H − L, |H − C_prev|, |L − C_prev|)`，ATR 是 TR 的均值。
   后两项 `|H − C_prev|`、`|L − C_prev|` **就是跳空效应**——若当日跳空高开，`high` 与昨收 `C_prev` 的差距
   会直接放大 TR，进而放大 ATR。所以「跳空」确实进 ATR，并非只算 `H − L`。
   原期货「跨日清空 `_bars`」会把隔夜跳空这段 TR 丢掉；**移除后，日线 ATR 自然包含隔夜跳空**，正是要的口径。

## §2 股票 vs 期货：逐条口径对照表

| 维度 | 期货（现状） | 股票（本次新增） | 差异落在哪 |
|---|---|---|---|
| 入场价（风控锚） | **实际成交价**（CTP 明细加权均价） | **买卖点所在 K 线的收盘价**（买点、卖点同此） | 只差 `plan()` 的入参；`Signal.price` 本身就是「信号 K 线收盘价」（`Records.py:174`） |
| 会计锚 | 同成交价 | 同收盘价 | 股票两者同值 |
| 持仓方向 | `Signal.side`（由 `is_buy` 派生） | `side = 'long' if is_buy else 'short'`（**对称做空，零分支**，Q2；此为响应/序列化约定，后端盈亏符号用 `sig.side.value`，P2-3） | 推演性质，A 股不能融券不影响（§8-S8） |
| 1R | `R = max(A, B)`，A=分型距离，B=2×ATR14 | **同**（`Exit.py:346`、`Config.py:305`） | 零差异；**Q5 移除跨日清空后日/周/30m 下 B 也可就绪**（§3.5） |
| 保本 | 浮盈 > 1R → 保护价 = 锚 ± 0.5R | **同**（`Config.py:308-309`） | 零差异 |
| 跟踪缓冲 | `0.5 × R` | **同**（`Config.py:310`） | 零差异 |
| 盈亏比（进跟踪层阈值） | 品种档案 `Product.win_loss_ratio`（现全品种 2.0） | **固定 2:1**，不随品种/环境变（Q8 不跟 `.env`） | 用 `ExitPolicyParams` 的模型默认值（`Config.py:359`），**不走品种档案** |
| 价格对齐（tick） | 品种档案 `price_tick`，保守取整 | **不做 tick 对齐**（Q6）：推演价均来自收盘价，无成交撮合/四舍五入 | `Instrument(product=None)` 的 `round_price` 原样返回（§3.4）正好适用 |
| 判定节奏 | 实时逐根 bar 闭合 | **全序列一次性推演**（历史 K 线已闭合） | 同一份 `check()`，只是驱动方式不同 |
| 买卖点类型 | — | **仅 0123 类**（Q3）：同根 K 线不可能出现多个买卖点 | 前端命中判定无需多选（§4.2/§4.6） |
| 是否报单 | 是（CTP） | **否**（纯图上推演，不接任何下单/持久化通道） | 边界，见 §8-S8 |

**一句话**：需求 ⑴-⑷ 里只有 **入场价的来源** 和 **盈亏比的来源** 两项与期货不同（Q2 的卖点只是把同一套
算法套到 `short` 方向），且都是「入参不同」，**不是「算法不同」**——这正是 §5 主张**复用
`Trading/Strategy/Exit.py`** 的直接依据。

### 3.5 ⚠️ 两个必须先知道的坑

**坑 1：股票 bsp 缺 `fractal_low` / `fractal_high`（R 的 A 分量拿不到）**

- 期货路径 `App/AppSSE.py:1397-1407` 输出了：`f_klu = bsp.bi.get_end_klu()` → `fractal_low = f_klu.low`、`fractal_high = f_klu.high`。

- 可达性：**必然可达**（任何股票分析请求都走这两处），不是偶发。
- 影响：不补字段 ⇒ A 恒 0；若届时 ATR 也未就绪（见坑 2）⇒ `R = 0`，L3 整层失效、退化到「入场价外 1 tick」。

  **Q3 不改变此坑**：补字段对所有 bsp 类型都必要，0123 类只是交互上同根无多点。

**坑 2：ATR 缓冲跨日清空 ⇒ 股票日线/周线/30m 下 2×ATR 不可用（Q5 已决策：移除清空）**

- 机制（**待移除**）：`Exit.on_bar` 每遇 `date[:10]` 变化就 `_bars.clear()`（`:199-201`），而 ATR 需要连续
  `atr_period+1 = 15` 根（`:209`）。

| 股票周期 | 每日 bar 数 | 移除前 ATR | 移除后 ATR（Q5 后） |
|---|---|---|---|
| `d`（日线） | 1 | 恒不可用 | **可用**（跨日连续，含隔夜跳空，见 §0.5-10） |

```
         └─ 再次右键同根 K 线 → 菜单变「取消盈损」→ 清 sltpPlan → render()
```

三条设计取舍（理由见 §4.4 / §5）：

1. **口径复用**：不重写 L1-L3，只组装 `Trading` 的三个数据结构去调 `plan()` / `check()`。
2. **payload 自包含**：K 线由前端回传，后端不重跑缠论分析、不依赖分析缓存 ⇒ 复盘 / 选点 / 双窗 / 前复权
   状态下的数据天然与屏幕上一致（若后端自己取数，还要处理 `end_date` 复盘、选点 `date_suffix` 缓存键，易漂）。
3. **纯推演、零副作用**：不写盘、不进 `state.db`、不接告警/toast 通道、不下单（§8-S8）。

### 4.2 数据契约

**请求** `POST /api/stocks/{code}/sltp`

```json
{
  "code": "sh600519",
  "freq": "d",
  "klines": [ { "date": "2026-01-05", "timestamp": 1767600000000,
                "open": 10.0, "high": 10.3, "low": 9.8, "close": 10.1 }, "…" ],
  "bsp": { "date": "2026-01-05", "type": "1", "is_buy": true,
           "price": 10.1, "high": 10.3, "low": 9.8,
           "fractal_low": 9.1, "fractal_high": 10.8 }
}
```

- `klines`：从 `max(0, idx-60)` 到末尾（60 = ATR 预热窗口，覆盖 `atr_period+1=15`）。
  日线 500 根 ≈ 数十 KB，可接受；后端另设上限（建议 2000 根，超出 400）。
- `bsp`：前端从 `chartData.bsps` 里按 `date` 命中取。**Q3 约束（v1.3 修订，P1-1）**：`type` 是**复合串**（`BS_Point.type` 为 list、`type2str()` 以逗号拼接，如 `"1,11"`），并非单值。
  命中判定 = `type2str().split(",")` 取各分量的 `main_type()`（`Common/CEnum.py`，`.rstrip('psab')`）∈ `{0,1,2,3}` 即命中（只认字面 `0/1/2/3`，排除 `11p/22/33a` 等"原 1/2/3 类变体"）；
  例：`"1,11"` → 分量 `1`/`11` → `main_type` `1`/`11` → 命中 `1` ⇒ 显示菜单；纯 `"11"` → 不命中 ⇒ 不显示。
  **同根多对象**：`add_another_bsp_prop`（`BuySellPoint/BS_Point.py:46-49`）会把 11 类等挂到同一 klu，故"同一根 K 线上可有多个买卖点对象"是可达的；
  **归一 + 取首发生在前端（N1 决议，采用方案 b）**：前端在 `chartData.bsps` 中按 `date` 过滤出 `main_type()∈{0,1,2,3}` 的候选，**取数组首个 + `console.warn`（可见、可排查）**；请求契约 `bsp` 仍送**单个对象**，后端只校验这唯一对象（不重做"多对象取首"）。同根不做多选交互。
- 校验（`AppErrors` 语义，4xx 而非静默 200）：非股票 market、`klines` 为空、`bsp.date` 在 `klines` 中找不到、
  `bsp` 缺 `fractal_*`（`AppEngine` 已补，仍做兜底校验）、`is_buy` 缺失、**`type` 经上述 main_type 归一后无分量 ∈ {0,1,2,3}** ⇒ 一律 `BadRequestError`。

**响应**

```json
{
  "ok": true,
  "entry": { "date": "2026-01-05", "price": 10.1, "side": "long" },
  "r": 1.0, "a": 1.0, "b": 0.0, "atr": null,
  "segments": [
    { "phase": "sl",        "price": 9.10,  "start_date": "2026-01-05", "end_date": "2026-01-09" },
    { "phase": "breakeven", "price": 10.60, "start_date": "2026-01-10", "end_date": "2026-01-19" },
    { "phase": "trailing",  "price": 11.55, "start_date": "2026-01-20", "end_date": "2026-03-20",
      "terminal": true }
  ],
  "current": { "phase": "trailing", "price": 11.55, "as_of": "2026-02-02" },
  "exit": { "date": "2026-02-03", "price": 11.55, "fill": 11.50,
            "reason": "trailing", "outcome": "trail_exit", "r_multiple": 1.50 },
  "terminal": { "phase": "trailing", "price": 11.55, "outcome": "trail_exit",
                "exit_date": "2026-02-03", "end_date": "2026-03-20" },
  "params": { "win_loss_ratio": 2.0, "breakeven_trigger_r": 1.0,
              "breakeven_buffer_r": 0.5, "trailing_trigger_r": 0.5,
              "atr_sl_multiple": 2.0, "atr_period": 14 }

```

- `side`：`"long"`（买点）/ `"short"`（卖点，Q2 对称做空）。**注意（P2-3，v1.3 订正）**：此 `side` 字段是**序列化字符串**，仅用于前端展示/判定；
  **后端计算盈亏符号一律用 `sig.side.value`（`Side` 枚举，`LONG=1`/`SHORT=-1`，见 `Records.py:60-63`、`:182`），切勿拿字符串 `'long'/'short'` 与 `Signal.side`（枚举）比较**，否则符号必走反分支。
- `phase` ∈ `sl` / `breakeven` / `trailing`（与 `ExitPlan.params["_phase"]` 一一对应，**`"_phase"` 键缺失或 `""` 均映射为 `sl`**，读法 `str(params.get("_phase") or "")`，P2-2 订正）。
- `exit`：收盘价穿越保护价时给出；未穿越为 `null`。
  - `reason` = `ExitCheck.reason` 原值（`sl` / `breakeven` / `trailing`），保留原值便于与交易引擎日志对齐；
  - `outcome` = 业务名（`sl_exit` / `be_exit` / `trail_exit`），**前端标签直接读它**（映射见 §3.8 表）；
  - `fill` = `ExitCheck.fill_price`（收盘价），`r_multiple` = 离场盈亏 ÷ R（**可为负**，见 §3.8-T2）。
- **`terminal`（v1.1）= 终态段的投影，即「离场后仍要画的那一条线」**：
  `phase` / `price` = 触发离场的那条保护价所属层与价位；`end_date` = **K 线序列最后一根**
  （不是离场那根）⇒ 线一直画到图最右侧，满足需求「已止损时**仍**在止损位画横虚线」（Q10 已采纳）。
  未离场时 `terminal` 为 `null`，此时最后一段即 `current`（仍在监控中）。
- `segments` 末段在离场时带 `"terminal": true`，其 `end_date` 同样延到末根（与 `terminal` 同价位、同层）。
- `params` 回显用于前端 tooltip 与事后对照（照抄期货「计划快照落盘」的既有思路）。

### 4.3 逐根推演算法（后端，`App/AppTPSL.py`）

```
1  校验（见 §4.2；含 type 复合归一 + main_type()∈{0,1,2,3} 校验，Q3/P1-1）
2  sig  = Signal.from_bsp(bsp, symbol=code, freq=freq)   # side 由 is_buy 派生（Side 枚举）；卖点→SHORT（Q2 零分支）；盈亏符号用 sig.side.value（P2-3）
3  inst = Instrument(product=None)                       # 不 tick 对齐（Q6）；round_price 原样返回
4  pol  = LayeredExitPolicy({})                          # 空 dict⇒取 ExitPolicyParams 模型默认（含 win_loss_ratio=2.0，Q8 不跟 .env）
                                                          # 注：Q5 后 Exit.py 已无跨日清空，故无需 App 侧子类覆写 on_bar
5  entry_idx = klines 中 date == bsp.date 的下标
   断言 abs(klines[entry_idx].close - sig.price) < eps   ← 需求⑴：入场价 = 该根收盘价
6  预热：for b in klines[max(0, entry_idx-60) .. entry_idx]: pol.on_bar(b, inst)
7  plan = pol.plan(sig, sig.price, inst)      ← 第三参实名 `state`（Exit.py:361，即 `def plan(self, signal, entry_price, state, ...)` 签名行），按位置传参；不传 anchor ⇒ base = 入场收盘价（Exit.py:370）。（原 `plan(sig, entry_price=sig.price, inst)` 为非法：关键字实参后跟位置实参 = SyntaxError，且参数名 `inst` 错，P1-2 订正；`:363` 系 docstring 行，已订正为签名行 `:361`，N2）
8  pos  = Position(symbol, side=sig.side, volume=1, entry_price=sig.price, entry_at="",
                   entry_bar_ts=klines[entry_idx].timestamp, signal_key=sig.key,
                   open_order_id="", exit_plan=plan)
9  for b in klines[entry_idx+1:]:                          ← 入场那根不判（与 Engine.py:819 同口径）
       pol.on_bar(b, inst)
       chk = pol.check(pos, b, inst)
       if chk is None: continue
       若 chk.plan 非空：先记"段切换"（新 stop_price / phase）   ← 先抬价再判触发的因果链
       if not chk.only_update:                               ← v1.1：终态分支
           sign = sig.side.value   # Side 枚举，LONG=1/SHORT=-1（P2-3：符号从枚举取，勿用 'long'/'short' 字符串）
           exit = {date: b.date, price: chk.price, fill: chk.fill_price,
                   reason: chk.reason, outcome: <reason→业务名>,
                   r_multiple: (chk.fill_price − entry) × sign ÷ R}
           末段标 terminal=true，end_date = klines[-1].date    ← 线画到图最右（需求 ⑸ 的"仍"）
           terminal = {phase: <离场时的层>, price: chk.price, outcome: …,
                       exit_date: b.date, end_date: klines[-1].date}
           break                                              ← 离场后不再推演（已无持仓）
       pos.exit_plan = chk.plan
10 收尾：未离场时最后一段 end_date = 最后一根 date；current = 末段；terminal = null
```

要点对齐（都是**沿用期货现有口径**，不是新发明）：

- 入场那根不参与出场判定（`Engine.py:819` `bar.timestamp <= run.entry_bar_ts: return`）。
- 「先抬价、再判触发」：`check()` 返回的 `plan` 可能非空**且**触发离场，`plan` 必须先落（段切换）再记离场，
  否则「因进保本/跟踪而离场」的因果链断掉（`Exit.py:124-127` 明确要求）。
- 触发价 = 保护价、成交参考价 = 该根收盘价（`ExitCheck.fill_price`）；推演里用它记 `exit.price`。
- `Position` 用「虚拟仓单」写法，与交易引擎 `_run_view()`（`Engine.py:1875-1887`）同一手法，不进任何账本。
- **Q2**：卖点只改变 `side='short'`，`plan()`/`check()` 内部对多空完全对称（L1-L3 无方向分支），故零额外代码。
- **Q3（v1.3 修订，P1-1；v1.4 按 N1 方案 b 收口）**：`type` 经 `main_type()` 归一后命中 `{0,1,2,3}` 即视为该买卖点对象"有效"，步骤 2 的 `from_bsp` 对**单个命中对象**取到的必是唯一方向，无需分支；同根多对象（不同 BS_Point 同根）的**取首 + `console.warn` 在前端完成**（前端持有完整 `chartData.bsps`，可取首并可观测），后端只校验前端送来的那一个 bsp，不在后端做多选或静默取舍。

## §5 ⑹ 落位分析：App/ 新写 还是 借用 Trading/ ？（含结论与理由）

### 5.1 三个候选方案

### 5.2 结论

**采用方案 B：口径借用 `Trading/Strategy/Exit.py`，新增代码全部落在 `App/`（+ `Frontend/` + `Test/`）；

### 5.3 理由（五条，逐条可核）

1. **SSOT**：`R = max(A, 2ATR)`、保本 ± 0.5R、跟踪 0.5R、严格不等边界、先抬价再判触发 —— 需求 ⑵⑶⑷ 要的
   正是这套口径，代码里只有 `Exit.py` 一份（`Exit.py:346 / 485-490 / 494-500 / 527-532`）。
2. **护栏免费继承**：`test_p61`（AST 钉时序与 high/low 白名单）、`test_p62`（保护价投影）、
   `test_p63`（文档不复述档位数值）继续有效；股票侧只需测「适配层组装」与「分段轨迹」。
3. **依赖方向合法**：`Trading/README.md:37` / `:190` 与 `Trading/__init__.py` 的层表写的是
   `Infra ← (Source/Strategy/Broker/Risk) ← Engine ← App`，**App 在最上层**，`App → Strategy` 是顺向调用。
   既有 `App/AppTrader.py` 已 import `Trading.Infra.*` 与 `Trading.Config`（共 11 处惰性 import），
   本次只是**同方向多跨一层**（到 Strategy），不产生反向边。
4. **不碰状态机**：只用 `plan()` / `check()` 两个**纯计算**入口，不 import `Engine` / `Broker` /
   `PositionBook` / `StateDB`，因此不触碰「生产代码任何模块不得反向 import Engine，装配只在 `main.py`」

   不影响正在跑的期货自动下单。
