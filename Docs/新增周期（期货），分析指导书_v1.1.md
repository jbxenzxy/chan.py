## 0. 结论先行

1. **期指不是独立市场，不需要单开一套周期集。** 全仓不存在 `INDEX_FUTURES` / 股指专用周期集合；`CFFEX.IF/IH/IC/IM` 与商品期货共用 `Common/CEnum.py` 的 `FUTURES_FREQS`，别名表 `DataAPI/TqSdkAPI.py : FUTURES_ALIASES` 已含四家期指。**加一次 = 期货和期指同时生效**，不存在"分别改两处"。
2. **15m 在期货上不是"新增周期"，而是"开放市场位 + 补一条回看配置 + 一条区间套映射"。** 客观属性层（`FREQ_TABLE`、秒数、KL_TYPE、中文标签、`FREQ_TO_COL` 选点列、前端 `FREQ_SEC_MAP_JS` / `freqLevel` / `freqLabel` / `INTRADAY_FREQS_JS`）**全部已含 15m**——股票那条线早把它建好了。真正缺的是下面 5 个点。
3. **风险不在"漏改文件"，而在 5 处静默降级**。改漏了不会报错，只会让 15m 的图能看、判定错：

| # | 静默降级点 | 触发条件 | 后果 | 现有测试能否守住 |
|---|---|---|---|---|
| 1 | `BSPointList._FUTURES_SUB_FREQ_MAP` 缺 `'15m'` | 15m 作上窗 | `sub_freq=None` → 缓存键 `SYMBOL:None` → 区间套直接 `return True`（判背驰=放行），买卖点失去区间套过滤 | ❌ 完全无守卫 |
| 2 | `AppConfig._FIELD_DEFAULTS["FUTURES_LOOKBACK_CONFIG"]` 缺 `'15m'` | 15m 单窗/双窗默认窗口 | `resolve_lookback_bars` 回退 300 根（≈18.75 个交易日），笔段/中枢样本不足，且**不报错** | ❌ 守卫是子集方向（`keys ⊆ FUTURES_FREQS`），缺 key 不红 |
| 3 | `TqSdkAPI.SUPPORTED_FREQS` 是**手写字面量**，不是从 `FUTURES_FREQS` 派生 | 只改 CEnum | 门禁 `test_15m_period` 红（集合+顺序双断言） | ✅ 会红 |
| 4 | 前端 `updateFreqButtonStates` 的 `SHOW` 映射 + 两处 `disabled` 硬覆盖 | 只改后端 | 按钮根本不出现（`display:none`），用户以为没生效 | ❌ 无守卫 |
| 5 | `AppSSE._sse_dual_gen` 的 `_FUTURES_DUAL_FREQ_MAP.get(main_freq, "15s")` | 上窗周期未登记在该表 | 下窗**静默变成 15s**（15m 上窗 900s → 下窗 15s，差 60 倍） | ❌ 无守卫 |

> 注：现状下前端双窗总会显式带 `sub_freq`（`connectRealtimeDual` 拼 `&sub_freq=`），所以第 5 条要在"直接调接口/新调用方漏传"时才踩到；但它是个把错误变成静默的兜底，值得一并收掉。

**改动面估算（v1.1 按裁决重算）**：后端 7 处（`FUTURES_FREQS` + `SUPPORTED_FREQS` 字面量 + 回看 1 条 + `_FUTURES_SUB_FREQ_MAP` 1 条 + 显式下窗透传读侧 + `_FUTURES_DUAL_PAIRS`/`_validate_futures_dual_pair`/默认解析收口 + 路由 400）；前端 6 处（`FUTURES_DUAL_PAIRS_JS` + `isValidFuturesDualPair` + `SHOW` + `btn-15m.disabled` + 双窗期货焦点分支 + `switchFreq` 两处校验/`updateDualBtn`）；Trading 3 处（`FREQ_SEC` / `PERIOD_PROFILES` / 对账测试）；测试 5 处断言。**Trading 已裁决跟进**（见 §7.4）。

## 2. 为什么不能照抄股票指导书（6 处结构差异）

| 维度 | 股票（v1.4 指导书的世界） | 期货（本文的世界） |
|---|---|---|
| 分析入口 | `AppEngine.analyze_stock`（REST），期货代码直接拒绝 | `AppSSE.sse_futures_stream_single/dual`（SSE 长连接），不走 REST |
| 取数路径 | 本地通达信文件：`.day` / `.lc5` / `.lc1`，要写 `read_main_level_records` 分支 | 天勤 `get_kline_serial(symbol, freq_sec, num_bars)`，**15m 无需新取数分支**，`FREQ_SEC_MAP` 已能给出 900 |
| 双窗配对空间 | 显式白名单 `_STOCKS_DUAL_PAIRS` + `_validate_stock_dual_pair` 显式拒绝 | **无白名单**；前端只做 `freqLevel(sub) < freqLevel(main)` 的"严格更小"比较，后端不校验 |
| 区间套子级别来源 | `_STOCKS_SUB_FREQ_MAP` **+ 显式 `chan._stocks_dual_sub_freq` 优先**（三套映射统一：显式传入优先） | `_FUTURES_SUB_FREQ_MAP` 静态一对一，**无显式透传机制** |
| 回看配置缺失 | 缺 key → `if freq in STOCKS_LOOKBACK_CONFIG` 不成立 → **不截断（全量）**，缺 key 是"更宽松"，无害 | 缺 key → `resolve_lookback_bars` 固定回退 **300 根**（常量，不按周期），是"更少"，有害且静默 |
| 守卫覆盖 | `test_market_freq_partition` 跨语言校验 levels + 回看 keys + 主周期时长 | 只覆盖集合/顺序；**缺 key、缺区间套映射、前端按钮三处都不守** |

**一句话**：股票那条"显式 sub_freq 优先"的机制（`_stocks_dual_sub_freq`）是股票双窗能支持 6 对配对的根本原因；**期货分支没有这个机制**，区间套只认一张静态表。所以"期货也能手工选 15m"这件事，难点不在按钮，而在区间套。

### 3.2 P0-3 的根数怎么定（算术，别拍脑袋）

| 方案 | 根数 | 覆盖时长（期指 4h/日） | 与现有配置的关系 |
|---|---|---|---|
| A. 与股票 15m 同值 | 960 | 960×15min=240h ≈ **60 交易日 ≈ 3 个月** | 与 `STOCKS_LOOKBACK_CONFIG["15m"]=(960,"近3个月")` 对齐，跨市场同名值可解释 |
| B. 与 30m 同历史跨度 | 1600 | 1600×15min=400h ≈ **100 交易日 ≈ 5 个月** | 800×30min 正好 400h，与 `"30m": (800, "近5个月")` 等跨度 |
| C. 不配（现状） | 300 | 75h ≈ **18.75 交易日** | 静默，且 `label` 都没得显示 |

- 推荐 **A（960，"近3个月"）**：与股票 15m 同值，维护者一眼能对上；若你的使用习惯是"15m 要和 30m 看一样长的历史"，选 B。
- **运维坑**：`_FIELD_TYPES["FUTURES_LOOKBACK_CONFIG"]` 允许用环境变量整份覆盖（`_env_lookback_dict`，JSON 解析后**整体替换**，不是合并）。线上 `.env` 里若写死了旧的 4 个 key，**即使代码默认值加了 15m，运行时仍是缺 key → 300 根**。改完要同步 `.env` 或删掉该覆盖项。
- `FULL_DATA_MODE=True` 时跳过截断，此坑不显形——别用它来"验证配置生效"。

## 4. 双窗口专项（你点名的这一块）

### 4.1 默认配对：按你的要求**保持不变**

| 上窗 | 默认下窗 | 落点 |
|---|---|---|
| 30m | 5m | `_FUTURES_DUAL_FREQ_MAP`（不改）、`getDualSubFreq('30m')`（已返回 5m） |
| 5m | 1m | 同上 |
| 1m | 15s | 同上 |
| **15m** | **5m（新增默认）** | `getDualSubFreq('15m')` **已经返回 `'5m'`**（股票分支先命中）；`_FUTURES_DUAL_FREQ_MAP` 是否登记 15m 只影响"调用方漏传 sub_freq"的场景 |

> 结论：既有三行默认配对（30m→5m、5m→1m、1m→15s）**一行都不用改**，15m→5m 在前端已经"免费"存在；要补的是 `_FUTURES_SUB_FREQ_MAP['15m']`（区间套），以及决定 `_FUTURES_DUAL_FREQ_MAP` 是否登记（建议登记——只新增一行，不动既有三行，让默认值与兜底一致）。

### 4.2 手工可选配对矩阵

| 上窗 | 现状可选下窗 | 加 15m 后可选 | 区间套实际用的子级别（现状语义） |
|---|---|---|---|
| 30m | 5m / 1m / 15s（前端只挡 level） | **15m** / 5m / 1m / 15s | 恒 `5m`（`_FUTURES_SUB_FREQ_MAP['30m']`） |
| **15m** | —（周期未开放） | **5m / 1m / 15s** | **`None` → 静默放行**（P0-5 修好后恒 `5m`） |
| 5m | 1m / 15s | 1m / 15s | 恒 `1m` |
| 1m | 15s | 15s | 恒 `15s` |
| 15s | 无（最小周期） | 无 | — |

### 4.3 核心风险：区间套只认默认配对（**既存缺口，不是 15m 引入**）

`check_nesting_divergence` 的期货分支从静态表推 `sub_freq`，再用 `make_futures_sub_key(symbol, sub_freq)`（键形如 `SYMBOL:sub_freq`）经 `AppData.futures_sub_chan_guarded_by_key` 取**活 CChan**：

- **路径 A（错误级别）**：上窗 30m + 手工下窗 15m → 静态表仍给 `5m` → 本次连接只建了 15m 下窗 → 5m 缓存 miss → `return True`（判背驰=放行）。
- **路径 B（更隐蔽）**：若同品种的 5m 下窗缓存**还在**（另一个标签页开着 30m/5m，或 LRU 未淘汰）→ 拿**上一场的 5m CChan** 去判**当前 15m 下窗**的背驰 → 结论错但不报错。
- **路径 C（15m 作上窗，P0-5 未修）**：`sub_freq=None` → 键 `SYMBOL:None` → 必然 miss → 恒定放行。

**既存事实**：今天 `30m+1m`、`30m+15s`、`5m+15s` 三组手工配对**已经**落在路径 A/B 上。也就是说，"手工改配对"这个能力本身在期货侧就没有区间套支撑，15m 只是第四组。改造前需要明确：

| 方案 | 做法 | 代价 |
|---|---|---|
| ①保持现状（静态表） | 只加 `'15m':'5m'`，其余不动 | 默认配对正确；**手工配对仍退化**，只是从静默变"可解释" |
| ②对齐股票（推荐） | 建上窗 CChan 时把实际 `sub_freq` 挂上去（股票是 `chan._stocks_dual_sub_freq`），区间套优先读显式值 | 要动 `AppSSE` 建链与 `BSPointList` 期货分支，属行为变更，需回归双窗用例 |
| ③最小安全兜底 | 缓存 miss 时由 `return True`（放行）改为 `return False`（不放行）+ 显式日志 | 一行改动，但会改变"上/下窗有时序差"时的既有表现，需实测 |

> ②与③不互斥：②解决"配错级别"，③解决"没数据时别默认放行"。若只做①，请把"手工配对时区间套按默认配对判定"写进用户可见的说明，否则这坑迟早被当成 bug 报。

### 4.4 红框与背驰口径不一致（同一现象的两个来源）

- **红框**（`_futures_red_range`）用的是**实际** `main_freq_sec` / `sub_freq_sec` / `sub_freq`——手工选 30m/15m 时红框按 15m 算，是对的。
- **背驰**（`check_nesting_divergence`）用的是**静态表**——同一组 30m/15m 按 5m 算。
- 表现：红框画在 15m 上、背驰按 5m 判（或直接放行）。**"红框对、买卖点不对"** 这类反馈的根因就在这里，排查时先看这条。

### 4.5 双窗入口（`updateDualBtn`）

期货 `disabled = (currentFreq === '15s')`，股票 `disabled = (currentFreq === '15m' || currentFreq === '5m')`。加 15m 后：
- 期货单窗 15m **自动可以**进双窗（默认 15m/5m）；
- 股票不允许 15m/5m 进双窗（既有产品口径，`test_dual_consistency` 有断言钉着）。

两市场口径不同，**不要"顺手对齐"**——股票那条是用户明确定的"单窗 15m/5m 灰化"，期货这条是"除 15s 外都能进"。要么维持差异，要么显式改股票那条并同步改测试，别让两边悄悄漂移。

## 5. 期指 vs 商品期货：差异只在日历，不在周期集

### 5.1 事实

| 检查项 | 结论 |
|---|---|
| 是否存在股指专用周期集 / 市场标识 | ❌ 全仓 grep 无 `INDEX_FUTURES` 一类独立集合、也没有按市场分叉的周期白名单；期指走 `FUTURES_FREQS` |
| 期指代码怎么进系统 | `FUTURES_ALIASES` 里 `IF/IH/IC/IM → KQ.m@CFFEX.*`；`isFutures` 判据在 `Frontend/app.js : isFuturesCode`（全站唯一） |
| 期指有什么专属逻辑 | 只有**合约日历**：`AppSSE._CFFEX_*`（第三周五交割、季月挂牌、换月窗口）——与周期无关 |
| 加 15m 要不要为期指单独改 | ❌ 不需要。期指自动获得，无需第二套配置 |

### 5.2 差异（只影响"根数/时段"，不影响"周期开关"）

| 品种组 | 交易时段 | 15m 根/日 |
|---|---|---|
| 期指 IF/IH/IC/IM | 9:30–11:30 + 13:00–15:00 = 4h | **16** |
| 国债 T/TF/TS/TL（同 CFFEX） | 9:30–11:30 + 13:00–15:15 = 4.25h | 17 |
| 商品含夜盘（如 rb：21:00–23:00 + 日盘 3.75h） | 5.75h | 23 |
| `Trading/Infra/Clock.py : SESSION_SECS` 近似值 | 4.5h（全局单一常量） | 18 |

- `SESSION_SECS = 4.5h` 是**全市场近似**，对期指 4h 偏高 12.5%。它只用于 `main.py` 启动横幅的"约 N 根/交易日"和 ATR 样本充足性粗算——**看图不受影响，接自动下单才需正视**。
- 因此"15m 回看根数"不能用一套值拍死所有品种：同一根数在期指上是 16 根/日、商品上是 23 根/日，跨品种的"看了几天"差 1.4 倍。P0-3 的 `label` 建议写"近3个月"这类**日历语义**，别写"N 个交易日"。

### 5.3 期指 15m 的两个使用特性（不是缺陷，但会被当成缺陷）

1. **换月跳空更显眼**：`KQ.m@CFFEX.IF` 是主力连续，同一次换月跳空在 15m 上横跨约 2 倍根数（同一次缺口 30m 占 1 根、15m 占 2 根），视觉上更刺眼。这是数据源语义（不复权），不是新增周期引入的问题。
2. **无夜盘 ⇒ 每日 K 线不连续**：15m 序列在 15:00 与次日 9:30 之间是断的。灰框/红框的边界推算走**相邻 K 线序**（不是墙钟连续），所以跨收盘段时"右边界 = 下一根时间 − sub_sec"会外扩到下一交易日开盘前，其区间内取不到下窗 K 线 → 呈现为空框。这是既存行为（30m 在 15:00 那根同样如此），与周期无关；但任何新写的"按根数推时间"逻辑不能假设 `15m × 16 = 一天`。

## 7. 已裁决（2026-11-23）+ 落地设计

> 裁决原则：**能跟股票一套逻辑的就一套逻辑**，两市场共用同一心智模型。下表 5 条对应 v1.0 的 5 个待裁决项；唯一不照抄的地方是期货 5m，理由在 §7.3 单列。

### 7.0 裁决总表

| # | 原待裁决项 | 裁决 | 落地形态 |
|---|---|---|---|
| ⑴ | 区间套配错级别 | **与股票一致**：显式下窗优先；单窗 15m 不进双窗，进双窗后上下窗手工可选 | 期货上窗 CChan 挂 `_futures_dual_sub_freq`，`check_nesting_divergence` 期货分支读它（与股票 `_stocks_dual_sub_freq` 同构） |
| ⑵ | 期货显式配对白名单 | **与股票一致**（显式表 + 显式报错，不做静默降级） | 后端 `_FUTURES_DUAL_PAIRS` + `_validate_futures_dual_pair`；前端 `FUTURES_DUAL_PAIRS_JS` + `isValidFuturesDualPair` |
| ⑶ | 单窗 15m 进双窗 | **与股票一致：禁** | `updateDualBtn` 期货分支加 `'15m'`；**5m 例外保留**（唯一偏离，见 §7.3） |
| ⑷ | Trading 网关跟进 15m | **跟进** | `Period.FREQ_SEC` + `"15m": 900`、`PERIOD_PROFILES` 加档、修哑护栏 import、对账断言 4→5 |
| ⑸ | 15m 回看根数 | **960**（与股票 15m 同值，"近3个月"） | `FUTURES_LOOKBACK_CONFIG["15m"] = (960, "近3个月")` |

### 7.1 期货双窗配对白名单（显式，同股票口径）

```python
# App/AppSSE.py，紧邻 _FUTURES_DUAL_FREQ_MAP —— 上窗 → 可选下窗集合
_FUTURES_DUAL_PAIRS = {
    "30m": {"15m", "5m", "1m", "15s"},
    "15m": {"5m", "1m", "15s"},
    "5m":  {"1m", "15s"},
    "1m":  {"15s"},
    # 15s 为期货最小周期，无下窗可选（与股票 5m 同语义）
}
```

- **与现状等价**：现在的规则就是"`freqLevel` 严格更小即可"，本表只是把它写死。改成显式表不新增、也不削减任何可选组合 ⇒ 零行为变更，换来的是可报错、可对账。
- `_validate_futures_dual_pair(freq, sub_freq)` **与 `_validate_stock_dual_pair` 同签名同返回**（`None`=合法，字符串=非法原因，调用方转 4xx）。照抄而非抽象基类：两市场本就隔离，合并会引入"期货路由 import 股票模块"的反向依赖。
- **拒绝点**：`FrontAPI.py` 的期货双窗路由（`dual=1` 分支，`sse_futures_stream_dual` 之前）校验，非法 → `HTTPException(400, detail=...)`，与股票 `AppEngine` 的 4xx 一致。
- **默认解析收口**：新增 `_resolve_futures_dual_sub_freq(main_freq, sub_freq)`（= `sub_freq or _FUTURES_DUAL_FREQ_MAP.get(main_freq)`），路由与 `_sse_dual_gen` 共用。眼下默认值在 `_sse_dual_gen` 里写了一次 `.get(main_freq, "15s")`，路由若要校验就会写第二遍——收口后 P0-5 的静默 15s 兜底**从结构上消失**，不只是补 key。
- **前端镜像**：`FUTURES_DUAL_PAIRS_JS` 同表；`isValidFuturesDualPair` 与 `isValidStockDualPair` 同实现（同参数、同返回）。

### 7.2 区间套：显式透传（对齐股票）

| 侧 | 股票现状 | 期货改法 |
|---|---|---|
| 写 | `AppEngine` 建上窗后 `chan._stocks_dual_sub_freq = sub_freq` | `_sse_dual_gen` 建上窗后 `chan._futures_dual_sub_freq = sub_freq` |
| 读 | `getattr(parent.chan, "_stocks_dual_sub_freq", None)` 命中则覆盖静态表 | 同款：命中则用它算 `cache_key`（仍走 `make_futures_sub_key_from_code`），未命中回落 `_FUTURES_SUB_FREQ_MAP` |

- `_FUTURES_SUB_FREQ_MAP` **仍要补 `'15m': '5m'`**：它撑的是"无显式下窗"的路径（单窗、legacy），也是 `_FUTURES_DUAL_FREQ_MAP` 默认值的对账对象。两条映射在 15m 上必须都指向 `5m`。
- **miss 语义照抄股票**：仍 `return True`（按子级别背驰）+ `SSE_DEBUG` 日志。不做"miss 不放行"——股票也没这么做，且会让一次缓存抖动变成全局不出信号；显式透传落地后 miss 只剩初始化竞态，日志已标明。
- 收益：手工选 30m+15m 时，红框与背驰**同用 15m**，§4.4 那个"红框对、买卖点错"的口径裂缝闭合。

### 7.3 双窗入口与按钮可用性

| 周期 | 股票 | 期货（裁决后） | 依据 |
|---|---|---|---|
| 15m | 单窗点双窗：**禁** | **禁** | 裁决 ⑴⑶ |
| 5m | 禁（股票最小周期，无下窗） | **保留可进** | **唯一偏离**，见下 |
| 15s | — | 禁（现状，无下窗） | 期货最小周期 |
| 30m / 1m | 可进 | 可进 | 同构 |

**为什么 5m 不照抄**：股票禁 5m 的因果是"无下窗可选"，期货 5m 有 `1m` 下窗且**现状正在用**（`30m/5m`、`5m/1m` 都通）。照抄字面 = 砍掉一条在用能力，属回归。同原则不同结论，是因为前提相反 —— 这条不是偷懒，是把"禁"的理由当规则而不是把"禁 5m"当规则。

改动点：
- `updateDualBtn` 期货分支：`disabled = (currentFreq === '15m' || currentFreq === '15s')`。
- `updateFreqButtonStates`：单窗 `SHOW['15m'] = true`（两市场一致）、删 `btn-15m.disabled = isFutures`；**双窗期货分支删掉 `btn-15m.disabled = true` 硬覆盖**，改成与股票同构的两级焦点（上窗焦点：禁 `15s`，其余可切；下窗焦点：按 `FUTURES_DUAL_PAIRS_JS[currentFreq]` 逐个开合）。
- `switchFreq` 期货分支补齐股票同款两处守卫（**现状缺口，与 15m 无关但同批修**）：
  1. 下窗焦点：用 `isValidFuturesDualPair(currentFreq, freq)` 替代裸 `freqLevel` 比较，报错时给出可选集；
  2. 上窗焦点：`FUTURES_DUAL_PAIRS_JS[freq]` 不存在 → 拒绝（15s）；存在但 `dualSubFreq` 不再合法 → 回退 `getDualSubFreq(freq)`。

### 7.4 Trading 跟进 15m（裁决 ⑷）

- `Trading/Infra/Period.py`：`FREQ_SEC` 加 `"15m": 900`；`PERIOD_PROFILES` 加 `Period(freq="15m", bar_secs=900)`；docstring "4 个周期" → 5。`SUPPORTED_FREQS` 是派生式，自动变 `("15s","1m","5m","15m","30m")`，无需手改。
