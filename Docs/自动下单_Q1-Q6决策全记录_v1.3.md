## Q6 · 解锁后的净敞口能否按 L1-L3 处理？

### 我的提问

> 解锁后的净敞口，是否必须配套止盈止损（S3）？
> - A 必须（推荐）
> - B 维持现状只等信号

### 你的答复

> 解锁后的净敞口，是否必须配套止盈止损。**但这个止损止盈还能按止盈止损 L1-L3 逻辑处理吗？**
> 按我那个举例，平旧仓 A 后，账户处于运行状态，旧仓 B 处于运行中，
> 但 B 这一笔（含 2 手）是前一交易日入场的，**感觉没法按 L1-L3 逻辑处理了吧**。
> **只能假想再平旧仓 A 那个时间点，开了一个新仓。** 我想听听你怎么考虑这个问题。

### 我的答复

**你的两点直觉都对，而且你给的解法（"假想开了新仓"）就是唯一自洽解。**

先摆代码事实（不是推测）：

- B 的出场计划是**占位符**：`ExitPlan("locked_await_unlock", stop_price=0.0)`（`Engine.py:802-803`）；
- `_settle_positions` 对 `entry_mode == LOCKED` 显式 `continue`（`Engine.py:346-347`）——
  B **连被 L1-L3 判定的资格都没有**。

各层对"入场时点"的依赖不同：

| 层 | 依赖 | B 沿用旧计划的问题 |
|---|---|---|
| **L1 结构止损** | `signal.fractal_low / fractal_high` | 昨天那个分型今天可能已被穿越 → `A ≤ 0` 被钳到 0（`Exit.py:118-120`）→ **L1 失效** |
| **L2 波动率** | `_atr()` 每根 bar 更新、跨日清缓冲 | 没问题（ATR 是当下的） |
| **L3 保本/跟踪** | `params["R"]`、`entry`、`_trail_best` | `_trail_best` 初值 = 昨天锁仓价 → 把**昨天已兑现的浮盈**算成今天的跟踪收益 → 过早、过激触发 |

**但你的方案有一处要修正 —— 不能真的把 `entry_price` 改成 P₂**（这也是 v1.1 里**我自己的错误**）：

```
B 多2 @P₀(昨), A 空2 @P₁(昨锁仓价)      锁定期浮盈恒 = (P₁−P₀)×2
次日平 A @P₂  →  已实现 (P₁−P₂)×2
              →  剩余 B 浮盈 = (P−P₀)×2
              →  累计 = (P₁−P₂)×2 + (P−P₀)×2     在 P=P₂ 时 = (P₁−P₀)×2 ✓

若把 B.entry_price 改成 P₂：
              →  累计 = (P₁−P₂)×2 + (P−P₂)×2     在 P=P₂ 时 = (P₁−P₂)×2 ✗ 少 (P₂−P₀)×2
```

**所以是双锚，不是换锚**：

| 口径 | 字段 | 值 | 用途 |
|---|---|---|---|
| 会计锚 | `B.entry_price`（**不动**） | P₀ | `pnl_points`、`Trade.net_points`、对账 |
| 风控锚 | `B.exit_plan.params["risk_anchor"]`（**新增**） | P₂ | L1 结构距离、L3 保本/跟踪基准 |

**用当前信号 `sig` 重算 R 是严格成立的**（不是凑合）：
`_unlock_position` 取的是与信号**反向**的 A，平掉 A 后剩下的 B 方向**恰好 == `sig.side`**，
所以 `plan()` 里的 `is_long` 与 B 天然一致，`fractal_low/high` 也是**当下**的结构位 → L1/L2/L3 全都能跑。

改动量很小（3 处）：

1. `Strategy/Exit.py:130` `plan()` 加可选参数 `anchor`，内部 entry 改用 `anchor or entry_price`，写入 `params["risk_anchor"]`；
2. `Strategy/Exit.py:176` `entry = position.entry_price` → `entry = plan.params.get("risk_anchor") or position.entry_price`；
3. `Engine._unlock_position` 成交后：配对腿 B 的 `entry_mode` `LOCKED → UNLOCK_FIRST`、重设 `exit_plan`、`_trail_best = P₂`
   （需要 S4 的 `lock_pair_id` 才能定位 B，故 S4 提为 P0）。

### 你的追问（第二轮 ⑷）—— 确认成立

> **锁仓状态下以做多为例，就是平掉空单。既然能做多，说明当时出现了买点信号；
> 既然有买点信号，说明有底分型，也有成交价，那么 1R 就能算出来 —— 所以跟 B 关系不大，
> 止盈止损的处理就相当于认为此时开了一个新的多单而已。**

### 我的复核（第二轮）—— 同意，且论证更干净

**R 的可算性来自"当前信号"，不来自 B 的历史**：有买点 ⇒ 有底分型 ⇒ 有成交价 ⇒ 1R 可算。
所以"平 A 之后 B 怎么止损"根本不需要看 B 是昨天几点开的。这就是风控锚的定义。

仍有一条**实现方式**层面的约束要留档（与你的结论不冲突）：风控锚必须落成**新增字段**
`risk_anchor`，**不能**直接改写 `B.entry_price` —— 否则 `(P₂−P₀)×N` 的已实现盈亏凭空消失、对账 mismatch。

### Q6 最终结论

| 项 | 内容 |
|---|---|
| **决策** | 解锁后的净敞口**必须**受 L1-L3 保护；实现 = **会计锚 / 风控锚分离** |
| **风控锚定义（v1.3 用户确认）** | = **当前信号的 1R**（有买点 ⇒ 有底分型 ⇒ 有成交价），**与 B 的历史成本无关** |
| **优先级** | **P0**（Q1=B 之下信号不再离场，B 若没保护就是永久裸奔，比 Q1 之前更危险） |
| **落地** | 上面 3 处改动 + `bars_held` 语义待定（P2，当前 L1-L3 未使用，无影响） |
